The 8 Fallacies of Distributed Computing (Deutsch & Gosling)

Every microservices engineer must design with the following operational realities in mind:

  1. The network is reliable: False. Packet drops, transient partition timeouts, and socket resets will occur continuously.
  2. Latency is zero: In-process method calls take $\approx 2\text{–}10\text{ ns}$; network hops take $0.5\text{–}50\text{ ms}$ (a million-fold slowdown).
  3. Bandwidth is infinite: Serializing excessive payloads chokes network saturation.
  4. The network is secure: Zero-trust mTLS and token validation are required at every boundary.
  5. Topology doesn't change: Kubernetes pods, load balancers, and nodes scale and relocate dynamically.
  6. There is one administrator: Microservices span heterogeneous squads, clusters, and clouds.
  7. Transport cost is zero: JSON parsing, serialization, TLS handshake, and socket overhead consume CPU.
  8. The network is homogeneous: Multiple OS versions, programming languages, and network stacks interact.

2. Domain-Driven Design (DDD): Strategic Design

Subdomain Taxonomy

  • Core Subdomain: The primary competitive engine of the enterprise. Bespoke, highly optimized, subject to frequent evolution.
  • Supporting Subdomain: Custom software essential for core operations, but not a competitive differentiator (e.g., custom warehouse racking allocation).
  • Generic Subdomain: Standardized domain problem shared across the industry (e.g., identity management, payment gateway integration, SMS notifications). Buy or integrate standard libraries whenever possible.

Ubiquitous Language & Bounded Contexts

A Bounded Context defines the conceptual boundary within which a specific domain model and Ubiquitous Language strictly apply.

A single real-world concept (e.g., a "Product") has radically different meanings and attributes across contexts:

  • In CatalogContext: SKU, marketing title, SEO tags, rich media, category tree.
  • In InventoryContext: SKU, bin location, weight, physical dimensions, units on hand, reorder point.
  • In BillingContext: Price, tax code, ledger account, discount eligibility.

Unifying these into a single bloated "Universal Product Entity" creates an unmaintainable monolith.

Context Mapping Patterns

  1. Shared Kernel: Two bounded contexts share a subset of the domain model and database. Creates high coupling; should be restricted to rare shared utilities.
  2. Customer / Supplier (Upstream / Downstream): The Upstream context (Supplier) delivers services or data to the Downstream context (Customer). Downstream needs dictate delivery priority.
  3. Conformist: Downstream conforms unconditionally to the Upstream schema without adaptation.
  4. Anti-Corruption Layer (ACL): Downstream implements a translation layer that maps foreign Upstream representations into clean Downstream domain concepts, preventing domain model corruption.
  5. Open Host Service (OHS) / Published Language (PL): Upstream exposes a stable, documented protocol (REST, gRPC, Protobuf, CloudEvents) for multiple consumers.

3. Tactical DDD Principles

1. Entities vs. Value Objects

  • Value Object:
  • Defined entirely by its attributes (immutable).
  • No conceptual identity.
  • Structural equality (record struct, record, or overridden Equals).
  • Example: Money(100, "USD"), Sku("LAPTOP-01"), Address("123 Main St", "NY").
  • Entity:
  • Defined by an immutable unique identifier (Id).
  • Has a lifecycle and mutable state transitions.
  • Example: OrderItem, Customer.

2. Aggregate Roots & Consistency Boundaries

An Aggregate is a cluster of entities and value objects that are treated as a single transactional consistency unit:

  • The Aggregate Root is the sole gatekeeper for all mutations within the aggregate.
  • External entities must never directly mutate interior aggregate entities.
  • Aggregates reference other aggregates exclusively by identifier (Guid OrderId), never by direct in-memory object reference.
  • Rule of Thumb: One database transaction should modify exactly one Aggregate Root instance. Cross-aggregate coordination is handled via Domain Events and eventual consistency (Sagas / Process Managers).

3. In-Process Domain Events

  • Aggregates record domain events when significant state transitions occur (OrderPlaced, PaymentAuthorized).
  • Events are dispatched either immediately in-process or persisted to an Outbox table before committing the database transaction.

4. Graph Algorithms: Number of Islands (LeetCode #200)

Problem Formulation

Given an $m \times n$ 2D binary grid representing '1' (land) and '0' (water), count the number of disconnected land masses (connected 4-directionally).

1. Depth-First Search (DFS) In-Place Sinking

  • Scan the 2D matrix linearly from $(0, 0)$ to $(m-1, n-1)$.
  • When a cell with value '1' is encountered:
  1. Increment islandCount.
  2. Invoke DfsSink(r, c): recursively visit its 4 cardinal neighbors ((r-1, c), (r+1, c), (r, c-1), (r, c+1)).
  3. Mark visited cells by overwriting '1' with '0' (sinking the island into water).
  • Time Complexity: $\mathcal{O}(M \times N)$ — each grid cell is evaluated at most 5 times (1 linear scan + 4 neighbor checks).
  • Space Complexity: $\mathcal{O}(M \times N)$ worst case recursion stack depth if the grid is solid land.

2. Breadth-First Search (BFS) Exploration

  • When encountering '1':
  1. Increment islandCount.
  2. Overwrite '1' with '0' immediately (prior to queue enqueue) to prevent duplicate enqueues from multiple neighbors.
  3. Enqueue (r, c).
  4. While queue is non-empty, dequeue and explore all 4 cardinal neighbors. Enqueue matching unvisited lands and mark them '0'.
  • Time Complexity: $\mathcal{O}(M \times N)$.
  • Space Complexity: $\mathcal{O}(\min(M, N))$ — the queue holds at most the diagonal cross-section/perimeter of the island at any point in time.

Day 26: Senior & Staff Engineer Interview Questions & Answers

1. How do you determine the correct boundaries for a Microservice, and why is premature decomposition considered an architectural catastrophe?

Answer:

A microservice boundary should align with a Bounded Context derived from business domain subdomains, not technical layers (e.g., UI service, Database service) or arbitrary entity boundaries (e.g., UserService, OrderService, ItemService).

Criteria for Service Boundaries:

  1. Autonomous Business Capability: Can the service deliver its core business value independently of other services being deployed?
  2. Independent Rate of Change: Does this area of the business evolve and deploy on a significantly different cadence than adjacent capabilities?
  3. Data Ownership & Invariants: Does the service own its transactional consistency boundary, completely encapsulating its database?
  4. Team Topology (Conway’s Law): Can a single cross-functional team own the lifecycle of the service end-to-end?

Dangers of Premature Decomposition:

  • Distributed Monolith: Services share synchronous request-response chains (HTTP/gRPC) where a failure in Service D cascades backwards to Service A.
  • Dual Writes & Distributed Transactions: Teams struggle to maintain consistency without 2PC, resulting in corrupted or out-of-sync data.
  • Operational Tax: Overhead of independent CI/CD pipelines, container orchestration, distributed tracing, observability, and network latency without reaping organizational autonomy.
  • Recommended Path: Start with a well-structured Modular Monolith enforcing bounded context boundaries in-process. Extract services only when organizational scale or distinct scalability profiles demand it.

2. Is every Bounded Context guaranteed to be an independent Microservice? How do you architect multiple Bounded Contexts within a Modular Monolith?

Answer:

No. A Bounded Context is a conceptual domain boundary in the problem/solution space, whereas a Microservice is a physical deployment and runtime boundary. A single microservice or modular monolith can host multiple bounded contexts.

Architecting Multiple Bounded Contexts in a Modular Monolith:

MyApp/
├── Modules/
│   ├── Ordering/
│   │   ├── Domain/
│   │   ├── Application/
│   │   ├── Infrastructure/
│   │   └── PublicApi/          <-- Only exposed interface
│   ├── Inventory/
│   │   ├── Domain/
│   │   ├── Application/
│   │   └── Infrastructure/

Enforcement Rules:

  1. Explicit API Contracts: Module A cannot reference Module B's internal Domain or Infrastructure assemblies. It can only reference PublicApi contracts or subscribe to in-process domain events.
  2. Separate Database Schemas: Use distinct schemas in PostgreSQL/SQL Server (ordering.orders, inventory.stock_items). Foreign keys never cross schema boundaries.
  3. Architecture Unit Tests: Use tools like NetArchTest or ArchUnitNET to fail CI if Module A accesses internal namespaces of Module B.

3. How does the Anti-Corruption Layer (ACL) pattern differ from an API Gateway, and where should it be implemented?

Answer:

  • API Gateway:
  • Focuses on cross-cutting technical concerns: reverse proxying, TLS termination, client routing, rate limiting, token validation (JWT), and response compression.
  • Sits at the edge of the system between external clients (Web, Mobile) and backend services.
  • Anti-Corruption Layer (ACL):
  • Focuses on domain model semantic translation.
  • Sits between two bounded contexts (specifically on the downstream side) or between a modern domain model and a legacy/third-party system.
  • Translates foreign data structures, terminology, and quirks into clean, immutable value objects and domain entities that align with the downstream Ubiquitous Language.

Implementation Example:

public class PaymentAntiCorruptionLayer
{
    public PaymentResult Adapt(LegacyVendorPayload raw)
    {
        // Translate untyped snake_case cents string into strong Money value object
        var amount = decimal.Parse(raw.amt_cents) / 100m;
        return new PaymentResult(
            OrderId: Guid.Parse(raw.order_ref),
            Amount: new Money(amount, raw.curr),
            Status: raw.status == "00" ? PaymentStatus.Authorized : PaymentStatus.Declined
        );
    }
}

4. Why must DDD Aggregate Roots reference other Aggregates strictly by identity (Guid Id) rather than direct object navigation properties?

Answer:

Referencing other aggregates via direct in-memory object references (e.g., public Customer Customer { get; set; } inside Order) introduces severe architectural anti-patterns:

  1. Undefined Transactional Consistency Boundary: When an ORM (like EF Core) saves an Order, developers or cascading updates might modify the loaded Customer instance, violating the principle that one transaction touches exactly one aggregate.
  2. Massive Memory Graphs & Lazy Loading: Traversing navigation properties triggers accidental database queries (N+1 queries) or pulls multi-megabyte object graphs into memory.
  3. Blocks Microservice Extraction: If Order holds a direct object reference to Customer, extracting Ordering into a separate microservice breaks compilation. With Guid CustomerId, extraction requires zero domain model changes because the boundary was already loosely coupled.

6. What is the Dual-Write Problem, and how does the Transactional Outbox Pattern solve it?

Answer:

The Dual-Write Problem:

When an application updates its database and publishes a message to a broker (e.g., RabbitMQ or Kafka):

await _dbContext.SaveChangesAsync(); // Step 1: DB commit
await _messageBus.PublishAsync(event); // Step 2: Message publish

If the process crashes, the network disconnects, or the message broker is unavailable between Step 1 and Step 2, the database mutation succeeds but the message is never sent, leading to permanent cross-system data inconsistency. Conversely, if Step 2 is executed first, message delivery may succeed while the DB transaction rolls back.

The Transactional Outbox Solution:

  1. Store an OutboxMessages table in the same database as the business entities.
  2. Inside a single atomic ACID database transaction, insert the business state mutation AND insert the serialized event into OutboxMessages.
  3. A background worker (e.g., using Change Data Capture / Debezium or an asynchronous polling worker) reads unpublished outbox rows, publishes them to the message broker, and marks them as dispatched upon broker acknowledgment.

7. How do you maintain data consistency across multiple Bounded Contexts without using Two-Phase Commit (2PC)?

Answer:

Two-Phase Commit (2PC / XA transactions) relies on distributed locking, which degrades availability, limits throughput, and creates single points of failure across microservices. Instead, modern cloud-native systems employ Eventual Consistency via the Saga Pattern:

Saga Architectures:

  1. Choreography:
  • Each service listens to domain events and executes its local transaction without a central coordinator.
  • Example: OrderService places order $\to$ emits OrderPlaced $\to$ InventoryService reserves stock $\to$ emits StockReserved $\to$ PaymentService charges card.
  • If payment fails, PaymentService emits PaymentFailed $\to$ InventoryService consumes it and runs Compensating Transaction to release stock.
  1. Orchestration:
  • A dedicated Orchestrator (Process Manager or workflow engine like Temporal / MassTransit State Machine) explicitly commands each participating service step-by-step and initiates compensation workflows upon errors.

8. Explain Conway's Law and the "Inverse Conway Maneuver". How does it influence microservice design?

Answer:

  • Conway's Law (Melvin Conway, 1967):

"Organizations which design systems are constrained to produce designs which are copies of the communication structures of these organizations."

If an engineering department is split into a DBA team, a Backend team, and a Frontend team, the system will inevitably consist of a database layer, a backend service layer, and a frontend layer with high coordination overhead.

  • Inverse Conway Maneuver:

An organization intentionally restructures its cross-functional teams around business capabilities and Bounded Contexts to drive the desired software architecture.

For example, creating a dedicated "Fulfillment Team" owning the Ordering and Shipping bounded contexts results in autonomous, decoupled services with clean API contracts.

9. What are the trade-offs between Synchronous HTTP/gRPC communication and Asynchronous Event-Driven communication in microservices?

Answer:

  • Synchronous HTTP/gRPC:
  • Pros: Simple programming model, immediate response / error feedback, straightforward debugging and tracing.
  • Cons: Temporal Coupling (both caller and callee must be available simultaneously), cascading latency (latency equals sum of all downstream calls), fragile under network degradation, thundering herds.
  • Asynchronous Event-Driven (Broker):
  • Pros: Temporal Decoupling (publisher produces even if consumer is down or deploying), load leveling / backpressure smoothing, high scalability, broadcast to multiple subscribers.
  • Cons: Eventual consistency complexity, out-of-order delivery risks, duplicate message handling (requires idempotency keys), distributed debugging and tracing require correlation IDs.

10. For LeetCode #200 (Number of Islands), what are the failure modes of recursive DFS on massive grids ($10^4 \times 10^4$), and how do BFS or Disjoint Set Union (DSU / Union-Find) overcome them?

Answer:

DFS Failure Modes on Massive Grids:

Recursive DFS uses the thread execution stack. On an $M \times N$ grid with solid land, recursion depth can reach $\mathcal{O}(M \times N)$. In .NET, the default thread stack size is 1 MB (or 256 KB on 64-bit secondary threads). A grid of size $1000 \times 1000 = 10^6$ will exceed the stack boundary within a few thousand recursive frames, throwing a fatal, uncatchable StackOverflowException.

Alternatives:

  1. Iterative BFS with FIFO Queue:
  • Uses managed heap memory rather than thread stack.
  • Space complexity is bounded by the perimeter of the island ($\mathcal{O}(\min(M, N))$), which is far smaller than the total area.
  1. Disjoint Set Union (Union-Find):
  • Treats each cell $(r, c)$ as a node $r \times N + c$.
  • Iterates through the grid once. For every land cell, it performs Union with its right and down adjacent land cells.
  • Number of islands equals total land cells minus successful union operations.
  • Space complexity is $\mathcal{O}(M \times N)$ array allocations on the heap, with near-constant $\mathcal{O}(\alpha(N))$ time complexity per operation.

/// <summary>
/// Anti-Corruption Layer (ACL) isolating the Core Domain from legacy/third-party schemas.
/// Protects domain models from leaking external vendor types and formatting quirks.
/// </summary>
public class PaymentAntiCorruptionLayer
{
    public PaymentAuthorizationResult Translate(LegacyPaymentGatewayPayload rawPayload)
    {
        if (rawPayload == null)
            throw new ArgumentNullException(nameof(rawPayload));

        if (!Guid.TryParse(rawPayload.order_ref, out var orderId))
        {
            return new PaymentAuthorizationResult(
                Guid.Empty,
                0m,
                rawPayload.curr ?? "USD",
                string.Empty,
                IsSuccessful: false,
                FailureReason: "Invalid order identifier format.");
        }

        if (!decimal.TryParse(rawPayload.amt_cents, out var cents))
        {
            return new PaymentAuthorizationResult(
                orderId,
                0m,
                rawPayload.curr ?? "USD",
                string.Empty,
                IsSuccessful: false,
                FailureReason: "Invalid amount representation.");
        }

        var amount = decimal.Round(cents / 100m, 2);
        var isSuccess = rawPayload.status_code == "AUTH_200" || rawPayload.status_code == "SUCCESS";

        return new PaymentAuthorizationResult(
            OrderId: orderId,
            Amount: amount,
            Currency: (rawPayload.curr ?? "USD").ToUpperInvariant(),
            AuthorizationCode: rawPayload.auth_token ?? string.Empty,
            IsSuccessful: isSuccess,
            FailureReason: isSuccess ? null : $"Gateway returned error code: {rawPayload.status_code}");
    }
}

/// <summary>
/// In-process asynchronous domain event dispatcher.
/// Decouples bounded contexts while maintaining transactional observability.
/// </summary>
public interface IDomainEventDispatcher
{
    void RegisterHandler<TEvent>(Func<TEvent, CancellationToken, Task> handler) where TEvent : IDomainEvent;
    Task DispatchAsync<TEvent>(TEvent domainEvent, CancellationToken cancellationToken = default) where TEvent : IDomainEvent;
    int DispatchedCount { get; }
}

public class InMemoryDomainEventDispatcher : IDomainEventDispatcher
{
    private readonly Dictionary<Type, List<Delegate>> _handlers = new();
    private readonly object _lock = new();
    private int _dispatchedCount;

    public int DispatchedCount => _dispatchedCount;

    public void RegisterHandler<TEvent>(Func<TEvent, CancellationToken, Task> handler) where TEvent : IDomainEvent
    {
        lock (_lock)
        {
            var eventType = typeof(TEvent);
            if (!_handlers.TryGetValue(eventType, out var list))
            {
                list = new List<Delegate>();
                _handlers[eventType] = list;
            }
            list.Add(handler);
        }
    }

    public async Task DispatchAsync<TEvent>(TEvent domainEvent, CancellationToken cancellationToken = default) where TEvent : IDomainEvent
    {
        List<Delegate> targets;
        lock (_lock)
        {
            var eventType = typeof(TEvent);
            if (!_handlers.TryGetValue(eventType, out var list))
                return;

            targets = new List<Delegate>(list);
        }

        foreach (var d in targets)
        {
            if (d is Func<TEvent, CancellationToken, Task> typedHandler)
            {
                await typedHandler(domainEvent, cancellationToken).ConfigureAwait(false);
                Interlocked.Increment(ref _dispatchedCount);
            }
        }
    }
}

/// <summary>
/// High-level orchestration showing Bounded Context interactions via Events and ACL.
/// </summary>
public class OrderFulfillmentCoordinator
{
    private readonly IDomainEventDispatcher _dispatcher;
    private readonly InventoryItem _inventoryItem;
    private readonly PaymentAntiCorruptionLayer _paymentAcl;

    public List<string> AuditLog { get; } = new();

    public OrderFulfillmentCoordinator(
        IDomainEventDispatcher dispatcher,
        InventoryItem inventoryItem,
        PaymentAntiCorruptionLayer paymentAcl)
    {
        _dispatcher = dispatcher;
        _inventoryItem = inventoryItem;
        _paymentAcl = paymentAcl;

        _dispatcher.RegisterHandler<OrderPlacedEvent>(HandleOrderPlacedAsync);
        _dispatcher.RegisterHandler<InventoryReservedEvent>(HandleInventoryReservedAsync);
    }

    public async Task ProcessOrderPlacementAsync(Order order)
    {
        order.Place();
        foreach (var ev in order.DomainEvents)
        {
            if (ev is OrderPlacedEvent placed)
            {
                await _dispatcher.DispatchAsync(placed).ConfigureAwait(false);
            }
        }
        order.ClearDomainEvents();
    }

    private Task HandleOrderPlacedAsync(OrderPlacedEvent ev, CancellationToken ct)
    {
        AuditLog.Add($"[OrderingContext] Order {ev.OrderId} placed for {ev.Quantity}x {ev.Sku}.");

        if (_inventoryItem.TryReserve(ev.Quantity, out var resId))
        {
            AuditLog.Add($"[InventoryContext] Stock reserved: {resId} for SKU {ev.Sku}.");
            var reservedEvent = new InventoryReservedEvent(resId, ev.OrderId, ev.Sku, ev.Quantity);
            return _dispatcher.DispatchAsync(reservedEvent, ct);
        }

        AuditLog.Add($"[InventoryContext] Out of stock for SKU {ev.Sku}.");
        return Task.CompletedTask;
    }

    private Task HandleInventoryReservedAsync(InventoryReservedEvent ev, CancellationToken ct)
    {
        AuditLog.Add($"[Fulfillment] Inventory confirmed for Order {ev.OrderId}. Ready for Payment Bounded Context.");
        return Task.CompletedTask;
    }

    public bool ProcessPaymentWithAcl(Order order, LegacyPaymentGatewayPayload gatewayResponse)
    {
        var aclResult = _paymentAcl.Translate(gatewayResponse);
        if (aclResult.IsSuccessful && aclResult.OrderId == order.Id)
        {
            order.MarkPaid();
            AuditLog.Add($"[PaymentContext] Payment authorized for Order {order.Id} with Code {aclResult.AuthorizationCode}.");
            return true;
        }

        AuditLog.Add($"[PaymentContext] Payment failed for Order {order.Id}: {aclResult.FailureReason}");
        return false;
    }
}

/// Order Aggregate Root in Ordering Bounded Context.
/// Enforces business invariants and encapsulates Domain Events.

public class Order
{
    private readonly List<IDomainEvent> _domainEvents = new();
    private readonly List<OrderItem> _items = new();

    public Guid Id { get; }
    public string CustomerId { get; }
    public OrderStatus Status { get; private set; }
    public IReadOnlyList<OrderItem> Items => _items.AsReadOnly();
    public IReadOnlyList<IDomainEvent> DomainEvents => _domainEvents.AsReadOnly();

    public Order(Guid id, string customerId)
    {
        if (string.IsNullOrWhiteSpace(customerId))
            throw new ArgumentException("Customer ID is required.", nameof(customerId));

        Id = id == Guid.Empty ? Guid.NewGuid() : id;
        CustomerId = customerId.Trim();
        Status = OrderStatus.Draft;
    }

    public void AddItem(Sku sku, int quantity, Money unitPrice)
    {
        if (Status != OrderStatus.Draft)
            throw new InvalidOperationException($"Cannot modify order in status: {Status}");
        if (quantity <= 0)
            throw new ArgumentOutOfRangeException(nameof(quantity), "Quantity must be greater than zero.");

        var existing = _items.FirstOrDefault(i => i.Sku == sku);
        if (existing != null)
        {
            _items.Remove(existing);
            _items.Add(new OrderItem(sku, existing.Quantity + quantity, unitPrice));
        }
        else
        {
            _items.Add(new OrderItem(sku, quantity, unitPrice));
        }
    }

    public Money CalculateTotal()
    {
        if (_items.Count == 0)
            return Money.Zero();

        var currency = _items[0].UnitPrice.Currency;
        var total = Money.Zero(currency);
        foreach (var item in _items)
        {
            total += item.UnitPrice * item.Quantity;
        }
        return total;
    }

    public void Place()
    {
        if (Status != OrderStatus.Draft)
            throw new InvalidOperationException($"Cannot place order in status: {Status}");
        if (_items.Count == 0)
            throw new InvalidOperationException("Cannot place an order with zero line items.");

        Status = OrderStatus.Placed;
        var total = CalculateTotal();
        var primaryItem = _items[0];

        _domainEvents.Add(new OrderPlacedEvent(
            Id,
            CustomerId,
            primaryItem.Sku.Value,
            primaryItem.Quantity,
            total.Amount,
            total.Currency
        ));
    }

    public void MarkPaid()
    {
        if (Status != OrderStatus.Placed)
            throw new InvalidOperationException($"Only placed orders can be marked paid. Current status: {Status}");
        Status = OrderStatus.Paid;
    }

    public void Cancel()
    {
        if (Status == OrderStatus.Paid)
            throw new InvalidOperationException("Cannot cancel an already paid order.");
        Status = OrderStatus.Cancelled;
    }

    public void ClearDomainEvents() => _domainEvents.Clear();
}

/// <summary>
/// Solves LeetCode #200: Number of Islands.
/// Given an m x n 2D binary grid grid which represents a map of '1's (land) and '0's (water),
/// return the number of islands. An island is surrounded by water and is formed by connecting
/// adjacent lands horizontally or vertically.
/// </summary>
public class NumberOfIslandsSolver
{
    private static readonly int[] RowOffsets = { -1, 1, 0, 0 };
    private static readonly int[] ColOffsets = { 0, 0, -1, 1 };

    /// <summary>
    /// Solves Number of Islands using Depth-First Search (DFS) with in-place sinking.
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(M * N) in worst case (recursion call stack for all land).
    /// </summary>
    public int NumIslandsDfs(char[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0)
            return 0;

        // Clone grid to preserve caller input
        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new char[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (char[])grid[i].Clone();
        }

        var islandCount = 0;
        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == '1')
                {
                    islandCount++;
                    DfsSink(workingGrid, r, c, m, n);
                }
            }
        }

        return islandCount;
    }

    private static void DfsSink(char[][] grid, int r, int c, int m, int n)
    {
        if (r < 0 || r >= m || c < 0 || c >= n || grid[r][c] != '1')
            return;

        // Sink land to water ('0') to prevent revisit
        grid[r][c] = '0';

        for (var i = 0; i < 4; i++)
        {
            DfsSink(grid, r + RowOffsets[i], c + ColOffsets[i], m, n);
        }
    }

    /// <summary>
    /// Solves Number of Islands using Breadth-First Search (BFS) with FIFO queue.
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(min(M, N)) queue memory.
    /// </summary>
    public int NumIslandsBfs(char[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0)
            return 0;

        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new char[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (char[])grid[i].Clone();
        }

        var islandCount = 0;
        var queue = new Queue<(int r, int c)>();

        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == '1')
                {
                    islandCount++;
                    workingGrid[r][c] = '0'; // mark visited immediately
                    queue.Enqueue((r, c));

                    while (queue.Count > 0)
                    {
                        var (currR, currC) = queue.Dequeue();

                        for (var i = 0; i < 4; i++)
                        {
                            var nr = currR + RowOffsets[i];
                            var nc = currC + ColOffsets[i];

                            if (nr >= 0 && nr < m && nc >= 0 && nc < n && workingGrid[nr][nc] == '1')
                            {
                                workingGrid[nr][nc] = '0'; // mark visited on enqueue to prevent duplicates
                                queue.Enqueue((nr, nc));
                            }
                        }
                    }
                }
            }
        }

        return islandCount;
    }
}

The 8 Fallacies of Distributed Computing (Deutsch & Gosling)

Every microservices engineer must design with the following operational realities in mind:

  1. The network is reliable: False. Packet drops, transient partition timeouts, and socket resets will occur continuously.
  2. Latency is zero: In-process method calls take $\approx 2\text{–}10\text{ ns}$; network hops take $0.5\text{–}50\text{ ms}$ (a million-fold slowdown).
  3. Bandwidth is infinite: Serializing excessive payloads chokes network saturation.
  4. The network is secure: Zero-trust mTLS and token validation are required at every boundary.
  5. Topology doesn't change: Kubernetes pods, load balancers, and nodes scale and relocate dynamically.
  6. There is one administrator: Microservices span heterogeneous squads, clusters, and clouds.
  7. Transport cost is zero: JSON parsing, serialization, TLS handshake, and socket overhead consume CPU.
  8. The network is homogeneous: Multiple OS versions, programming languages, and network stacks interact.

2. Domain-Driven Design (DDD): Strategic Design

Subdomain Taxonomy

  • Core Subdomain: The primary competitive engine of the enterprise. Bespoke, highly optimized, subject to frequent evolution.
  • Supporting Subdomain: Custom software essential for core operations, but not a competitive differentiator (e.g., custom warehouse racking allocation).
  • Generic Subdomain: Standardized domain problem shared across the industry (e.g., identity management, payment gateway integration, SMS notifications). Buy or integrate standard libraries whenever possible.

Ubiquitous Language & Bounded Contexts

A Bounded Context defines the conceptual boundary within which a specific domain model and Ubiquitous Language strictly apply.

A single real-world concept (e.g., a "Product") has radically different meanings and attributes across contexts:

  • In CatalogContext: SKU, marketing title, SEO tags, rich media, category tree.
  • In InventoryContext: SKU, bin location, weight, physical dimensions, units on hand, reorder point.
  • In BillingContext: Price, tax code, ledger account, discount eligibility.

Unifying these into a single bloated "Universal Product Entity" creates an unmaintainable monolith.

Context Mapping Patterns

  1. Shared Kernel: Two bounded contexts share a subset of the domain model and database. Creates high coupling; should be restricted to rare shared utilities.
  2. Customer / Supplier (Upstream / Downstream): The Upstream context (Supplier) delivers services or data to the Downstream context (Customer). Downstream needs dictate delivery priority.
  3. Conformist: Downstream conforms unconditionally to the Upstream schema without adaptation.
  4. Anti-Corruption Layer (ACL): Downstream implements a translation layer that maps foreign Upstream representations into clean Downstream domain concepts, preventing domain model corruption.
  5. Open Host Service (OHS) / Published Language (PL): Upstream exposes a stable, documented protocol (REST, gRPC, Protobuf, CloudEvents) for multiple consumers.

3. Tactical DDD Principles

1. Entities vs. Value Objects

  • Value Object:
  • Defined entirely by its attributes (immutable).
  • No conceptual identity.
  • Structural equality (record struct, record, or overridden Equals).
  • Example: Money(100, "USD"), Sku("LAPTOP-01"), Address("123 Main St", "NY").
  • Entity:
  • Defined by an immutable unique identifier (Id).
  • Has a lifecycle and mutable state transitions.
  • Example: OrderItem, Customer.

2. Aggregate Roots & Consistency Boundaries

An Aggregate is a cluster of entities and value objects that are treated as a single transactional consistency unit:

  • The Aggregate Root is the sole gatekeeper for all mutations within the aggregate.
  • External entities must never directly mutate interior aggregate entities.
  • Aggregates reference other aggregates exclusively by identifier (Guid OrderId), never by direct in-memory object reference.
  • Rule of Thumb: One database transaction should modify exactly one Aggregate Root instance. Cross-aggregate coordination is handled via Domain Events and eventual consistency (Sagas / Process Managers).

3. In-Process Domain Events

  • Aggregates record domain events when significant state transitions occur (OrderPlaced, PaymentAuthorized).
  • Events are dispatched either immediately in-process or persisted to an Outbox table before committing the database transaction.

4. Graph Algorithms: Number of Islands (LeetCode #200)

Problem Formulation

Given an $m \times n$ 2D binary grid representing '1' (land) and '0' (water), count the number of disconnected land masses (connected 4-directionally).

1. Depth-First Search (DFS) In-Place Sinking

  • Scan the 2D matrix linearly from $(0, 0)$ to $(m-1, n-1)$.
  • When a cell with value '1' is encountered:
  1. Increment islandCount.
  2. Invoke DfsSink(r, c): recursively visit its 4 cardinal neighbors ((r-1, c), (r+1, c), (r, c-1), (r, c+1)).
  3. Mark visited cells by overwriting '1' with '0' (sinking the island into water).
  • Time Complexity: $\mathcal{O}(M \times N)$ — each grid cell is evaluated at most 5 times (1 linear scan + 4 neighbor checks).
  • Space Complexity: $\mathcal{O}(M \times N)$ worst case recursion stack depth if the grid is solid land.

2. Breadth-First Search (BFS) Exploration

  • When encountering '1':
  1. Increment islandCount.
  2. Overwrite '1' with '0' immediately (prior to queue enqueue) to prevent duplicate enqueues from multiple neighbors.
  3. Enqueue (r, c).
  4. While queue is non-empty, dequeue and explore all 4 cardinal neighbors. Enqueue matching unvisited lands and mark them '0'.
  • Time Complexity: $\mathcal{O}(M \times N)$.
  • Space Complexity: $\mathcal{O}(\min(M, N))$ — the queue holds at most the diagonal cross-section/perimeter of the island at any point in time.

Day 26: Senior & Staff Engineer Interview Questions & Answers

1. How do you determine the correct boundaries for a Microservice, and why is premature decomposition considered an architectural catastrophe?

Answer:

A microservice boundary should align with a Bounded Context derived from business domain subdomains, not technical layers (e.g., UI service, Database service) or arbitrary entity boundaries (e.g., UserService, OrderService, ItemService).

Criteria for Service Boundaries:

  1. Autonomous Business Capability: Can the service deliver its core business value independently of other services being deployed?
  2. Independent Rate of Change: Does this area of the business evolve and deploy on a significantly different cadence than adjacent capabilities?
  3. Data Ownership & Invariants: Does the service own its transactional consistency boundary, completely encapsulating its database?
  4. Team Topology (Conway’s Law): Can a single cross-functional team own the lifecycle of the service end-to-end?

Dangers of Premature Decomposition:

  • Distributed Monolith: Services share synchronous request-response chains (HTTP/gRPC) where a failure in Service D cascades backwards to Service A.
  • Dual Writes & Distributed Transactions: Teams struggle to maintain consistency without 2PC, resulting in corrupted or out-of-sync data.
  • Operational Tax: Overhead of independent CI/CD pipelines, container orchestration, distributed tracing, observability, and network latency without reaping organizational autonomy.
  • Recommended Path: Start with a well-structured Modular Monolith enforcing bounded context boundaries in-process. Extract services only when organizational scale or distinct scalability profiles demand it.

2. Is every Bounded Context guaranteed to be an independent Microservice? How do you architect multiple Bounded Contexts within a Modular Monolith?

Answer:

No. A Bounded Context is a conceptual domain boundary in the problem/solution space, whereas a Microservice is a physical deployment and runtime boundary. A single microservice or modular monolith can host multiple bounded contexts.

Architecting Multiple Bounded Contexts in a Modular Monolith:

MyApp/
├── Modules/
│   ├── Ordering/
│   │   ├── Domain/
│   │   ├── Application/
│   │   ├── Infrastructure/
│   │   └── PublicApi/          <-- Only exposed interface
│   ├── Inventory/
│   │   ├── Domain/
│   │   ├── Application/
│   │   └── Infrastructure/

Enforcement Rules:

  1. Explicit API Contracts: Module A cannot reference Module B's internal Domain or Infrastructure assemblies. It can only reference PublicApi contracts or subscribe to in-process domain events.
  2. Separate Database Schemas: Use distinct schemas in PostgreSQL/SQL Server (ordering.orders, inventory.stock_items). Foreign keys never cross schema boundaries.
  3. Architecture Unit Tests: Use tools like NetArchTest or ArchUnitNET to fail CI if Module A accesses internal namespaces of Module B.

3. How does the Anti-Corruption Layer (ACL) pattern differ from an API Gateway, and where should it be implemented?

Answer:

  • API Gateway:
  • Focuses on cross-cutting technical concerns: reverse proxying, TLS termination, client routing, rate limiting, token validation (JWT), and response compression.
  • Sits at the edge of the system between external clients (Web, Mobile) and backend services.
  • Anti-Corruption Layer (ACL):
  • Focuses on domain model semantic translation.
  • Sits between two bounded contexts (specifically on the downstream side) or between a modern domain model and a legacy/third-party system.
  • Translates foreign data structures, terminology, and quirks into clean, immutable value objects and domain entities that align with the downstream Ubiquitous Language.

Implementation Example:

4. Why must DDD Aggregate Roots reference other Aggregates strictly by identity (Guid Id) rather than direct object navigation properties?

Answer:

Referencing other aggregates via direct in-memory object references (e.g., public Customer Customer { get; set; } inside Order) introduces severe architectural anti-patterns:

  1. Undefined Transactional Consistency Boundary: When an ORM (like EF Core) saves an Order, developers or cascading updates might modify the loaded Customer instance, violating the principle that one transaction touches exactly one aggregate.
  2. Massive Memory Graphs & Lazy Loading: Traversing navigation properties triggers accidental database queries (N+1 queries) or pulls multi-megabyte object graphs into memory.
  3. Blocks Microservice Extraction: If Order holds a direct object reference to Customer, extracting Ordering into a separate microservice breaks compilation. With Guid CustomerId, extraction requires zero domain model changes because the boundary was already loosely coupled.

6. What is the Dual-Write Problem, and how does the Transactional Outbox Pattern solve it?

Answer:

The Dual-Write Problem:

When an application updates its database and publishes a message to a broker (e.g., RabbitMQ or Kafka):

await _dbContext.SaveChangesAsync(); // Step 1: DB commit
await _messageBus.PublishAsync(event); // Step 2: Message publish

If the process crashes, the network disconnects, or the message broker is unavailable between Step 1 and Step 2, the database mutation succeeds but the message is never sent, leading to permanent cross-system data inconsistency. Conversely, if Step 2 is executed first, message delivery may succeed while the DB transaction rolls back.

The Transactional Outbox Solution:

  1. Store an OutboxMessages table in the same database as the business entities.
  2. Inside a single atomic ACID database transaction, insert the business state mutation AND insert the serialized event into OutboxMessages.
  3. A background worker (e.g., using Change Data Capture / Debezium or an asynchronous polling worker) reads unpublished outbox rows, publishes them to the message broker, and marks them as dispatched upon broker acknowledgment.

7. How do you maintain data consistency across multiple Bounded Contexts without using Two-Phase Commit (2PC)?

Answer:

Two-Phase Commit (2PC / XA transactions) relies on distributed locking, which degrades availability, limits throughput, and creates single points of failure across microservices. Instead, modern cloud-native systems employ Eventual Consistency via the Saga Pattern:

Saga Architectures:

  1. Choreography:
  • Each service listens to domain events and executes its local transaction without a central coordinator.
  • Example: OrderService places order $\to$ emits OrderPlaced $\to$ InventoryService reserves stock $\to$ emits StockReserved $\to$ PaymentService charges card.
  • If payment fails, PaymentService emits PaymentFailed $\to$ InventoryService consumes it and runs Compensating Transaction to release stock.
  1. Orchestration:
  • A dedicated Orchestrator (Process Manager or workflow engine like Temporal / MassTransit State Machine) explicitly commands each participating service step-by-step and initiates compensation workflows upon errors.

8. Explain Conway's Law and the "Inverse Conway Maneuver". How does it influence microservice design?

Answer:

  • Conway's Law (Melvin Conway, 1967):

"Organizations which design systems are constrained to produce designs which are copies of the communication structures of these organizations."

If an engineering department is split into a DBA team, a Backend team, and a Frontend team, the system will inevitably consist of a database layer, a backend service layer, and a frontend layer with high coordination overhead.

  • Inverse Conway Maneuver:

An organization intentionally restructures its cross-functional teams around business capabilities and Bounded Contexts to drive the desired software architecture.

For example, creating a dedicated "Fulfillment Team" owning the Ordering and Shipping bounded contexts results in autonomous, decoupled services with clean API contracts.

9. What are the trade-offs between Synchronous HTTP/gRPC communication and Asynchronous Event-Driven communication in microservices?

Answer:

  • Synchronous HTTP/gRPC:
  • Pros: Simple programming model, immediate response / error feedback, straightforward debugging and tracing.
  • Cons: Temporal Coupling (both caller and callee must be available simultaneously), cascading latency (latency equals sum of all downstream calls), fragile under network degradation, thundering herds.
  • Asynchronous Event-Driven (Broker):
  • Pros: Temporal Decoupling (publisher produces even if consumer is down or deploying), load leveling / backpressure smoothing, high scalability, broadcast to multiple subscribers.
  • Cons: Eventual consistency complexity, out-of-order delivery risks, duplicate message handling (requires idempotency keys), distributed debugging and tracing require correlation IDs.

10. For LeetCode #200 (Number of Islands), what are the failure modes of recursive DFS on massive grids ($10^4 \times 10^4$), and how do BFS or Disjoint Set Union (DSU / Union-Find) overcome them?

Answer:

DFS Failure Modes on Massive Grids:

Recursive DFS uses the thread execution stack. On an $M \times N$ grid with solid land, recursion depth can reach $\mathcal{O}(M \times N)$. In .NET, the default thread stack size is 1 MB (or 256 KB on 64-bit secondary threads). A grid of size $1000 \times 1000 = 10^6$ will exceed the stack boundary within a few thousand recursive frames, throwing a fatal, uncatchable StackOverflowException.

Alternatives:

  1. Iterative BFS with FIFO Queue:
  • Uses managed heap memory rather than thread stack.
  • Space complexity is bounded by the perimeter of the island ($\mathcal{O}(\min(M, N))$), which is far smaller than the total area.
  1. Disjoint Set Union (Union-Find):
  • Treats each cell $(r, c)$ as a node $r \times N + c$.
  • Iterates through the grid once. For every land cell, it performs Union with its right and down adjacent land cells.
  • Number of islands equals total land cells minus successful union operations.
  • Space complexity is $\mathcal{O}(M \times N)$ array allocations on the heap, with near-constant $\mathcal{O}(\alpha(N))$ time complexity per operation.

/// <summary>
/// In-process asynchronous domain event dispatcher.
/// Decouples bounded contexts while maintaining transactional observability.
/// </summary>
public interface IDomainEventDispatcher
{
    void RegisterHandler<TEvent>(Func<TEvent, CancellationToken, Task> handler) where TEvent : IDomainEvent;
    Task DispatchAsync<TEvent>(TEvent domainEvent, CancellationToken cancellationToken = default) where TEvent : IDomainEvent;
    int DispatchedCount { get; }
}

public class InMemoryDomainEventDispatcher : IDomainEventDispatcher
{
    private readonly Dictionary<Type, List<Delegate>> _handlers = new();
    private readonly object _lock = new();
    private int _dispatchedCount;

    public int DispatchedCount => _dispatchedCount;

    public void RegisterHandler<TEvent>(Func<TEvent, CancellationToken, Task> handler) where TEvent : IDomainEvent
    {
        lock (_lock)
        {
            var eventType = typeof(TEvent);
            if (!_handlers.TryGetValue(eventType, out var list))
            {
                list = new List<Delegate>();
                _handlers[eventType] = list;
            }
            list.Add(handler);
        }
    }

    public async Task DispatchAsync<TEvent>(TEvent domainEvent, CancellationToken cancellationToken = default) where TEvent : IDomainEvent
    {
        List<Delegate> targets;
        lock (_lock)
        {
            var eventType = typeof(TEvent);
            if (!_handlers.TryGetValue(eventType, out var list))
                return;

            targets = new List<Delegate>(list);
        }

        foreach (var d in targets)
        {
            if (d is Func<TEvent, CancellationToken, Task> typedHandler)
            {
                await typedHandler(domainEvent, cancellationToken).ConfigureAwait(false);
                Interlocked.Increment(ref _dispatchedCount);
            }
        }
    }
}

/// <summary>
/// High-level orchestration showing Bounded Context interactions via Events and ACL.
/// </summary>
public class OrderFulfillmentCoordinator
{
    private readonly IDomainEventDispatcher _dispatcher;
    private readonly InventoryItem _inventoryItem;
    private readonly PaymentAntiCorruptionLayer _paymentAcl;

    public List<string> AuditLog { get; } = new();

    public OrderFulfillmentCoordinator(
        IDomainEventDispatcher dispatcher,
        InventoryItem inventoryItem,
        PaymentAntiCorruptionLayer paymentAcl)
    {
        _dispatcher = dispatcher;
        _inventoryItem = inventoryItem;
        _paymentAcl = paymentAcl;

        _dispatcher.RegisterHandler<OrderPlacedEvent>(HandleOrderPlacedAsync);
        _dispatcher.RegisterHandler<InventoryReservedEvent>(HandleInventoryReservedAsync);
    }

    public async Task ProcessOrderPlacementAsync(Order order)
    {
        order.Place();
        foreach (var ev in order.DomainEvents)
        {
            if (ev is OrderPlacedEvent placed)
            {
                await _dispatcher.DispatchAsync(placed).ConfigureAwait(false);
            }
        }
        order.ClearDomainEvents();
    }

    private Task HandleOrderPlacedAsync(OrderPlacedEvent ev, CancellationToken ct)
    {
        AuditLog.Add($"[OrderingContext] Order {ev.OrderId} placed for {ev.Quantity}x {ev.Sku}.");

        if (_inventoryItem.TryReserve(ev.Quantity, out var resId))
        {
            AuditLog.Add($"[InventoryContext] Stock reserved: {resId} for SKU {ev.Sku}.");
            var reservedEvent = new InventoryReservedEvent(resId, ev.OrderId, ev.Sku, ev.Quantity);
            return _dispatcher.DispatchAsync(reservedEvent, ct);
        }

        AuditLog.Add($"[InventoryContext] Out of stock for SKU {ev.Sku}.");
        return Task.CompletedTask;
    }

    private Task HandleInventoryReservedAsync(InventoryReservedEvent ev, CancellationToken ct)
    {
        AuditLog.Add($"[Fulfillment] Inventory confirmed for Order {ev.OrderId}. Ready for Payment Bounded Context.");
        return Task.CompletedTask;
    }

    public bool ProcessPaymentWithAcl(Order order, LegacyPaymentGatewayPayload gatewayResponse)
    {
        var aclResult = _paymentAcl.Translate(gatewayResponse);
        if (aclResult.IsSuccessful && aclResult.OrderId == order.Id)
        {
            order.MarkPaid();
            AuditLog.Add($"[PaymentContext] Payment authorized for Order {order.Id} with Code {aclResult.AuthorizationCode}.");
            return true;
        }

        AuditLog.Add($"[PaymentContext] Payment failed for Order {order.Id}: {aclResult.FailureReason}");
        return false;
    }
}

/// <summary>
/// Money Value Object with immutable semantics and currency guardrails.
/// </summary>
public readonly record struct Money
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(decimal amount, string currency = "USD")
    {
        if (amount < 0)
            throw new ArgumentException("Money amount cannot be negative.", nameof(amount));
        if (string.IsNullOrWhiteSpace(currency))
            throw new ArgumentException("Currency must be specified.", nameof(currency));

        Amount = decimal.Round(amount, 2, MidpointRounding.AwayFromZero);
        Currency = currency.ToUpperInvariant();
    }

    public static Money Zero(string currency = "USD") => new(0m, currency);

    public static Money operator +(Money a, Money b)
    {
        if (a.Currency != b.Currency)
            throw new InvalidOperationException($"Cannot add mismatched currencies: {a.Currency} and {b.Currency}");
        return new Money(a.Amount + b.Amount, a.Currency);
    }

    public static Money operator *(Money a, int multiplier)
    {
        if (multiplier < 0)
            throw new ArgumentException("Multiplier cannot be negative.", nameof(multiplier));
        return new Money(a.Amount * multiplier, a.Currency);
    }
}

public class Order
{

    private readonly List<OrderItem> _items = new();

    public Guid Id { get; }
    public string CustomerId { get; }
    public OrderStatus Status { get; private set; }
    public IReadOnlyList<OrderItem> Items => _items.AsReadOnly();
    public IReadOnlyList<IDomainEvent> DomainEvents => _domainEvents.AsReadOnly();

    public Order(Guid id, string customerId)
    {
        if (string.IsNullOrWhiteSpace(customerId))
            throw new ArgumentException("Customer ID is required.", nameof(customerId));

        Id = id == Guid.Empty ? Guid.NewGuid() : id;
        CustomerId = customerId.Trim();
        Status = OrderStatus.Draft;
    }

    public void AddItem(Sku sku, int quantity, Money unitPrice)
    {
        if (Status != OrderStatus.Draft)
            throw new InvalidOperationException($"Cannot modify order in status: {Status}");
        if (quantity <= 0)
            throw new ArgumentOutOfRangeException(nameof(quantity), "Quantity must be greater than zero.");

        var existing = _items.FirstOrDefault(i => i.Sku == sku);
        if (existing != null)
        {
            _items.Remove(existing);
            _items.Add(new OrderItem(sku, existing.Quantity + quantity, unitPrice));
        }
        else
        {
            _items.Add(new OrderItem(sku, quantity, unitPrice));
        }
    }

    public Money CalculateTotal()
    {
        if (_items.Count == 0)
            return Money.Zero();

        var currency = _items[0].UnitPrice.Currency;
        var total = Money.Zero(currency);
        foreach (var item in _items)
        {
            total += item.UnitPrice * item.Quantity;
        }
        return total;
    }

    public void Place()
    {
        if (Status != OrderStatus.Draft)
            throw new InvalidOperationException($"Cannot place order in status: {Status}");
        if (_items.Count == 0)
            throw new InvalidOperationException("Cannot place an order with zero line items.");

        Status = OrderStatus.Placed;
        var total = CalculateTotal();
        var primaryItem = _items[0];

        _domainEvents.Add(new OrderPlacedEvent(
            Id,
            CustomerId,
            primaryItem.Sku.Value,
            primaryItem.Quantity,
            total.Amount,
            total.Currency
        ));
    }

    public void MarkPaid()
    {
        if (Status != OrderStatus.Placed)
            throw new InvalidOperationException($"Only placed orders can be marked paid. Current status: {Status}");
        Status = OrderStatus.Paid;
    }

    public void Cancel()
    {
        if (Status == OrderStatus.Paid)
            throw new InvalidOperationException("Cannot cancel an already paid order.");
        Status = OrderStatus.Cancelled;
    }

    public void ClearDomainEvents() => _domainEvents.Clear();
}

/// <summary>

public class InventoryItem
{
    public Sku Sku { get; }
    public int AvailableStock { get; private set; }
    public int ReservedStock { get; private set; }

    public InventoryItem(Sku sku, int initialStock)
    {
        if (initialStock < 0)
            throw new ArgumentException("Initial stock cannot be negative.", nameof(initialStock));
        Sku = sku;
        AvailableStock = initialStock;
        ReservedStock = 0;
    }

    public bool TryReserve(int quantity, out Guid reservationId)
    {
        if (quantity <= 0 || AvailableStock < quantity)
        {
            reservationId = Guid.Empty;
            return false;
        }

        AvailableStock -= quantity;
        ReservedStock += quantity;
        reservationId = Guid.NewGuid();
        return true;
    }

    public void ReleaseReservation(int quantity)
    {
        if (quantity <= 0 || ReservedStock < quantity)
            throw new InvalidOperationException("Cannot release more stock than currently reserved.");

        ReservedStock -= quantity;
        AvailableStock += quantity;
    }
}

    /// Space Complexity: O(M * N) in worst case (recursion call stack for all land).
    /// </summary>
    public int NumIslandsDfs(char[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0)
            return 0;

        // Clone grid to preserve caller input
        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new char[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (char[])grid[i].Clone();
        }

        var islandCount = 0;
        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == '1')
                {
                    islandCount++;
                    DfsSink(workingGrid, r, c, m, n);
                }
            }
        }

        return islandCount;
    }

    private static void DfsSink(char[][] grid, int r, int c, int m, int n)
    {
        if (r < 0 || r >= m || c < 0 || c >= n || grid[r][c] != '1')
            return;

        // Sink land to water ('0') to prevent revisit
        grid[r][c] = '0';

        for (var i = 0; i < 4; i++)
        {
            DfsSink(grid, r + RowOffsets[i], c + ColOffsets[i], m, n);
        }
    }

    /// <summary>
    /// Solves Number of Islands using Breadth-First Search (BFS) with FIFO queue.
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(min(M, N)) queue memory.
    /// </summary>
    public int NumIslandsBfs(char[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0)
            return 0;

        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new char[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (char[])grid[i].Clone();
        }

        var islandCount = 0;
        var queue = new Queue<(int r, int c)>();

        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == '1')
                {
                    islandCount++;
                    workingGrid[r][c] = '0'; // mark visited immediately
                    queue.Enqueue((r, c));

                    while (queue.Count > 0)
                    {
                        var (currR, currC) = queue.Dequeue();

                        for (var i = 0; i < 4; i++)
                        {
                            var nr = currR + RowOffsets[i];
                            var nc = currC + ColOffsets[i];

                            if (nr >= 0 && nr < m && nc >= 0 && nc < n && workingGrid[nr][nc] == '1')
                            {
                                workingGrid[nr][nc] = '0'; // mark visited on enqueue to prevent duplicates
                                queue.Enqueue((nr, nc));
                            }
                        }
                    }
                }
            }
        }

        return islandCount;
    }
}
