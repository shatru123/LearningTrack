1. The API Gateway Architectural Pattern

In a microservices topology, client applications (web SPAs, mobile apps, IoT devices, third-party partners) should not directly communicate with dozens of discrete backend microservices. Doing so leaks internal service topology, creates tight coupling, and requires each service to reimplement authentication, rate limiting, and SSL termination.

Key Gateway Topologies

  1. Edge Gateway: Central entry point handling public internet traffic, DDoS mitigation, and global TLS termination.
  2. Backend for Frontend (BFF): Tailored gateways for specific client experiences (e.g., Mobile BFF vs Desktop Web BFF), aggregating multiple downstream calls into client-optimized DTOs.
  3. Internal Gateway / Service Mesh Ingress: Routes East-West traffic between internal VPCs or Kubernetes clusters.

Layer 4 vs. Layer 7 Reverse Proxies

  • Layer 4 (Transport Layer): Proxies raw TCP/UDP byte streams. Extremely high throughput and low CPU overhead, but cannot inspect HTTP paths, headers, cookies, or payloads.
  • Layer 7 (Application Layer): Proxies HTTP/1.1, HTTP/2, HTTP/3, and gRPC. Full visibility into URL paths, headers, and request bodies, enabling intelligent routing, header rewriting, rate limiting, and circuit breaking.

2. YARP (Yet Another Reverse Proxy) Internals

YARP is Microsoft's high-performance reverse proxy toolkit built on top of ASP.NET Core and .NET Kestrel.

1. Route and Cluster Configuration

  • Route (RouteConfig): Defines the incoming match conditions (e.g., path pattern /api/orders/{**catch-all}, allowed HTTP methods, host headers) and links to a target Cluster.
  • Cluster (ClusterConfig): Represents a logical microservice comprised of one or more physical Destinations (IP/port or DNS name).
  • Destinations (DestinationConfig): Individual instances of the service.

2. Request Transform Pipeline

Transforms execute sequentially before the request is forwarded:

  • Header Transforms:
  • RequestHeaderAdd: Injects headers such as X-Forwarded-Prefix, X-Forwarded-For, X-Correlation-ID.
  • RequestHeaderRemove: Strips sensitive internal authentication tokens or client secrets.
  • Path Transforms:
  • PathRemovePrefix: Strips gateway API versioning (e.g., /api/v1/orders/1 $\to$ /orders/1).
  • PathPrefix: Prepends a backend-specific namespace.
  • Query Transforms: Append or sanitize query parameters.

3. Destination Health Checking

  • Active Health Checks: YARP's background worker periodically sends probes (e.g. GET /health) to every registered destination at configured intervals. Destinations that fail consecutive probes are removed from the healthy routing pool.
  • Passive Health Checks: Monitored inline during live traffic. If an attempt to reach a destination results in a connection timeout or 5xx response, YARP immediately marks that destination as degraded without waiting for the next active probe.

4. Load Balancing Policies

  • RoundRobin: Distributes requests sequentially across all healthy destinations.
  • PowerOfTwoChoices: Selects two random healthy destinations and picks the one with the fewest active requests (prevents thundering herd).
  • LeastRequests: Scans all destinations and chooses the one with the lowest active connection count.

3. Graph Algorithms: LeetCode #133 & #695

LeetCode #133: Clone Graph (Medium)

  • Problem: Given a reference of a node in a connected undirected graph, return a deep copy (clone) of the graph.
  • Cyclic Hazard: Graphs often contain cycles ($A \leftrightarrow B$). A naive recursive traversal results in infinite recursion and StackOverflowException.
  • Solution Strategy:
  • Use a hash table Dictionary<Node, Node> mapping each original node to its newly allocated clone.
  • When visiting a node:
  1. If already present in visited, immediately return the clone.
  2. Otherwise, allocate clone = new Node(node.val), register in visited[node] = clone.
  3. Recursively (or via BFS queue) clone each neighbor and append to clone.neighbors.
  • Time Complexity: $\mathcal{O}(V + E)$ where $V$ is vertices and $E$ is edges.
  • Space Complexity: $\mathcal{O}(V)$ for the hash map and traversal stack.

LeetCode #695: Max Area of Island (Medium)

  • Problem: Given an $m \times n$ binary matrix grid, an island is a 4-directionally connected group of 1s. Return the maximum area of an island.
  • Solution Strategy:
  • Iterate through every cell $(r, c)$ in the matrix.
  • When encountering grid[r][c] == 1:
  • Run DFS or BFS to traverse the entire connected component.
  • Sink visited land cells by mutating grid[r][c] = 0 (or using a bool[][] visited set) to ensure every cell is evaluated in $\mathcal{O}(1)$ amortized operations.
  • Accumulate the area (1 + sum(neighbors)) and update maxArea = max(maxArea, currentArea).
  • Time Complexity: $\mathcal{O}(M \times N)$ — every cell is processed at most once.
  • Space Complexity: $\mathcal{O}(M \times N)$ worst-case DFS call stack (or $\mathcal{O}(\min(M, N))$ for BFS queue).

Day 27: Senior & Staff Engineer Interview Questions & Answers

1. What are the definitive architectural distinctions between a Reverse Proxy, an API Gateway, and a Service Mesh?

Answer:

  • Reverse Proxy (e.g., NGINX, HAProxy, basic YARP):
  • Operates primarily at Layer 4 and Layer 7.
  • Sits in front of a pool of servers to provide load balancing, SSL/TLS termination, static caching, and basic route forwarding.
  • Generally stateless, with limited awareness of business domain semantics.
  • API Gateway (e.g., Kong, Apisix, Enterprise YARP):
  • Sits at the perimeter (North-South traffic) between external clients and backend microservices.
  • Provides advanced cross-cutting business and security capabilities: centralized OAuth2/JWT token validation, granular API key rate limiting, request aggregation (BFF pattern), schema validation, response transformation, and monetization metering.
  • Service Mesh (e.g., Istio, Linkerd, Envoy sidecars):
  • Operates entirely internally (East-West traffic) between microservices within a private network or Kubernetes cluster.
  • Uses transparent sidecar proxies to provide mutual TLS (mTLS) with cryptographic identity, distributed tracing, canary traffic splitting, and service-to-service circuit breaking without altering application code.

2. How does YARP achieve competitive performance with NGINX and Envoy despite running on the managed .NET runtime?

Answer:

Historically, managed reverse proxies suffered from Garbage Collection pause times and memory copying overhead. YARP achieves near-C/C++ parity through foundational runtime improvements:

  1. ASP.NET Core Kestrel & SocketsHttpHandler: Built directly on non-allocating socket layers using libuv/epoll/kqueue.
  2. Zero-Copy Pipelines (System.IO.Pipelines): Request and response streams are transferred using rented byte buffers (MemoryPool<byte>) and ReadOnlySequence<byte>, streaming data directly from incoming network sockets to downstream sockets without buffering entire request bodies on the managed heap.
  3. Hardware Intrinsic SIMD & POH: Pinned Object Heap (POH) and vector-accelerated UTF-8 parsing avoid GC compaction latency during heavy header parsing.
  4. C# Extensibility: Unlike NGINX (requiring C modules or Lua) or Envoy (requiring C++ filters), YARP allows .NET engineers to write native C# middleware, dependency injection, and health checks with full debugger support.

3. How does YARP support zero-downtime dynamic configuration reloading without terminating in-flight HTTP requests?

Answer:

YARP decouples proxy configuration from active request processing using the IProxyConfigProvider and change token pattern (IChangeToken).

public class DynamicConfigProvider : IProxyConfigProvider
{
    private volatile CustomMemoryConfig _config;
    public IProxyConfig GetConfig() => _config;

    public void Update(IReadOnlyList<RouteConfig> routes, IReadOnlyList<ClusterConfig> clusters)
    {
        var oldConfig = _config;
        _config = new CustomMemoryConfig(routes, clusters);
        oldConfig.SignalChange(); // Notifies YARP to swap snapshot atomically
    }
}

Reload Mechanics:

  • YARP maintains an immutable snapshot of routes, clusters, and destinations.
  • When SignalChange() fires, YARP compiles a new routing tree in memory and verifies routing syntax.
  • The reference is swapped atomically (Interlocked.Exchange).
  • In-flight requests continue executing against the prior snapshot's destination pools until completed. New incoming requests are dispatched immediately against the newly activated snapshot.

4. What is the difference between Active and Passive Health Checks in YARP, and how do they prevent "Black Hole" cascading failures?

Answer:

  • Active Health Checks:
  • The gateway initiates proactive periodic probes (e.g., GET /health every 10 seconds).
  • Limitation: If a downstream service instance crashes between probe intervals (e.g., second 2 of a 10s interval), requests sent during that 8-second window will fail.
  • Passive Health Checks:
  • The gateway monitors real-time client traffic.
  • If a destination returns transport errors (e.g., connection refused, socket reset) or consecutive HTTP 503s, YARP immediately flags the destination as unhealthy in real time.
  • Preventing "Black Hole" Cascading Failures:
  • If a destination becomes slow or unresponsive, naive active probing might still consider it healthy if it responds to simple /health probes. Passive health checks detect increasing latency or transport timeouts on actual business endpoints and divert traffic immediately.
  • To prevent cascading thundering herd failures where failing one instance overburdens the rest, YARP supports setting minimum healthy percentage thresholds.

5. Why is the "Power of Two Random Choices (P2C)" load balancing policy superior to standard Round-Robin in distributed systems?

Answer:

In simple Round-Robin or Least-Connections:

  • Under rapid concurrent requests, multiple threads or gateway instances read the same connection counter and concurrently assign new requests to the same destination before its active count updates, causing severe latency spikes (herd effect).
  • Round-Robin assumes all requests have equal processing cost and all downstream nodes have identical CPU capacity.

Power of Two Random Choices (P2C) Mechanics:

  1. Pick two candidate destinations at random from the healthy destination pool: $D_1$ and $D_2$.
  2. Inspect their active request counters.
  3. Forward the request to whichever candidate has fewer active requests.
  • Mathematical Foundation (Mitzenmacher, 2001): Selecting the minimum of just two random choices exponentially reduces the maximum queue length from $\mathcal{O}(\frac{\ln N}{\ln \ln N})$ to $\mathcal{O}(\ln \ln N)$, yielding near-optimal load distribution with $\mathcal{O}(1)$ overhead and zero global lock contention.

6. What request transformations must an enterprise API Gateway enforce to prevent Header Smuggling and Spoofing?

Answer:

  1. Sanitize Untrusted Headers: Strip client-supplied internal metadata (e.g. X-User-Id, X-User-Roles, X-Tenant-Id) to prevent malicious clients from impersonating administrators.
  2. Normalize Forwarded Headers: Override X-Forwarded-For with the true TCP remote IP, or append client IP to the existing comma-delimited chain.
  3. Inject Trace Context: Ensure every incoming request receives a W3C traceparent or X-Correlation-ID header for distributed tracing.
  4. Prevent HTTP Request Smuggling: Normalize Transfer-Encoding and Content-Length headers; reject requests containing ambiguous or duplicate framing headers.

7. How does a Gateway-level Token Bucket Rate Limiter differ from downstream service rate limiting?

Answer:

  • Gateway-level Rate Limiting:
  • Acts as the first line of defense against volumetric denial-of-service (DDoS), credential stuffing, and abusive scraping.
  • Rejects excess traffic at the network edge before requests consume internal bandwidth, TLS handshakes with microservices, or database connection pool leases.
  • Partitioned coarse-grained: by Client IP, API Key, or Client Certificate Thumbprint.
  • Downstream Service Rate Limiting:
  • Enforces fine-grained domain constraints (e.g., maximum 5 password reset attempts per user account per hour, maximum 10 checkout submissions per minute).
  • Understands authenticated business domain entities (UserId, AccountId).
  • Best Practice: Defense-in-depth—use coarse-grained Token Bucket rate limiting at the Gateway to protect infrastructure, combined with domain-specific rate limiting in microservices.

8. How does YARP handle protocol upgrading for WebSockets and gRPC?

Answer:

  • WebSockets:
  • YARP inspects the Upgrade: websocket and Connection: Upgrade headers.
  • Once validated, YARP facilitates an opaque, full-duplex TCP/TLS byte stream tunnel between client and downstream server.
  • YARP keeps the connection open until either client or backend initiates closure.
  • gRPC:
  • gRPC requires HTTP/2 with trailer headers (grpc-status, grpc-message).
  • YARP fully supports HTTP/2 end-to-end (Client $\to$ Gateway $\to$ Microservice).
  • YARP preserves HTTP/2 multiplexing and accurately forwards trailing headers, allowing bidirectional streaming RPCs to operate transparently.

9. For LeetCode #133 (Clone Graph), how do you prevent infinite recursion in cyclic graphs, and what is the optimal complexity?

Answer:

Cycle Handling:

An undirected graph containing a cycle (e.g., Node 1 connected to Node 2, which connects back to Node 1) will trap a naive DFS in an infinite loop.

To guarantee termination:

  1. Maintain a hash table Dictionary<Node, Node> mapping original node instances to their newly constructed clones.
  2. Before traversing any neighbor, check if the neighbor has already been cloned.
  3. If already cloned, retrieve the clone from the dictionary and link it immediately.
  4. If not cloned, allocate the clone, insert it into the map before recursing, and then visit its neighbors.

Complexity:

  • Time Complexity: $\mathcal{O}(V + E)$ where $V$ is vertices and $E$ is edges. Every node and edge is traversed once.
  • Space Complexity: $\mathcal{O}(V)$ to store the hash map and call stack recursion.

10. For LeetCode #695 (Max Area of Island), compare in-place grid mutation vs an auxiliary visited set in production environments.

Answer:

  • In-Place Mutation (grid[r][c] = 0):
  • Pros: $\mathcal{O}(1)$ auxiliary space overhead (excluding recursion stack); avoids allocating an $M \times N$ boolean array or hash set.
  • Cons: Mutates input data. In production environments or multi-threaded pipelines, mutating shared data creates race conditions and violates caller immutability expectations.
  • Auxiliary Set / Array (bool[m, n] visited):
  • Pros: Leaves input grid immutable and thread-safe.
  • Cons: Allocates $\mathcal{O}(M \times N)$ additional heap memory, increasing GC ephemeral allocation pressure.
  • Production Standard: If the input grid is disposable or local, in-place sinking is optimal; if exposed via a shared API or cached memory buffer, clone the grid or use a bit array (BitArray or rented memory) to preserve caller data integrity.

public class Node
{
    public int val;
    public IList<Node> neighbors;

    public Node()
    {
        val = 0;
        neighbors = new List<Node>();
    }

    public Node(int _val)
    {
        val = _val;
        neighbors = new List<Node>();
    }

    public Node(int _val, IList<Node> _neighbors)
    {
        val = _val;
        neighbors = _neighbors;
    }
}

/// <summary>
/// Graph and 2D Grid Solvers:
/// 1. LeetCode #133: Clone Graph (Medium)
/// 2. LeetCode #695: Max Area of Island (Medium)
/// </summary>
public class GraphAndIslandSolver
{
    private static readonly int[] RowOffsets = { -1, 1, 0, 0 };
    private static readonly int[] ColOffsets = { 0, 0, -1, 1 };

    /// <summary>
    /// Clones an undirected graph using Depth-First Search (DFS) with a visited lookup map.
    /// Time Complexity: O(V + E) where V is vertices and E is edges.
    /// Space Complexity: O(V) for clone map and recursion stack.
    /// </summary>
    public Node? CloneGraphDfs(Node? node)
    {
        if (node == null) return null;
        var visited = new Dictionary<Node, Node>();
        return DfsClone(node, visited);
    }

    private Node DfsClone(Node node, Dictionary<Node, Node> visited)
    {
        if (visited.TryGetValue(node, out var existingClone))
        {
            return existingClone;
        }

        var clone = new Node(node.val);
        visited[node] = clone;

        foreach (var neighbor in node.neighbors)
        {
            clone.neighbors.Add(DfsClone(neighbor, visited));
        }

        return clone;
    }

    /// <summary>
    /// Clones an undirected graph using Breadth-First Search (BFS) with a FIFO queue.
    /// Time Complexity: O(V + E)
    /// Space Complexity: O(V)
    /// </summary>
    public Node? CloneGraphBfs(Node? node)
    {
        if (node == null) return null;

        var visited = new Dictionary<Node, Node>();
        var queue = new Queue<Node>();

        var cloneRoot = new Node(node.val);
        visited[node] = cloneRoot;
        queue.Enqueue(node);

        while (queue.Count > 0)
        {
            var current = queue.Dequeue();

            foreach (var neighbor in current.neighbors)
            {
                if (!visited.TryGetValue(neighbor, out var neighborClone))
                {
                    neighborClone = new Node(neighbor.val);
                    visited[neighbor] = neighborClone;
                    queue.Enqueue(neighbor);
                }

                visited[current].neighbors.Add(neighborClone);
            }
        }

        return cloneRoot;
    }

    /// <summary>
    /// Computes the maximum area of an island using Depth-First Search (DFS).
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(M * N) recursion stack.
    /// </summary>
    public int MaxAreaOfIslandDfs(int[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0) return 0;

        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new int[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (int[])grid[i].Clone();
        }

        var maxArea = 0;
        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == 1)
                {
                    var area = DfsSinkArea(workingGrid, r, c, m, n);
                    maxArea = Math.Max(maxArea, area);
                }
            }
        }

        return maxArea;
    }

    private int DfsSinkArea(int[][] grid, int r, int c, int m, int n)
    {
        if (r < 0 || r >= m || c < 0 || c >= n || grid[r][c] != 1)
            return 0;

        // Sink cell to 0 to prevent re-counting
        grid[r][c] = 0;
        var area = 1;

        for (var i = 0; i < 4; i++)
        {
            area += DfsSinkArea(grid, r + RowOffsets[i], c + ColOffsets[i], m, n);
        }

        return area;
    }

    /// <summary>
    /// Computes the maximum area of an island using Breadth-First Search (BFS).
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(min(M, N))
    /// </summary>
    public int MaxAreaOfIslandBfs(int[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0) return 0;

        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new int[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (int[])grid[i].Clone();
        }

        var maxArea = 0;
        var queue = new Queue<(int r, int c)>();

        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == 1)
                {
                    workingGrid[r][c] = 0; // sink immediately
                    queue.Enqueue((r, c));
                    var currentArea = 0;

                    while (queue.Count > 0)
                    {
                        var (currR, currC) = queue.Dequeue();
                        currentArea++;

                        for (var i = 0; i < 4; i++)
                        {
                            var nr = currR + RowOffsets[i];
                            var nc = currC + ColOffsets[i];

                            if (nr >= 0 && nr < m && nc >= 0 && nc < n && workingGrid[nr][nc] == 1)
                            {
                                workingGrid[nr][nc] = 0;
                                queue.Enqueue((nr, nc));
                            }
                        }
                    }

                    maxArea = Math.Max(maxArea, currentArea);
                }
            }
        }

        return maxArea;
    }
}

/// <summary>
/// Gateway Token Bucket Rate Limiter partitioned by Client IP or API Key.
/// </summary>
public class GatewayRateLimiter
{
    private readonly int _capacity;
    private readonly double _refillRatePerSecond;
    private readonly ConcurrentDictionary<string, TokenBucket> _clientBuckets = new();

    public GatewayRateLimiter(int capacity, double refillRatePerSecond)
    {
        if (capacity <= 0) throw new ArgumentOutOfRangeException(nameof(capacity));
        if (refillRatePerSecond <= 0) throw new ArgumentOutOfRangeException(nameof(refillRatePerSecond));

        _capacity = capacity;
        _refillRatePerSecond = refillRatePerSecond;
    }

    public bool TryConsume(string clientKey, out int remainingTokens, out TimeSpan retryAfter)
    {
        var bucket = _clientBuckets.GetOrAdd(clientKey, _ => new TokenBucket(_capacity, _refillRatePerSecond));
        return bucket.TryConsume(out remainingTokens, out retryAfter);
    }

    private class TokenBucket
    {
        private readonly int _maxTokens;
        private readonly double _refillRate;
        private double _currentTokens;
        private DateTime _lastRefillUtc;
        private readonly object _lock = new();

        public TokenBucket(int maxTokens, double refillRate)
        {
            _maxTokens = maxTokens;
            _refillRate = refillRate;
            _currentTokens = maxTokens;
            _lastRefillUtc = DateTime.UtcNow;
        }

        public bool TryConsume(out int remaining, out TimeSpan retryAfter)
        {
            lock (_lock)
            {
                var now = DateTime.UtcNow;
                var elapsed = (now - _lastRefillUtc).TotalSeconds;
                _currentTokens = Math.Min(_maxTokens, _currentTokens + (elapsed * _refillRate));
                _lastRefillUtc = now;

                if (_currentTokens >= 1.0)
                {
                    _currentTokens -= 1.0;
                    remaining = (int)_currentTokens;
                    retryAfter = TimeSpan.Zero;
                    return true;
                }

                remaining = 0;
                var missingTokens = 1.0 - _currentTokens;
                retryAfter = TimeSpan.FromSeconds(Math.Ceiling(missingTokens / _refillRate));
                return false;
            }
        }
    }
}

/// <summary>
/// High-throughput simulated YARP Reverse Proxy Engine.
/// Handles route dispatching, request transformation, health check filtering, and destination load balancing.
/// </summary>
public class YarpGatewayEngine
{
    private readonly List<RouteConfig> _routes = new();
    private readonly Dictionary<string, List<DownstreamDestination>> _clusterDestinations = new();
    private readonly ConcurrentDictionary<string, int> _clusterRoundRobinIndices = new();
    private readonly GatewayRateLimiter _rateLimiter;
    private readonly TransformRule _globalTransforms;

    public YarpGatewayEngine(GatewayRateLimiter rateLimiter, TransformRule? globalTransforms = null)
    {
        _rateLimiter = rateLimiter;
        _globalTransforms = globalTransforms ?? new TransformRule();
    }

    public void RegisterRoute(RouteConfig route)
    {
        _routes.Add(route);
    }

    public void RegisterCluster(string clusterId, IEnumerable<DownstreamDestination> destinations)
    {
        _clusterDestinations[clusterId] = destinations.ToList();
        _clusterRoundRobinIndices[clusterId] = 0;
    }

    /// <summary>
    /// Processes an incoming request through Rate Limiter, Route Matching, Transform Pipeline, and Load Balancer.
    /// </summary>
    public GatewayProxyResult Forward(GatewayRequest request)
    {
        // 1. Rate Limiting Check
        if (!_rateLimiter.TryConsume(request.ClientIp, out var remainingTokens, out var retryAfter))
        {
            return new GatewayProxyResult(
                StatusCode: 429,
                ErrorMessage: "Rate limit exceeded. Try again later.",
                TransformedHeaders: new Dictionary<string, string>
                {
                    ["Retry-After"] = ((int)retryAfter.TotalSeconds).ToString(),
                    ["X-RateLimit-Remaining"] = "0"
                });
        }

        // 2. Route Matching
        var matchedRoute = FindMatchingRoute(request.Path);
        if (matchedRoute == null)
        {
            return new GatewayProxyResult(
                StatusCode: 404,
                ErrorMessage: $"No matching YARP route found for path: {request.Path}");
        }

        // 3. Cluster & Healthy Destination Selection
        if (!_clusterDestinations.TryGetValue(matchedRoute.ClusterId ?? string.Empty, out var destinations))
        {
            return new GatewayProxyResult(
                StatusCode: 502,
                ErrorMessage: $"Target cluster '{matchedRoute.ClusterId}' not configured.");
        }

        var healthyDestinations = destinations
            .Where(d => d.HealthStatus == DestinationHealthStatus.Healthy)
            .ToList();

        if (healthyDestinations.Count == 0)
        {
            return new GatewayProxyResult(
                StatusCode: 503,
                ErrorMessage: $"All destinations for cluster '{matchedRoute.ClusterId}' are unhealthy.");
        }

        // Round-Robin selection over healthy destinations
        var index = _clusterRoundRobinIndices.AddOrUpdate(
            matchedRoute.ClusterId!,
            0,
            (_, curr) => (curr + 1) % healthyDestinations.Count);
        var targetDestination = healthyDestinations[index % healthyDestinations.Count];

        // 4. Request Transformation
        var transformedHeaders = ApplyHeaderTransforms(request.Headers);
        transformedHeaders["X-RateLimit-Remaining"] = remainingTokens.ToString();
        transformedHeaders["X-Forwarded-Host"] = request.Host;
        transformedHeaders["X-Forwarded-For"] = request.ClientIp;
        if (!transformedHeaders.ContainsKey("X-Correlation-ID"))
        {
            transformedHeaders["X-Correlation-ID"] = Guid.NewGuid().ToString("N");
        }

        var transformedPath = ApplyPathTransforms(request.Path, matchedRoute);

        return new GatewayProxyResult(
            StatusCode: 200,
            DestinationId: targetDestination.Id,
            DestinationUri: new Uri(targetDestination.Address, transformedPath.TrimStart('/')),
            TransformedPath: transformedPath,
            TransformedHeaders: transformedHeaders);
    }

    private RouteConfig? FindMatchingRoute(string path)
    {
        foreach (var route in _routes)
        {
            if (string.IsNullOrEmpty(route.Match.Path)) continue;

            // Simplified prefix & wildcards matching (e.g. /api/orders/{**catch-all} or /api/orders)
            var pattern = route.Match.Path
                .Replace("{**catch-all}", ".*")
                .Replace("{**remainder}", ".*");

            if (Regex.IsMatch(path, $"^{pattern}$", RegexOptions.IgnoreCase))
            {
                return route;
            }
        }
        return null;
    }

    private Dictionary<string, string> ApplyHeaderTransforms(IReadOnlyDictionary<string, string> incomingHeaders)
    {
        var headers = new Dictionary<string, string>(incomingHeaders, StringComparer.OrdinalIgnoreCase);

        // Strip disallowed headers
        foreach (var removeKey in _globalTransforms.RemoveHeaders)
        {
            headers.Remove(removeKey);
        }

        // Add configured headers
        foreach (var (k, v) in _globalTransforms.AddHeaders)
        {
            headers[k] = v;
        }

        return headers;
    }

    private string ApplyPathTransforms(string incomingPath, RouteConfig route)
    {
        var path = incomingPath;

        if (_globalTransforms.PathRemovePrefix != null && path.StartsWith(_globalTransforms.PathRemovePrefix, StringComparison.OrdinalIgnoreCase))
        {
            path = path[_globalTransforms.PathRemovePrefix.Length..];
        }

        if (_globalTransforms.PathAddPrefix != null)
        {
            path = _globalTransforms.PathAddPrefix.TrimEnd('/') + "/" + path.TrimStart('/');
        }

        return string.IsNullOrEmpty(path) ? "/" : path;
    }
}

1. The API Gateway Architectural Pattern

In a microservices topology, client applications (web SPAs, mobile apps, IoT devices, third-party partners) should not directly communicate with dozens of discrete backend microservices. Doing so leaks internal service topology, creates tight coupling, and requires each service to reimplement authentication, rate limiting, and SSL termination.

Key Gateway Topologies

  1. Edge Gateway: Central entry point handling public internet traffic, DDoS mitigation, and global TLS termination.
  2. Backend for Frontend (BFF): Tailored gateways for specific client experiences (e.g., Mobile BFF vs Desktop Web BFF), aggregating multiple downstream calls into client-optimized DTOs.
  3. Internal Gateway / Service Mesh Ingress: Routes East-West traffic between internal VPCs or Kubernetes clusters.

Layer 4 vs. Layer 7 Reverse Proxies

  • Layer 4 (Transport Layer): Proxies raw TCP/UDP byte streams. Extremely high throughput and low CPU overhead, but cannot inspect HTTP paths, headers, cookies, or payloads.
  • Layer 7 (Application Layer): Proxies HTTP/1.1, HTTP/2, HTTP/3, and gRPC. Full visibility into URL paths, headers, and request bodies, enabling intelligent routing, header rewriting, rate limiting, and circuit breaking.

2. YARP (Yet Another Reverse Proxy) Internals

YARP is Microsoft's high-performance reverse proxy toolkit built on top of ASP.NET Core and .NET Kestrel.

1. Route and Cluster Configuration

  • Route (RouteConfig): Defines the incoming match conditions (e.g., path pattern /api/orders/{**catch-all}, allowed HTTP methods, host headers) and links to a target Cluster.
  • Cluster (ClusterConfig): Represents a logical microservice comprised of one or more physical Destinations (IP/port or DNS name).
  • Destinations (DestinationConfig): Individual instances of the service.

2. Request Transform Pipeline

Transforms execute sequentially before the request is forwarded:

  • Header Transforms:
  • RequestHeaderAdd: Injects headers such as X-Forwarded-Prefix, X-Forwarded-For, X-Correlation-ID.
  • RequestHeaderRemove: Strips sensitive internal authentication tokens or client secrets.
  • Path Transforms:
  • PathRemovePrefix: Strips gateway API versioning (e.g., /api/v1/orders/1 $\to$ /orders/1).
  • PathPrefix: Prepends a backend-specific namespace.
  • Query Transforms: Append or sanitize query parameters.

3. Destination Health Checking

  • Active Health Checks: YARP's background worker periodically sends probes (e.g. GET /health) to every registered destination at configured intervals. Destinations that fail consecutive probes are removed from the healthy routing pool.
  • Passive Health Checks: Monitored inline during live traffic. If an attempt to reach a destination results in a connection timeout or 5xx response, YARP immediately marks that destination as degraded without waiting for the next active probe.

4. Load Balancing Policies

  • RoundRobin: Distributes requests sequentially across all healthy destinations.
  • PowerOfTwoChoices: Selects two random healthy destinations and picks the one with the fewest active requests (prevents thundering herd).
  • LeastRequests: Scans all destinations and chooses the one with the lowest active connection count.

3. Graph Algorithms: LeetCode #133 & #695

LeetCode #133: Clone Graph (Medium)

  • Problem: Given a reference of a node in a connected undirected graph, return a deep copy (clone) of the graph.
  • Cyclic Hazard: Graphs often contain cycles ($A \leftrightarrow B$). A naive recursive traversal results in infinite recursion and StackOverflowException.
  • Solution Strategy:
  • Use a hash table Dictionary<Node, Node> mapping each original node to its newly allocated clone.
  • When visiting a node:
  1. If already present in visited, immediately return the clone.
  2. Otherwise, allocate clone = new Node(node.val), register in visited[node] = clone.
  3. Recursively (or via BFS queue) clone each neighbor and append to clone.neighbors.
  • Time Complexity: $\mathcal{O}(V + E)$ where $V$ is vertices and $E$ is edges.
  • Space Complexity: $\mathcal{O}(V)$ for the hash map and traversal stack.

LeetCode #695: Max Area of Island (Medium)

  • Problem: Given an $m \times n$ binary matrix grid, an island is a 4-directionally connected group of 1s. Return the maximum area of an island.
  • Solution Strategy:
  • Iterate through every cell $(r, c)$ in the matrix.
  • When encountering grid[r][c] == 1:
  • Run DFS or BFS to traverse the entire connected component.
  • Sink visited land cells by mutating grid[r][c] = 0 (or using a bool[][] visited set) to ensure every cell is evaluated in $\mathcal{O}(1)$ amortized operations.
  • Accumulate the area (1 + sum(neighbors)) and update maxArea = max(maxArea, currentArea).
  • Time Complexity: $\mathcal{O}(M \times N)$ — every cell is processed at most once.
  • Space Complexity: $\mathcal{O}(M \times N)$ worst-case DFS call stack (or $\mathcal{O}(\min(M, N))$ for BFS queue).

We explore reverse proxy routing architectures, transform pipelines (header forwarding/removal, path rewriting), active & passive health check monitoring, and distributed token bucket rate limiting at the gateway layer. For DSA, we tackle **LeetCode #133 (Clone Graph) using visited hash map node tracking across cyclic graphs and LeetCode #695 (Max Area of Island)** using recursive DFS and iterative BFS.

  • Routes, Clusters, Destinations, and Match Criteria (Path, Hosts, Headers).
  • Active Health Checks (Interval, Timeout, ConsecutiveFailuresPolicy, /health probes) vs Passive Failure detection.
  • Load Balancing Policies: RoundRobin, PowerOfTwoChoices, LeastRequests.
  1. Gateway Transform Pipeline:
  • Header enrichment: Injecting X-Forwarded-Prefix, X-Forwarded-For, X-Forwarded-Host, X-Correlation-ID.
  • Header sanitization: Stripping internal secrets, confidential tokens, and sensitive headers before forwarding downstream.
  • Path transformations: PathRemovePrefix and prefix routing to backends.
  1. Gateway Rate Limiting:
  • Token Bucket rate limiting partitioned by Client IP or API Key.
  • Emission of standard RFC headers (Retry-After, X-RateLimit-Remaining) and HTTP 429 Too Many Requests.
  1. Graph Algorithms:
  • LeetCode #133: Clone Graph (Medium): Deep copy of an undirected cyclic graph using a Dictionary<Node, Node> to resolve cyclic dependencies in $\mathcal{O}(V + E)$ time.
  • LeetCode #695: Max Area of Island (Medium): Finding the largest connected 4-directional component on a 2D binary grid in $\mathcal{O}(M \times N)$ time.

Day 27: Senior & Staff Engineer Interview Questions & Answers

1. What are the definitive architectural distinctions between a Reverse Proxy, an API Gateway, and a Service Mesh?

Answer:

  • Reverse Proxy (e.g., NGINX, HAProxy, basic YARP):
  • Operates primarily at Layer 4 and Layer 7.
  • Sits in front of a pool of servers to provide load balancing, SSL/TLS termination, static caching, and basic route forwarding.
  • Generally stateless, with limited awareness of business domain semantics.
  • API Gateway (e.g., Kong, Apisix, Enterprise YARP):
  • Sits at the perimeter (North-South traffic) between external clients and backend microservices.
  • Provides advanced cross-cutting business and security capabilities: centralized OAuth2/JWT token validation, granular API key rate limiting, request aggregation (BFF pattern), schema validation, response transformation, and monetization metering.
  • Service Mesh (e.g., Istio, Linkerd, Envoy sidecars):
  • Operates entirely internally (East-West traffic) between microservices within a private network or Kubernetes cluster.
  • Uses transparent sidecar proxies to provide mutual TLS (mTLS) with cryptographic identity, distributed tracing, canary traffic splitting, and service-to-service circuit breaking without altering application code.

2. How does YARP achieve competitive performance with NGINX and Envoy despite running on the managed .NET runtime?

Answer:

Historically, managed reverse proxies suffered from Garbage Collection pause times and memory copying overhead. YARP achieves near-C/C++ parity through foundational runtime improvements:

  1. ASP.NET Core Kestrel & SocketsHttpHandler: Built directly on non-allocating socket layers using libuv/epoll/kqueue.
  2. Zero-Copy Pipelines (System.IO.Pipelines): Request and response streams are transferred using rented byte buffers (MemoryPool<byte>) and ReadOnlySequence<byte>, streaming data directly from incoming network sockets to downstream sockets without buffering entire request bodies on the managed heap.
  3. Hardware Intrinsic SIMD & POH: Pinned Object Heap (POH) and vector-accelerated UTF-8 parsing avoid GC compaction latency during heavy header parsing.
  4. C# Extensibility: Unlike NGINX (requiring C modules or Lua) or Envoy (requiring C++ filters), YARP allows .NET engineers to write native C# middleware, dependency injection, and health checks with full debugger support.

3. How does YARP support zero-downtime dynamic configuration reloading without terminating in-flight HTTP requests?

Answer:

YARP decouples proxy configuration from active request processing using the IProxyConfigProvider and change token pattern (IChangeToken).

public class DynamicConfigProvider : IProxyConfigProvider
{
    private volatile CustomMemoryConfig _config;
    public IProxyConfig GetConfig() => _config;

    public void Update(IReadOnlyList<RouteConfig> routes, IReadOnlyList<ClusterConfig> clusters)
    {
        var oldConfig = _config;
        _config = new CustomMemoryConfig(routes, clusters);
        oldConfig.SignalChange(); // Notifies YARP to swap snapshot atomically
    }
}

Reload Mechanics:

  • YARP maintains an immutable snapshot of routes, clusters, and destinations.
  • When SignalChange() fires, YARP compiles a new routing tree in memory and verifies routing syntax.
  • The reference is swapped atomically (Interlocked.Exchange).
  • In-flight requests continue executing against the prior snapshot's destination pools until completed. New incoming requests are dispatched immediately against the newly activated snapshot.

4. What is the difference between Active and Passive Health Checks in YARP, and how do they prevent "Black Hole" cascading failures?

Answer:

  • Active Health Checks:
  • The gateway initiates proactive periodic probes (e.g., GET /health every 10 seconds).
  • Limitation: If a downstream service instance crashes between probe intervals (e.g., second 2 of a 10s interval), requests sent during that 8-second window will fail.
  • Passive Health Checks:
  • The gateway monitors real-time client traffic.
  • If a destination returns transport errors (e.g., connection refused, socket reset) or consecutive HTTP 503s, YARP immediately flags the destination as unhealthy in real time.
  • Preventing "Black Hole" Cascading Failures:
  • If a destination becomes slow or unresponsive, naive active probing might still consider it healthy if it responds to simple /health probes. Passive health checks detect increasing latency or transport timeouts on actual business endpoints and divert traffic immediately.
  • To prevent cascading thundering herd failures where failing one instance overburdens the rest, YARP supports setting minimum healthy percentage thresholds.

5. Why is the "Power of Two Random Choices (P2C)" load balancing policy superior to standard Round-Robin in distributed systems?

Answer:

In simple Round-Robin or Least-Connections:

  • Under rapid concurrent requests, multiple threads or gateway instances read the same connection counter and concurrently assign new requests to the same destination before its active count updates, causing severe latency spikes (herd effect).
  • Round-Robin assumes all requests have equal processing cost and all downstream nodes have identical CPU capacity.

Power of Two Random Choices (P2C) Mechanics:

  1. Pick two candidate destinations at random from the healthy destination pool: $D_1$ and $D_2$.
  2. Inspect their active request counters.
  3. Forward the request to whichever candidate has fewer active requests.
  • Mathematical Foundation (Mitzenmacher, 2001): Selecting the minimum of just two random choices exponentially reduces the maximum queue length from $\mathcal{O}(\frac{\ln N}{\ln \ln N})$ to $\mathcal{O}(\ln \ln N)$, yielding near-optimal load distribution with $\mathcal{O}(1)$ overhead and zero global lock contention.

6. What request transformations must an enterprise API Gateway enforce to prevent Header Smuggling and Spoofing?

Answer:

  1. Sanitize Untrusted Headers: Strip client-supplied internal metadata (e.g. X-User-Id, X-User-Roles, X-Tenant-Id) to prevent malicious clients from impersonating administrators.
  2. Normalize Forwarded Headers: Override X-Forwarded-For with the true TCP remote IP, or append client IP to the existing comma-delimited chain.
  3. Inject Trace Context: Ensure every incoming request receives a W3C traceparent or X-Correlation-ID header for distributed tracing.
  4. Prevent HTTP Request Smuggling: Normalize Transfer-Encoding and Content-Length headers; reject requests containing ambiguous or duplicate framing headers.

7. How does a Gateway-level Token Bucket Rate Limiter differ from downstream service rate limiting?

Answer:

  • Gateway-level Rate Limiting:
  • Acts as the first line of defense against volumetric denial-of-service (DDoS), credential stuffing, and abusive scraping.
  • Rejects excess traffic at the network edge before requests consume internal bandwidth, TLS handshakes with microservices, or database connection pool leases.
  • Partitioned coarse-grained: by Client IP, API Key, or Client Certificate Thumbprint.
  • Downstream Service Rate Limiting:
  • Enforces fine-grained domain constraints (e.g., maximum 5 password reset attempts per user account per hour, maximum 10 checkout submissions per minute).
  • Understands authenticated business domain entities (UserId, AccountId).
  • Best Practice: Defense-in-depth—use coarse-grained Token Bucket rate limiting at the Gateway to protect infrastructure, combined with domain-specific rate limiting in microservices.

8. How does YARP handle protocol upgrading for WebSockets and gRPC?

Answer:

  • WebSockets:
  • YARP inspects the Upgrade: websocket and Connection: Upgrade headers.
  • Once validated, YARP facilitates an opaque, full-duplex TCP/TLS byte stream tunnel between client and downstream server.
  • YARP keeps the connection open until either client or backend initiates closure.
  • gRPC:
  • gRPC requires HTTP/2 with trailer headers (grpc-status, grpc-message).
  • YARP fully supports HTTP/2 end-to-end (Client $\to$ Gateway $\to$ Microservice).
  • YARP preserves HTTP/2 multiplexing and accurately forwards trailing headers, allowing bidirectional streaming RPCs to operate transparently.

9. For LeetCode #133 (Clone Graph), how do you prevent infinite recursion in cyclic graphs, and what is the optimal complexity?

Answer:

Cycle Handling:

An undirected graph containing a cycle (e.g., Node 1 connected to Node 2, which connects back to Node 1) will trap a naive DFS in an infinite loop.

To guarantee termination:

  1. Maintain a hash table Dictionary<Node, Node> mapping original node instances to their newly constructed clones.
  2. Before traversing any neighbor, check if the neighbor has already been cloned.
  3. If already cloned, retrieve the clone from the dictionary and link it immediately.
  4. If not cloned, allocate the clone, insert it into the map before recursing, and then visit its neighbors.

Complexity:

  • Time Complexity: $\mathcal{O}(V + E)$ where $V$ is vertices and $E$ is edges. Every node and edge is traversed once.
  • Space Complexity: $\mathcal{O}(V)$ to store the hash map and call stack recursion.

10. For LeetCode #695 (Max Area of Island), compare in-place grid mutation vs an auxiliary visited set in production environments.

Answer:

  • In-Place Mutation (grid[r][c] = 0):
  • Pros: $\mathcal{O}(1)$ auxiliary space overhead (excluding recursion stack); avoids allocating an $M \times N$ boolean array or hash set.
  • Cons: Mutates input data. In production environments or multi-threaded pipelines, mutating shared data creates race conditions and violates caller immutability expectations.
  • Auxiliary Set / Array (bool[m, n] visited):
  • Pros: Leaves input grid immutable and thread-safe.
  • Cons: Allocates $\mathcal{O}(M \times N)$ additional heap memory, increasing GC ephemeral allocation pressure.
  • Production Standard: If the input grid is disposable or local, in-place sinking is optimal; if exposed via a shared API or cached memory buffer, clone the grid or use a bit array (BitArray or rented memory) to preserve caller data integrity.

/// <summary>
/// Graph and 2D Grid Solvers:
/// 1. LeetCode #133: Clone Graph (Medium)
/// 2. LeetCode #695: Max Area of Island (Medium)
/// </summary>
public class GraphAndIslandSolver
{
    private static readonly int[] RowOffsets = { -1, 1, 0, 0 };
    private static readonly int[] ColOffsets = { 0, 0, -1, 1 };

    /// <summary>
    /// Clones an undirected graph using Depth-First Search (DFS) with a visited lookup map.
    /// Time Complexity: O(V + E) where V is vertices and E is edges.
    /// Space Complexity: O(V) for clone map and recursion stack.
    /// </summary>
    public Node? CloneGraphDfs(Node? node)
    {
        if (node == null) return null;
        var visited = new Dictionary<Node, Node>();
        return DfsClone(node, visited);
    }

    private Node DfsClone(Node node, Dictionary<Node, Node> visited)
    {
        if (visited.TryGetValue(node, out var existingClone))
        {
            return existingClone;
        }

        var clone = new Node(node.val);
        visited[node] = clone;

        foreach (var neighbor in node.neighbors)
        {
            clone.neighbors.Add(DfsClone(neighbor, visited));
        }

        return clone;
    }

    /// <summary>
    /// Clones an undirected graph using Breadth-First Search (BFS) with a FIFO queue.
    /// Time Complexity: O(V + E)
    /// Space Complexity: O(V)
    /// </summary>
    public Node? CloneGraphBfs(Node? node)
    {
        if (node == null) return null;

        var visited = new Dictionary<Node, Node>();
        var queue = new Queue<Node>();

        var cloneRoot = new Node(node.val);
        visited[node] = cloneRoot;
        queue.Enqueue(node);

        while (queue.Count > 0)
        {
            var current = queue.Dequeue();

            foreach (var neighbor in current.neighbors)
            {
                if (!visited.TryGetValue(neighbor, out var neighborClone))
                {
                    neighborClone = new Node(neighbor.val);
                    visited[neighbor] = neighborClone;
                    queue.Enqueue(neighbor);
                }

                visited[current].neighbors.Add(neighborClone);
            }
        }

        return cloneRoot;
    }

    /// <summary>
    /// Computes the maximum area of an island using Depth-First Search (DFS).
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(M * N) recursion stack.
    /// </summary>
    public int MaxAreaOfIslandDfs(int[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0) return 0;

        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new int[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (int[])grid[i].Clone();
        }

        var maxArea = 0;
        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == 1)
                {
                    var area = DfsSinkArea(workingGrid, r, c, m, n);
                    maxArea = Math.Max(maxArea, area);
                }
            }
        }

        return maxArea;
    }

    private int DfsSinkArea(int[][] grid, int r, int c, int m, int n)
    {
        if (r < 0 || r >= m || c < 0 || c >= n || grid[r][c] != 1)
            return 0;

        // Sink cell to 0 to prevent re-counting
        grid[r][c] = 0;
        var area = 1;

        for (var i = 0; i < 4; i++)
        {
            area += DfsSinkArea(grid, r + RowOffsets[i], c + ColOffsets[i], m, n);
        }

        return area;
    }

    /// <summary>
    /// Computes the maximum area of an island using Breadth-First Search (BFS).
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(min(M, N))
    /// </summary>
    public int MaxAreaOfIslandBfs(int[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0) return 0;

        var m = grid.Length;
        var n = grid[0].Length;
        var workingGrid = new int[m][];
        for (var i = 0; i < m; i++)
        {
            workingGrid[i] = (int[])grid[i].Clone();
        }

        var maxArea = 0;
        var queue = new Queue<(int r, int c)>();

        for (var r = 0; r < m; r++)
        {
            for (var c = 0; c < n; c++)
            {
                if (workingGrid[r][c] == 1)
                {
                    workingGrid[r][c] = 0; // sink immediately
                    queue.Enqueue((r, c));
                    var currentArea = 0;

                    while (queue.Count > 0)
                    {
                        var (currR, currC) = queue.Dequeue();
                        currentArea++;

                        for (var i = 0; i < 4; i++)
                        {
                            var nr = currR + RowOffsets[i];
                            var nc = currC + ColOffsets[i];

                            if (nr >= 0 && nr < m && nc >= 0 && nc < n && workingGrid[nr][nc] == 1)
                            {
                                workingGrid[nr][nc] = 0;
                                queue.Enqueue((nr, nc));
                            }
                        }
                    }

                    maxArea = Math.Max(maxArea, currentArea);
                }
            }
        }

        return maxArea;
    }
}

/// <summary>
/// Gateway Token Bucket Rate Limiter partitioned by Client IP or API Key.
/// </summary>
public class GatewayRateLimiter
{
    private readonly int _capacity;
    private readonly double _refillRatePerSecond;
    private readonly ConcurrentDictionary<string, TokenBucket> _clientBuckets = new();

    public GatewayRateLimiter(int capacity, double refillRatePerSecond)
    {
        if (capacity <= 0) throw new ArgumentOutOfRangeException(nameof(capacity));
        if (refillRatePerSecond <= 0) throw new ArgumentOutOfRangeException(nameof(refillRatePerSecond));

        _capacity = capacity;
        _refillRatePerSecond = refillRatePerSecond;
    }

    public bool TryConsume(string clientKey, out int remainingTokens, out TimeSpan retryAfter)
    {
        var bucket = _clientBuckets.GetOrAdd(clientKey, _ => new TokenBucket(_capacity, _refillRatePerSecond));
        return bucket.TryConsume(out remainingTokens, out retryAfter);
    }

    private class TokenBucket
    {
        private readonly int _maxTokens;
        private readonly double _refillRate;
        private double _currentTokens;
        private DateTime _lastRefillUtc;
        private readonly object _lock = new();

        public TokenBucket(int maxTokens, double refillRate)
        {
            _maxTokens = maxTokens;
            _refillRate = refillRate;
            _currentTokens = maxTokens;
            _lastRefillUtc = DateTime.UtcNow;
        }

        public bool TryConsume(out int remaining, out TimeSpan retryAfter)
        {
            lock (_lock)
            {
                var now = DateTime.UtcNow;
                var elapsed = (now - _lastRefillUtc).TotalSeconds;
                _currentTokens = Math.Min(_maxTokens, _currentTokens + (elapsed * _refillRate));
                _lastRefillUtc = now;

                if (_currentTokens >= 1.0)
                {
                    _currentTokens -= 1.0;
                    remaining = (int)_currentTokens;
                    retryAfter = TimeSpan.Zero;
                    return true;
                }

                remaining = 0;
                var missingTokens = 1.0 - _currentTokens;
                retryAfter = TimeSpan.FromSeconds(Math.Ceiling(missingTokens / _refillRate));
                return false;
            }
        }
    }
}

/// <summary>
/// High-throughput simulated YARP Reverse Proxy Engine.
/// Handles route dispatching, request transformation, health check filtering, and destination load balancing.
/// </summary>
public class YarpGatewayEngine
{
    private readonly List<RouteConfig> _routes = new();
    private readonly Dictionary<string, List<DownstreamDestination>> _clusterDestinations = new();
    private readonly ConcurrentDictionary<string, int> _clusterRoundRobinIndices = new();
    private readonly GatewayRateLimiter _rateLimiter;
    private readonly TransformRule _globalTransforms;

    public YarpGatewayEngine(GatewayRateLimiter rateLimiter, TransformRule? globalTransforms = null)
    {
        _rateLimiter = rateLimiter;
        _globalTransforms = globalTransforms ?? new TransformRule();
    }

    public void RegisterRoute(RouteConfig route)
    {
        _routes.Add(route);
    }

    public void RegisterCluster(string clusterId, IEnumerable<DownstreamDestination> destinations)
    {
        _clusterDestinations[clusterId] = destinations.ToList();
        _clusterRoundRobinIndices[clusterId] = 0;
    }

    /// <summary>
    /// Processes an incoming request through Rate Limiter, Route Matching, Transform Pipeline, and Load Balancer.
    /// </summary>
    public GatewayProxyResult Forward(GatewayRequest request)
    {
        // 1. Rate Limiting Check
        if (!_rateLimiter.TryConsume(request.ClientIp, out var remainingTokens, out var retryAfter))
        {
            return new GatewayProxyResult(
                StatusCode: 429,
                ErrorMessage: "Rate limit exceeded. Try again later.",
                TransformedHeaders: new Dictionary<string, string>
                {
                    ["Retry-After"] = ((int)retryAfter.TotalSeconds).ToString(),
                    ["X-RateLimit-Remaining"] = "0"
                });
        }

        // 2. Route Matching
        var matchedRoute = FindMatchingRoute(request.Path);
        if (matchedRoute == null)
        {
            return new GatewayProxyResult(
                StatusCode: 404,
                ErrorMessage: $"No matching YARP route found for path: {request.Path}");
        }

        // 3. Cluster & Healthy Destination Selection
        if (!_clusterDestinations.TryGetValue(matchedRoute.ClusterId ?? string.Empty, out var destinations))
        {
            return new GatewayProxyResult(
                StatusCode: 502,
                ErrorMessage: $"Target cluster '{matchedRoute.ClusterId}' not configured.");
        }

        var healthyDestinations = destinations
            .Where(d => d.HealthStatus == DestinationHealthStatus.Healthy)
            .ToList();

        if (healthyDestinations.Count == 0)
        {
            return new GatewayProxyResult(
                StatusCode: 503,
                ErrorMessage: $"All destinations for cluster '{matchedRoute.ClusterId}' are unhealthy.");
        }

        // Round-Robin selection over healthy destinations
        var index = _clusterRoundRobinIndices.AddOrUpdate(
            matchedRoute.ClusterId!,
            0,
            (_, curr) => (curr + 1) % healthyDestinations.Count);
        var targetDestination = healthyDestinations[index % healthyDestinations.Count];

        // 4. Request Transformation
        var transformedHeaders = ApplyHeaderTransforms(request.Headers);
        transformedHeaders["X-RateLimit-Remaining"] = remainingTokens.ToString();
        transformedHeaders["X-Forwarded-Host"] = request.Host;
        transformedHeaders["X-Forwarded-For"] = request.ClientIp;
        if (!transformedHeaders.ContainsKey("X-Correlation-ID"))
        {
            transformedHeaders["X-Correlation-ID"] = Guid.NewGuid().ToString("N");
        }

        var transformedPath = ApplyPathTransforms(request.Path, matchedRoute);

        return new GatewayProxyResult(
            StatusCode: 200,
            DestinationId: targetDestination.Id,
            DestinationUri: new Uri(targetDestination.Address, transformedPath.TrimStart('/')),
            TransformedPath: transformedPath,
            TransformedHeaders: transformedHeaders);
    }

    private RouteConfig? FindMatchingRoute(string path)
    {
        foreach (var route in _routes)
        {
            if (string.IsNullOrEmpty(route.Match.Path)) continue;

            // Simplified prefix & wildcards matching (e.g. /api/orders/{**catch-all} or /api/orders)
            var pattern = route.Match.Path
                .Replace("{**catch-all}", ".*")
                .Replace("{**remainder}", ".*");

            if (Regex.IsMatch(path, $"^{pattern}$", RegexOptions.IgnoreCase))
            {
                return route;
            }
        }
        return null;
    }

    private Dictionary<string, string> ApplyHeaderTransforms(IReadOnlyDictionary<string, string> incomingHeaders)
    {
        var headers = new Dictionary<string, string>(incomingHeaders, StringComparer.OrdinalIgnoreCase);

        // Strip disallowed headers
        foreach (var removeKey in _globalTransforms.RemoveHeaders)
        {
            headers.Remove(removeKey);
        }

        // Add configured headers
        foreach (var (k, v) in _globalTransforms.AddHeaders)
        {
            headers[k] = v;
        }

        return headers;
    }

    private string ApplyPathTransforms(string incomingPath, RouteConfig route)
    {
        var path = incomingPath;

        if (_globalTransforms.PathRemovePrefix != null && path.StartsWith(_globalTransforms.PathRemovePrefix, StringComparison.OrdinalIgnoreCase))
        {
            path = path[_globalTransforms.PathRemovePrefix.Length..];
        }

        if (_globalTransforms.PathAddPrefix != null)
        {
            path = _globalTransforms.PathAddPrefix.TrimEnd('/') + "/" + path.TrimStart('/');
        }

        return string.IsNullOrEmpty(path) ? "/" : path;
    }
}
