1. AMQP 0-9-1 Architectural Model

RabbitMQ implements the Advanced Message Queuing Protocol (AMQP 0-9-1), an open standard wire-level protocol for enterprise asynchronous messaging.

Connection vs. Channel

  • Connection: A persistent TCP/IP socket between the client application and RabbitMQ broker. Establishing a connection involves a full TCP handshake, TLS negotiation, and authentication challenge (expensive).
  • Channel: A lightweight virtual connection multiplexed inside a single physical TCP connection. Applications open and close hundreds of channels concurrently for publishing and consuming, completely avoiding TCP handshake overhead.

2. The 4 AMQP Exchange Types

An exchange acts as an internal message router. Producers never send messages directly to queues; they publish to an Exchange with an optional Routing Key.

1. Direct Exchange

Routes messages to queues whose Binding Key exactly matches the message's Routing Key.

  • Example:
  • Queue A bound with orders.created
  • Queue B bound with orders.cancelled
  • Publishing with orders.created goes exclusively to Queue A.

2. Fanout Exchange

Routinely ignores routing keys and duplicates incoming messages to all queues bound to the exchange.

  • Blazingly fast ($\mathcal{O}(1)$ routing table lookup).
  • Ideal for publish-subscribe broadcast patterns (e.g., distributed cache invalidation, live price feeds).

3. Topic Exchange

Performs routing based on dot-delimited tokens in the routing key using wildcard tokens:

  • * (asterisk): Matches exactly one word.
  • # (hash): Matches zero or more words.
  • Examples:
  • orders.eu.*: Matches orders.eu.created, orders.eu.paid; does NOT match orders.eu.b2b.created.
  • orders.#: Matches orders, orders.us, orders.us.california.expedited.
  • #.critical: Matches any routing key ending with .critical.

4. Headers Exchange

Routes messages based on message header attributes rather than the routing key string.

  • Uses x-match:
  • x-match = all: Every header key/value pair specified in the binding must be present in the message.
  • x-match = any: At least one matching header key/value pair routes the message.

3. Reliability, Confirmations & DLX

1. Publisher Confirms

In standard fire-and-forget publishing, a producer does not know if a message was successfully accepted, written to disk, or rejected by the broker.

  • Publisher Confirms: Once enabled on a channel, the broker asynchronously sends an Ack back to the publisher with the message's sequence number once:
  1. The message is persisted to disk on all durable queues, or
  2. The message is consumed and acknowledged by downstream workers.
  • If the broker encounters disk full errors or internal node crashes, it emits a Nack.

2. Consumer Acknowledgments (Ack / Nack)

  • autoAck = true: The broker removes the message from the queue the instant it sends it over the socket. If the worker process crashes before processing the payload, the message is permanently lost.
  • autoAck = false (Manual Ack):
  • basic.ack(delivery_tag): Worker successfully processed the message; broker removes it from memory.
  • basic.nack(delivery_tag, requeue = true): Worker encountered a transient failure (e.g., DB lock timeout); broker re-enqueues the message at the head of the queue.
  • basic.nack(delivery_tag, requeue = false): Poison message; discarded or forwarded to a Dead Letter Exchange.

3. Dead Letter Exchange (DLX)

Queues configured with x-dead-letter-exchange automatically re-route messages to the DLX when:

  1. The message is rejected via basic.nack(requeue: false) or basic.reject(requeue: false).
  2. The message's Time-To-Live (x-message-ttl) expires in the queue.
  3. The queue reaches its maximum capacity (x-max-length).

4. Consumer QoS & Fair Dispatch

By default, RabbitMQ dispatches messages round-robin in large batches to all connected consumers without checking how many unacknowledged messages each consumer currently holds.

  • The Problem: If Consumer A gets heavy, slow jobs while Consumer B gets quick jobs, Consumer A becomes saturated with hundreds of queued messages while Consumer B sits idle.
  • The Solution (basic.qos(prefetch_count)):
  • prefetch_count = 1: Tells RabbitMQ never to give more than 1 unacknowledged message to a worker at a time.
  • RabbitMQ only assigns a new message to that worker after receiving basic.ack.
  • Achieves optimal load leveling across heterogeneous workers.

5. Graph Algorithms: LeetCode #130 & #994

LeetCode #130: Surrounded Regions (Medium)

  • Problem: Given an $m \times n$ matrix containing 'X' and 'O', flip all 'O's that are 4-directionally surrounded by 'X' into 'X'.
  • Key Insight: Any 'O' connected to the border can never be surrounded.
  • Reverse Algorithm:
  1. Iterate along the 4 borders of the matrix (row $0$, row $m-1$, col $0$, col $n-1$).
  2. For every 'O' on the boundary, run DFS/BFS to mark all connected 'O's as a safe sentinel character ('#').
  3. Scan the entire grid:
  • Flip all remaining 'O's to 'X' (these are truly surrounded).
  • Restore all '#' back to 'O' (these were border-connected).
  • Complexity: $\mathcal{O}(M \times N)$ time, $\mathcal{O}(M \times N)$ space.

LeetCode #994: Rotting Oranges (Medium)

  • Problem: In an $m \times n$ grid of 0 (empty), 1 (fresh), and 2 (rotten), every minute any fresh orange adjacent to a rotten orange becomes rotten. Return minimum minutes until no fresh oranges remain, or -1.
  • Algorithm (Multi-Source BFS):
  1. Scan the grid to enqueue all initially rotten oranges (2) into a FIFO queue and count the total number of fresh oranges (1).
  2. If freshCount == 0, return 0 immediately.
  3. While queue is not empty and freshCount > 0:
  • Increment minutes.
  • Process the current level snapshot (size of queue at this minute).
  • For each rotten orange, inspect 4 cardinal neighbors. If neighbor is fresh (1):
  • Mark as rotten (2), decrement freshCount, and enqueue.
  1. If freshCount == 0, return minutes; else return -1 (unreachable fresh oranges).
  • Complexity: $\mathcal{O}(M \times N)$ time, $\mathcal{O}(M \times N)$ space.

1. What are the core architectural trade-offs between RabbitMQ and Apache Kafka?

Answer:

Architectural Dimension RabbitMQ Apache Kafka
Architectural Model Smart Broker / Dumb Consumer: Broker tracks message state, delivery tags, queue indexes, and consumer acks. Deletes messages upon acknowledgment. Dumb Broker / Smart Consumer: Broker is an immutable distributed commit log. Consumers track their own offsets. Messages persist until retention policy expires.
Routing Flexibility Complex in-broker routing (Direct, Topic, Fanout, Headers, Dead-lettering). Partition key hashing (Hash(Key) % Partitions). Filtering happens client-side.
Ordering Guarantees FIFO per queue. Concurrency (prefetch > 1 or multiple consumers) breaks strict order. Strict FIFO order guaranteed within each partition.
Throughput & Scale Tens to hundreds of thousands of messages/sec. Memory-intensive broker state. Millions of messages/sec. Sequential disk I/O, zero-copy OS page cache (sendfile).
Replayability No message replay (once acked, it is gone). High replayability (consumers can reset offsets to reprocess historic logs).
Best Suited For Complex task routing, microservices commands, RPC, dynamic work queues. High-volume telemetry, clickstreams, event sourcing, CDC stream processing.

2. How do modern RabbitMQ Quorum Queues (Raft Consensus) overcome the vulnerabilities of Classic Mirrored Queues?

Answer:

  • Classic Mirrored Queues (Deprecated):
  • Relied on a proprietary primary-mirror synchronization mechanism.
  • Vulnerable to network partitions (Split-Brain). When a partition healed, non-synchronized mirrors either dropped messages or blocked the primary while replicating the entire queue from scratch, causing cluster-wide latency pauses.
  • Quorum Queues (RabbitMQ 3.8+):
  • Implemented using the formal Raft Consensus Algorithm.
  • A quorum queue consists of a Raft leader and followers across cluster nodes.
  • State replication requires acknowledgment from a majority of nodes ($\lfloor N/2 \rfloor + 1$) before confirming publishes to clients.
  • Tolerates $F$ node failures in an $2F+1$ node cluster with zero message loss and deterministic leader election without cluster-wide stalling.

3. What is the impact of basic.qos(prefetch_count) on consumer throughput, latency, and memory footprint?

Answer:

prefetch_count dictates how many unacknowledged messages the broker can deliver to a consumer channel before waiting for an ACK.

  • Prefetch = 0 (Unlimited):
  • The broker pushes all available queue messages over the TCP connection into the consumer process's RAM buffer.
  • Risk: Consumer process experiences Out-Of-Memory (OOM) crashes under high volume. Fast workers starve while slow workers buffer thousands of messages.
  • Prefetch = 1 (Strict Fair Dispatch):
  • The broker delivers exactly one message and waits for an ACK before sending another.
  • Advantage: Maximum work balancing across uneven workloads.
  • Disadvantage: High network round-trip time (RTT) latency overhead. The consumer thread remains idle between ACKing message $N$ and receiving message $N+1$.
  • Production Sweet Spot (prefetch_count = 50–200):
  • Pipelining allows the consumer to process incoming messages continuously while prior ACKs travel back over the wire, optimizing throughput without risking memory saturation.

4. How do Publisher Confirms guarantee zero message loss during broker node crashes and disk flushes?

Answer:

When a producer publishes a message without confirms, the socket write succeeds the moment bytes leave the client OS network buffer, giving no guarantee that the broker received, routed, or stored the message.

With Publisher Confirms:

  1. The client issues confirm.select on the AMQP channel.
  2. The broker assigns an incrementing 64-bit integer sequence number to each incoming message on that channel.
  3. The broker asynchronously returns basic.ack(sequenceNumber) to the publisher only after:
  • For a persistent message on a durable queue: The message has been written and fsynced to disk (or replicated to a Raft quorum).
  • If the queue is transient or already consumed: The message is accepted by the consumer.
  1. If a disk write fails, the broker returns basic.nack(sequenceNumber).
  2. The publisher maintains a pending dictionary of unconfirmed sequence numbers and retries or alerts upon receiving Nack or a confirmation timeout.

5. What causes "Unacknowledged Message Creep" in RabbitMQ, and how does it manifest in production?

Answer:

  • The Cause:

When consumer applications consume messages with autoAck = false but fail to call basic.ack or basic.nack due to:

  1. An unhandled exception that bypasses the acknowledgment block.
  2. Infinite loops or asynchronous deadlocks in worker processing logic.
  3. Swallowing exceptions without invoking basic.nack(requeue: false).
  • The Impact:
  • The broker must keep unacknowledged messages stored in RAM and tracked in memory metadata in case the consumer disconnects and messages must be re-queued.
  • As unacked messages accumulate into the millions, broker RAM consumption hits the High Memory Watermark (vm_memory_high_watermark).
  • RabbitMQ initiates alarms, blocks all incoming publishers (TCP backpressure), and halts message throughput across the entire cluster.

6. How do you implement non-blocking exponential backoff retries using Dead Letter Exchanges (DLX) in RabbitMQ?

Answer:

Directly retrying failed messages with basic.nack(requeue: true) immediately puts the message at the front of the same queue. If the failure is persistent (e.g., database down), the worker immediately re-consumes it, causing a 100% CPU busy-spin loop that blocks all other legitimate queue messages.

Dead-Letter Exponential Backoff Topology:

  1. Main Queue (orders.queue): Consumed by application workers.
  2. When processing fails, worker calls basic.nack(requeue: false).
  3. The main queue's x-dead-letter-exchange forwards the message to a Retry Exchange.
  4. The message routes to a series of delay queues with Message TTL (e.g. retry.10s, retry.60s, retry.5m):
  • Delay queues have no consumers.
  • Configured with x-message-ttl: 10000 and x-dead-letter-exchange: main.exchange.
  1. When the 10-second TTL expires, RabbitMQ automatically dead-letters the message back into the Main Queue for another processing attempt without blocking any concurrent traffic.
  2. Messages exceeding maximum retry counts are forwarded to a permanent orders.poison.dlq.

7. How does a Topic Exchange match routing keys, and what is the difference between * and #?

Answer:

Routing keys in AMQP Topic Exchanges consist of dot-delimited words (e.g., us.shipping.express).

  • * (asterisk): Substitutes for exactly one word.
  • Pattern: *.shipping.* matches us.shipping.express and eu.shipping.standard.
  • Does NOT match shipping.express or us.west.shipping.express.
  • # (hash): Substitutes for zero or more words.
  • Pattern: orders.# matches orders, orders.created, orders.us.california.b2b.priority.
  • Internal Optimization:

RabbitMQ indexes topic bindings using a Trie (Prefix Tree) data structure. Incoming routing keys traverse the trie in $\mathcal{O}(K)$ time where $K$ is the number of words in the routing key, rather than performing slow sequential regex evaluations across thousands of queues.

8. When should an architect choose a Headers Exchange over a Topic Exchange?

Answer:

  • Topic Exchange Limitations:
  • Requires a single linear dot-separated hierarchy (e.g., format.vendor.region).
  • Cannot cleanly express non-hierarchical, multi-dimensional queries. For example, if a message has format json, region us, vendor acme, and encrypted true, routing keys become combinatorial (json.us.acme.true).
  • Headers Exchange Advantages:
  • Operates on arbitrary key-value metadata dictionaries.
  • Supports x-match: all (AND logic) and x-match: any (OR logic).
  • Best Suited For: Multi-tenant architectures where messages have disparate dimensions (e.g., tenant_id, environment: staging, data_classification: pii), or when the payload structure naturally maps to HTTP headers.

9. For LeetCode #130 (Surrounded Regions), why is reverse boundary flood fill superior to searching from every interior cell?

Answer:

  • Forward Interior Search:
  • Testing each 'O' cell requires checking whether its connected component can reach any boundary.
  • If a large connected component of size $K$ does not touch the boundary, we must track and flip all its cells. If it does touch the boundary, all explored paths must be retained without flipping.
  • Requires maintaining temporary component lists, tracking visited states, and handling multiple rollbacks.
  • Reverse Boundary Flood Fill:
  • We observe that only cells connected to the boundary survive.
  • We initiate DFS/BFS strictly from the boundary 'O' cells (at most $2M + 2N$ perimeter cells).
  • Any cell reached is marked with a safe sentinel ('#').
  • A single linear $\mathcal{O}(M \times N)$ pass flips all remaining 'O's (which are guaranteed to be captured) to 'X', and restores '#' to 'O'.
  • Zero rollback overhead and optimal cache-friendly linear memory access.

10. For LeetCode #994 (Rotting Oranges), why must the contagion simulation be solved with Multi-Source BFS rather than DFS?

Answer:

  • Multi-Source BFS:
  • BFS explores a graph in concentric waves of equal distance (Level-by-Level).
  • In Rotting Oranges, all initially rotten oranges spread infection simultaneously in parallel at minute $1$, minute $2$, etc.
  • By enqueuing all initial rotten oranges into the BFS queue at minute $0$, the BFS naturally simulates this simultaneous parallel expansion. The number of BFS level expansions equals the exact minimum minutes required.
  • Why DFS Fails:
  • DFS explores one deep path to its termination before backtracking.
  • A single rotten orange might take a 20-step path to rot an orange that was actually adjacent to another rotten orange that would have reached it in minute 1.
  • DFS cannot easily calculate the minimum parallel time without complex, expensive minimum timestamp relaxation across all cells.

using System.Collections.Concurrent;
using System.Text.RegularExpressions;

namespace Day29.RabbitMQCoreExchanges;

public enum ExchangeType
{
    Direct,
    Topic,
    Fanout,
    Headers
}

public enum HeadersMatchMode
{
    All,
    Any
}

public record AmqpMessage(
    ulong DeliveryTag,
    string MessageId,
    string RoutingKey,
    string Payload,
    IReadOnlyDictionary<string, object> Headers,
    bool Redelivered,
    DateTime TimestampUtc);

public class QueueBinding
{
    public string QueueName { get; }
    public string RoutingKeyPattern { get; }
    public IReadOnlyDictionary<string, object>? HeaderFilter { get; }
    public HeadersMatchMode MatchMode { get; }

    public QueueBinding(
        string queueName,
        string routingKeyPattern = "",
        IReadOnlyDictionary<string, object>? headerFilter = null,
        HeadersMatchMode matchMode = HeadersMatchMode.All)
    {
        QueueName = queueName;
        RoutingKeyPattern = routingKeyPattern;
        HeaderFilter = headerFilter;
        MatchMode = matchMode;
    }
}

public class AmqpQueue
{
    public string Name { get; }
    public string? DeadLetterExchange { get; }
    public string? DeadLetterRoutingKey { get; }
    public int PrefetchCount { get; set; } = 10;

    private readonly ConcurrentQueue<AmqpMessage> _messages = new();
    private readonly ConcurrentDictionary<ulong, AmqpMessage> _unackedMessages = new();

    public int ReadyMessageCount => _messages.Count;
    public int UnackedMessageCount => _unackedMessages.Count;

    public AmqpQueue(string name, string? deadLetterExchange = null, string? deadLetterRoutingKey = null)
    {
        Name = name;
        DeadLetterExchange = deadLetterExchange;
        DeadLetterRoutingKey = deadLetterRoutingKey;
    }

    public void Enqueue(AmqpMessage message, bool toFront = false)
    {
        if (toFront)
        {
            // Requeue to head: snapshot, clear, push redelivered, restore remaining
            var list = _messages.ToList();
            while (_messages.TryDequeue(out _)) { }
            _messages.Enqueue(message);
            foreach (var item in list)
            {
                _messages.Enqueue(item);
            }
        }
        else
        {
            _messages.Enqueue(message);
        }
    }

    public AmqpMessage? Dequeue()
    {
        if (_unackedMessages.Count >= PrefetchCount)
        {
            // QoS Prefetch limit reached: hold message delivery until ACK/NACK
            return null;
        }

        if (_messages.TryDequeue(out var msg))
        {
            _unackedMessages[msg.DeliveryTag] = msg;
            return msg;
        }
        return null;
    }

    public bool Ack(ulong deliveryTag)
    {
        return _unackedMessages.TryRemove(deliveryTag, out _);
    }

    public AmqpMessage? Nack(ulong deliveryTag, bool requeue)
    {
        if (!_unackedMessages.TryRemove(deliveryTag, out var msg))
            return null;

        if (requeue)
        {
            Enqueue(msg with { Redelivered = true }, toFront: true);
        }

        return msg;
    }
}

/// <summary>
/// High-fidelity in-memory AMQP 0-9-1 Message Broker Simulator.
/// Simulates Direct, Topic, Fanout, and Headers exchanges, Publisher Confirms,
/// Consumer Ack/Nack, Dead Letter Exchanges (DLX), and Prefetch QoS.
/// </summary>
public class AmqpBrokerSimulator
{
    private readonly ConcurrentDictionary<string, (ExchangeType Type, List<QueueBinding> Bindings)> _exchanges = new();
    private readonly ConcurrentDictionary<string, AmqpQueue> _queues = new();
    private ulong _deliveryTagSequence;

    public int PublishedCount { get; private set; }
    public int AckedCount { get; private set; }
    public int NackedCount { get; private set; }
    public int DeadLetteredCount { get; private set; }

    public void DeclareExchange(string name, ExchangeType type)
    {
        _exchanges.TryAdd(name, (type, new List<QueueBinding>()));
    }

    public void DeclareQueue(string name, string? deadLetterExchange = null, string? deadLetterRoutingKey = null, int prefetchCount = 10)
    {
        var queue = new AmqpQueue(name, deadLetterExchange, deadLetterRoutingKey) { PrefetchCount = prefetchCount };
        _queues.TryAdd(name, queue);
    }

    public void BindQueue(
        string queueName,
        string exchangeName,
        string routingKey = "",
        IReadOnlyDictionary<string, object>? headers = null,
        HeadersMatchMode matchMode = HeadersMatchMode.All)
    {
        if (!_exchanges.TryGetValue(exchangeName, out var exchange))
            throw new InvalidOperationException($"Exchange '{exchangeName}' does not exist.");
        if (!_queues.ContainsKey(queueName))
            throw new InvalidOperationException($"Queue '{queueName}' does not exist.");

        lock (exchange.Bindings)
        {
            exchange.Bindings.Add(new QueueBinding(queueName, routingKey, headers, matchMode));
        }
    }

    /// <summary>
    /// Publishes a message to an exchange with Publisher Confirms semantics.
    /// Returns true (ACK) if successfully delivered to matching queues, or false (NACK) if unrouted on mandatory.
    /// </summary>
    public bool Publish(
        string exchangeName,
        string routingKey,
        string payload,
        IReadOnlyDictionary<string, object>? headers = null,
        bool mandatory = false)
    {
        if (!_exchanges.TryGetValue(exchangeName, out var exchange))
            throw new InvalidOperationException($"Exchange '{exchangeName}' not declared.");

        headers ??= new Dictionary<string, object>();
        var matchingQueueNames = GetMatchingQueues(exchange.Type, exchange.Bindings, routingKey, headers);

        if (matchingQueueNames.Count == 0 && mandatory)
        {
            return false; // Publisher confirm NACK for unroutable mandatory message
        }

        var tag = Interlocked.Increment(ref _deliveryTagSequence);
        var message = new AmqpMessage(
            DeliveryTag: tag,
            MessageId: Guid.NewGuid().ToString("N"),
            RoutingKey: routingKey,
            Payload: payload,
            Headers: headers,
            Redelivered: false,
            TimestampUtc: DateTime.UtcNow);

        foreach (var qName in matchingQueueNames)
        {
            if (_queues.TryGetValue(qName, out var queue))
            {
                queue.Enqueue(message);
            }
        }

        PublishedCount++;
        return true; // Publisher confirm ACK
    }

    public AmqpMessage? BasicGet(string queueName)
    {
        if (!_queues.TryGetValue(queueName, out var queue))
            return null;

        return queue.Dequeue();
    }

    public bool BasicAck(string queueName, ulong deliveryTag)
    {
        if (_queues.TryGetValue(queueName, out var queue))
        {
            var success = queue.Ack(deliveryTag);
            if (success) AckedCount++;
            return success;
        }
        return false;
    }

    public bool BasicNack(string queueName, ulong deliveryTag, bool requeue)
    {
        if (!_queues.TryGetValue(queueName, out var queue))
            return false;

        var message = queue.Nack(deliveryTag, requeue);
        if (message == null) return false;

        NackedCount++;

        if (!requeue && !string.IsNullOrEmpty(queue.DeadLetterExchange))
        {
            // Route to Dead Letter Exchange (DLX)
            DeadLetteredCount++;
            var dlxRoutingKey = queue.DeadLetterRoutingKey ?? message.RoutingKey;
            Publish(queue.DeadLetterExchange, dlxRoutingKey, message.Payload, message.Headers);
        }

        return true;
    }

    public AmqpQueue? GetQueue(string name)
    {
        _queues.TryGetValue(name, out var queue);
        return queue;
    }

    private HashSet<string> GetMatchingQueues(
        ExchangeType type,
        List<QueueBinding> bindings,
        string routingKey,
        IReadOnlyDictionary<string, object> headers)
    {
        var matched = new HashSet<string>();
        lock (bindings)
        {
            foreach (var b in bindings)
            {
                if (IsBindingMatch(type, b, routingKey, headers))
                {
                    matched.Add(b.QueueName);
                }
            }
        }
        return matched;
    }

    private bool IsBindingMatch(
        ExchangeType type,
        QueueBinding binding,
        string routingKey,
        IReadOnlyDictionary<string, object> headers)
    {
        return type switch
        {
            ExchangeType.Fanout => true,
            ExchangeType.Direct => string.Equals(binding.RoutingKeyPattern, routingKey, StringComparison.Ordinal),
            ExchangeType.Topic => MatchTopicPattern(binding.RoutingKeyPattern, routingKey),
            ExchangeType.Headers => MatchHeaders(binding.HeaderFilter, headers, binding.MatchMode),
            _ => false
        };
    }

    private static bool MatchTopicPattern(string pattern, string routingKey)
    {
        // AMQP 0-9-1 Topic Exchange rules:
        // * matches exactly one word
        // # matches zero or more words
        var regexPattern = "^" + Regex.Escape(pattern)
            .Replace("\\*", "[^.]+")
            .Replace("\\#", ".*") + "$";

        return Regex.IsMatch(routingKey, regexPattern);
    }

    private static bool MatchHeaders(
        IReadOnlyDictionary<string, object>? filter,
        IReadOnlyDictionary<string, object> headers,
        HeadersMatchMode mode)
    {
        if (filter == null || filter.Count == 0) return true;

        if (mode == HeadersMatchMode.All)
        {
            foreach (var (k, v) in filter)
            {
                if (!headers.TryGetValue(k, out var actual) || !object.Equals(v, actual))
                    return false;
            }
            return true;
        }
        else // Any
        {
            foreach (var (k, v) in filter)
            {
                if (headers.TryGetValue(k, out var actual) && object.Equals(v, actual))
                    return true;
            }
            return false;
        }
    }

/// <summary>
/// Solvers for Graph / Grid algorithms:
/// 1. LeetCode #130: Surrounded Regions (Medium)
/// 2. LeetCode #994: Rotting Oranges (Medium)
/// </summary>
public class SurroundedRegionsAndOrangesSolver
{
    private static readonly int[] RowOffsets = { -1, 1, 0, 0 };
    private static readonly int[] ColOffsets = { 0, 0, -1, 1 };

    /// <summary>
    /// Solves LeetCode #130: Surrounded Regions using reverse boundary DFS.
    /// Captures all regions surrounded by 'X' by preserving boundary-connected 'O's.
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(M * N) recursion stack.
    /// </summary>
    public void SolveSurroundedRegions(char[][]? board)
    {
        if (board == null || board.Length == 0 || board[0].Length == 0)
            return;

        int m = board.Length;
        int n = board[0].Length;

        // 1. Mark boundary 'O's and their connected component as '#' (protected)
        for (int r = 0; r < m; r++)
        {
            if (board[r][0] == 'O') DfsMarkSafe(board, r, 0, m, n);
            if (board[r][n - 1] == 'O') DfsMarkSafe(board, r, n - 1, m, n);
        }

        for (int c = 0; c < n; c++)
        {
            if (board[0][c] == 'O') DfsMarkSafe(board, 0, c, m, n);
            if (board[m - 1][c] == 'O') DfsMarkSafe(board, m - 1, c, m, n);
        }

        // 2. Flip all unprotected 'O's to 'X', and restore '#' back to 'O'
        for (int r = 0; r < m; r++)
        {
            for (int c = 0; c < n; c++)
            {
                if (board[r][c] == 'O')
                {
                    board[r][c] = 'X'; // Captured
                }
                else if (board[r][c] == '#')
                {
                    board[r][c] = 'O'; // Restored
                }
            }
        }
    }

    private void DfsMarkSafe(char[][] board, int r, int c, int m, int n)
    {
        if (r < 0 || r >= m || c < 0 || c >= n || board[r][c] != 'O')
            return;

        board[r][c] = '#'; // Mark safe

        for (int i = 0; i < 4; i++)
        {
            DfsMarkSafe(board, r + RowOffsets[i], c + ColOffsets[i], m, n);
        }
    }

    /// <summary>
    /// Solves LeetCode #994: Rotting Oranges using level-by-level Multi-Source Breadth-First Search (BFS).
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(M * N)
    /// </summary>
    public int OrangesRotting(int[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0)
            return 0;

        int m = grid.Length;
        int n = grid[0].Length;

        var queue = new Queue<(int r, int c)>();
        int freshCount = 0;

        // Clone grid to preserve caller input
        var workingGrid = new int[m][];
        for (int i = 0; i < m; i++)
        {
            workingGrid[i] = (int[])grid[i].Clone();
            for (int j = 0; j < n; j++)
            {
                if (workingGrid[i][j] == 2)
                {
                    queue.Enqueue((i, j));
                }
                else if (workingGrid[i][j] == 1)
                {
                    freshCount++;
                }
            }
        }

        if (freshCount == 0) return 0;

        int minutesElapsed = 0;

        while (queue.Count > 0 && freshCount > 0)
        {
            int currentBatchSize = queue.Count;
            minutesElapsed++;

            for (int i = 0; i < currentBatchSize; i++)
            {
                var (r, c) = queue.Dequeue();

                for (int d = 0; d < 4; d++)
                {
                    int nr = r + RowOffsets[d];
                    int nc = c + ColOffsets[d];

                    if (nr >= 0 && nr < m && nc >= 0 && nc < n && workingGrid[nr][nc] == 1)
                    {
                        workingGrid[nr][nc] = 2; // Infect to rotten
                        freshCount--;
                        queue.Enqueue((nr, nc));
                    }
                }
            }
        }

        return freshCount == 0 ? minutesElapsed : -1;
    }
}

1. AMQP 0-9-1 Architectural Model

RabbitMQ implements the Advanced Message Queuing Protocol (AMQP 0-9-1), an open standard wire-level protocol for enterprise asynchronous messaging.

Connection vs. Channel

  • Connection: A persistent TCP/IP socket between the client application and RabbitMQ broker. Establishing a connection involves a full TCP handshake, TLS negotiation, and authentication challenge (expensive).
  • Channel: A lightweight virtual connection multiplexed inside a single physical TCP connection. Applications open and close hundreds of channels concurrently for publishing and consuming, completely avoiding TCP handshake overhead.

2. The 4 AMQP Exchange Types

An exchange acts as an internal message router. Producers never send messages directly to queues; they publish to an Exchange with an optional Routing Key.

1. Direct Exchange

Routes messages to queues whose Binding Key exactly matches the message's Routing Key.

  • Example:
  • Queue A bound with orders.created
  • Queue B bound with orders.cancelled
  • Publishing with orders.created goes exclusively to Queue A.

2. Fanout Exchange

Routinely ignores routing keys and duplicates incoming messages to all queues bound to the exchange.

  • Blazingly fast ($\mathcal{O}(1)$ routing table lookup).
  • Ideal for publish-subscribe broadcast patterns (e.g., distributed cache invalidation, live price feeds).

3. Topic Exchange

Performs routing based on dot-delimited tokens in the routing key using wildcard tokens:

  • * (asterisk): Matches exactly one word.
  • # (hash): Matches zero or more words.
  • Examples:
  • orders.eu.*: Matches orders.eu.created, orders.eu.paid; does NOT match orders.eu.b2b.created.
  • orders.#: Matches orders, orders.us, orders.us.california.expedited.
  • #.critical: Matches any routing key ending with .critical.

4. Headers Exchange

Routes messages based on message header attributes rather than the routing key string.

  • Uses x-match:
  • x-match = all: Every header key/value pair specified in the binding must be present in the message.
  • x-match = any: At least one matching header key/value pair routes the message.

3. Reliability, Confirmations & DLX

1. Publisher Confirms

In standard fire-and-forget publishing, a producer does not know if a message was successfully accepted, written to disk, or rejected by the broker.

  • Publisher Confirms: Once enabled on a channel, the broker asynchronously sends an Ack back to the publisher with the message's sequence number once:
  1. The message is persisted to disk on all durable queues, or
  2. The message is consumed and acknowledged by downstream workers.
  • If the broker encounters disk full errors or internal node crashes, it emits a Nack.

2. Consumer Acknowledgments (Ack / Nack)

  • autoAck = true: The broker removes the message from the queue the instant it sends it over the socket. If the worker process crashes before processing the payload, the message is permanently lost.
  • autoAck = false (Manual Ack):
  • basic.ack(delivery_tag): Worker successfully processed the message; broker removes it from memory.
  • basic.nack(delivery_tag, requeue = true): Worker encountered a transient failure (e.g., DB lock timeout); broker re-enqueues the message at the head of the queue.
  • basic.nack(delivery_tag, requeue = false): Poison message; discarded or forwarded to a Dead Letter Exchange.

3. Dead Letter Exchange (DLX)

Queues configured with x-dead-letter-exchange automatically re-route messages to the DLX when:

  1. The message is rejected via basic.nack(requeue: false) or basic.reject(requeue: false).
  2. The message's Time-To-Live (x-message-ttl) expires in the queue.
  3. The queue reaches its maximum capacity (x-max-length).

4. Consumer QoS & Fair Dispatch

By default, RabbitMQ dispatches messages round-robin in large batches to all connected consumers without checking how many unacknowledged messages each consumer currently holds.

  • The Problem: If Consumer A gets heavy, slow jobs while Consumer B gets quick jobs, Consumer A becomes saturated with hundreds of queued messages while Consumer B sits idle.
  • The Solution (basic.qos(prefetch_count)):
  • prefetch_count = 1: Tells RabbitMQ never to give more than 1 unacknowledged message to a worker at a time.
  • RabbitMQ only assigns a new message to that worker after receiving basic.ack.
  • Achieves optimal load leveling across heterogeneous workers.

5. Graph Algorithms: LeetCode #130 & #994

LeetCode #130: Surrounded Regions (Medium)

  • Problem: Given an $m \times n$ matrix containing 'X' and 'O', flip all 'O's that are 4-directionally surrounded by 'X' into 'X'.
  • Key Insight: Any 'O' connected to the border can never be surrounded.
  • Reverse Algorithm:
  1. Iterate along the 4 borders of the matrix (row $0$, row $m-1$, col $0$, col $n-1$).
  2. For every 'O' on the boundary, run DFS/BFS to mark all connected 'O's as a safe sentinel character ('#').
  3. Scan the entire grid:
  • Flip all remaining 'O's to 'X' (these are truly surrounded).
  • Restore all '#' back to 'O' (these were border-connected).
  • Complexity: $\mathcal{O}(M \times N)$ time, $\mathcal{O}(M \times N)$ space.

LeetCode #994: Rotting Oranges (Medium)

  • Problem: In an $m \times n$ grid of 0 (empty), 1 (fresh), and 2 (rotten), every minute any fresh orange adjacent to a rotten orange becomes rotten. Return minimum minutes until no fresh oranges remain, or -1.
  • Algorithm (Multi-Source BFS):
  1. Scan the grid to enqueue all initially rotten oranges (2) into a FIFO queue and count the total number of fresh oranges (1).
  2. If freshCount == 0, return 0 immediately.
  3. While queue is not empty and freshCount > 0:
  • Increment minutes.
  • Process the current level snapshot (size of queue at this minute).
  • For each rotten orange, inspect 4 cardinal neighbors. If neighbor is fresh (1):
  • Mark as rotten (2), decrement freshCount, and enqueue.
  1. If freshCount == 0, return minutes; else return -1 (unreachable fresh oranges).
  • Complexity: $\mathcal{O}(M \times N)$ time, $\mathcal{O}(M \times N)$ space.

1. What are the core architectural trade-offs between RabbitMQ and Apache Kafka?

Answer:

2. How do modern RabbitMQ Quorum Queues (Raft Consensus) overcome the vulnerabilities of Classic Mirrored Queues?

Answer:

  • Classic Mirrored Queues (Deprecated):
  • Relied on a proprietary primary-mirror synchronization mechanism.
  • Vulnerable to network partitions (Split-Brain). When a partition healed, non-synchronized mirrors either dropped messages or blocked the primary while replicating the entire queue from scratch, causing cluster-wide latency pauses.
  • Quorum Queues (RabbitMQ 3.8+):
  • Implemented using the formal Raft Consensus Algorithm.
  • A quorum queue consists of a Raft leader and followers across cluster nodes.
  • State replication requires acknowledgment from a majority of nodes ($\lfloor N/2 \rfloor + 1$) before confirming publishes to clients.
  • Tolerates $F$ node failures in an $2F+1$ node cluster with zero message loss and deterministic leader election without cluster-wide stalling.

3. What is the impact of basic.qos(prefetch_count) on consumer throughput, latency, and memory footprint?

Answer:

prefetch_count dictates how many unacknowledged messages the broker can deliver to a consumer channel before waiting for an ACK.

  • Prefetch = 0 (Unlimited):
  • The broker pushes all available queue messages over the TCP connection into the consumer process's RAM buffer.
  • Risk: Consumer process experiences Out-Of-Memory (OOM) crashes under high volume. Fast workers starve while slow workers buffer thousands of messages.
  • Prefetch = 1 (Strict Fair Dispatch):
  • The broker delivers exactly one message and waits for an ACK before sending another.
  • Advantage: Maximum work balancing across uneven workloads.
  • Disadvantage: High network round-trip time (RTT) latency overhead. The consumer thread remains idle between ACKing message $N$ and receiving message $N+1$.
  • Production Sweet Spot (prefetch_count = 50–200):
  • Pipelining allows the consumer to process incoming messages continuously while prior ACKs travel back over the wire, optimizing throughput without risking memory saturation.

4. How do Publisher Confirms guarantee zero message loss during broker node crashes and disk flushes?

Answer:

When a producer publishes a message without confirms, the socket write succeeds the moment bytes leave the client OS network buffer, giving no guarantee that the broker received, routed, or stored the message.

With Publisher Confirms:

  1. The client issues confirm.select on the AMQP channel.
  2. The broker assigns an incrementing 64-bit integer sequence number to each incoming message on that channel.
  3. The broker asynchronously returns basic.ack(sequenceNumber) to the publisher only after:
  • For a persistent message on a durable queue: The message has been written and fsynced to disk (or replicated to a Raft quorum).
  • If the queue is transient or already consumed: The message is accepted by the consumer.
  1. If a disk write fails, the broker returns basic.nack(sequenceNumber).
  2. The publisher maintains a pending dictionary of unconfirmed sequence numbers and retries or alerts upon receiving Nack or a confirmation timeout.

5. What causes "Unacknowledged Message Creep" in RabbitMQ, and how does it manifest in production?

Answer:

  • The Cause:

When consumer applications consume messages with autoAck = false but fail to call basic.ack or basic.nack due to:

  1. An unhandled exception that bypasses the acknowledgment block.
  2. Infinite loops or asynchronous deadlocks in worker processing logic.
  3. Swallowing exceptions without invoking basic.nack(requeue: false).
  • The Impact:
  • The broker must keep unacknowledged messages stored in RAM and tracked in memory metadata in case the consumer disconnects and messages must be re-queued.
  • As unacked messages accumulate into the millions, broker RAM consumption hits the High Memory Watermark (vm_memory_high_watermark).
  • RabbitMQ initiates alarms, blocks all incoming publishers (TCP backpressure), and halts message throughput across the entire cluster.

6. How do you implement non-blocking exponential backoff retries using Dead Letter Exchanges (DLX) in RabbitMQ?

Answer:

Directly retrying failed messages with basic.nack(requeue: true) immediately puts the message at the front of the same queue. If the failure is persistent (e.g., database down), the worker immediately re-consumes it, causing a 100% CPU busy-spin loop that blocks all other legitimate queue messages.

Dead-Letter Exponential Backoff Topology:

  1. Main Queue (orders.queue): Consumed by application workers.
  2. When processing fails, worker calls basic.nack(requeue: false).
  3. The main queue's x-dead-letter-exchange forwards the message to a Retry Exchange.
  4. The message routes to a series of delay queues with Message TTL (e.g. retry.10s, retry.60s, retry.5m):
  • Delay queues have no consumers.
  • Configured with x-message-ttl: 10000 and x-dead-letter-exchange: main.exchange.
  1. When the 10-second TTL expires, RabbitMQ automatically dead-letters the message back into the Main Queue for another processing attempt without blocking any concurrent traffic.
  2. Messages exceeding maximum retry counts are forwarded to a permanent orders.poison.dlq.

7. How does a Topic Exchange match routing keys, and what is the difference between * and #?

Answer:

Routing keys in AMQP Topic Exchanges consist of dot-delimited words (e.g., us.shipping.express).

  • * (asterisk): Substitutes for exactly one word.
  • Pattern: *.shipping.* matches us.shipping.express and eu.shipping.standard.
  • Does NOT match shipping.express or us.west.shipping.express.
  • # (hash): Substitutes for zero or more words.
  • Pattern: orders.# matches orders, orders.created, orders.us.california.b2b.priority.
  • Internal Optimization:

RabbitMQ indexes topic bindings using a Trie (Prefix Tree) data structure. Incoming routing keys traverse the trie in $\mathcal{O}(K)$ time where $K$ is the number of words in the routing key, rather than performing slow sequential regex evaluations across thousands of queues.

8. When should an architect choose a Headers Exchange over a Topic Exchange?

Answer:

  • Topic Exchange Limitations:
  • Requires a single linear dot-separated hierarchy (e.g., format.vendor.region).
  • Cannot cleanly express non-hierarchical, multi-dimensional queries. For example, if a message has format json, region us, vendor acme, and encrypted true, routing keys become combinatorial (json.us.acme.true).
  • Headers Exchange Advantages:
  • Operates on arbitrary key-value metadata dictionaries.
  • Supports x-match: all (AND logic) and x-match: any (OR logic).
  • Best Suited For: Multi-tenant architectures where messages have disparate dimensions (e.g., tenant_id, environment: staging, data_classification: pii), or when the payload structure naturally maps to HTTP headers.

9. For LeetCode #130 (Surrounded Regions), why is reverse boundary flood fill superior to searching from every interior cell?

Answer:

  • Forward Interior Search:
  • Testing each 'O' cell requires checking whether its connected component can reach any boundary.
  • If a large connected component of size $K$ does not touch the boundary, we must track and flip all its cells. If it does touch the boundary, all explored paths must be retained without flipping.
  • Requires maintaining temporary component lists, tracking visited states, and handling multiple rollbacks.
  • Reverse Boundary Flood Fill:
  • We observe that only cells connected to the boundary survive.
  • We initiate DFS/BFS strictly from the boundary 'O' cells (at most $2M + 2N$ perimeter cells).
  • Any cell reached is marked with a safe sentinel ('#').
  • A single linear $\mathcal{O}(M \times N)$ pass flips all remaining 'O's (which are guaranteed to be captured) to 'X', and restores '#' to 'O'.
  • Zero rollback overhead and optimal cache-friendly linear memory access.

10. For LeetCode #994 (Rotting Oranges), why must the contagion simulation be solved with Multi-Source BFS rather than DFS?

Answer:

  • Multi-Source BFS:
  • BFS explores a graph in concentric waves of equal distance (Level-by-Level).
  • In Rotting Oranges, all initially rotten oranges spread infection simultaneously in parallel at minute $1$, minute $2$, etc.
  • By enqueuing all initial rotten oranges into the BFS queue at minute $0$, the BFS naturally simulates this simultaneous parallel expansion. The number of BFS level expansions equals the exact minimum minutes required.
  • Why DFS Fails:
  • DFS explores one deep path to its termination before backtracking.
  • A single rotten orange might take a 20-step path to rot an orange that was actually adjacent to another rotten orange that would have reached it in minute 1.
  • DFS cannot easily calculate the minimum parallel time without complex, expensive minimum timestamp relaxation across all cells.

public record AmqpMessage(
    ulong DeliveryTag,
    string MessageId,
    string RoutingKey,
    string Payload,

public class QueueBinding
{
    public string QueueName { get; }
    public string RoutingKeyPattern { get; }
    public IReadOnlyDictionary<string, object>? HeaderFilter { get; }
    public HeadersMatchMode MatchMode { get; }

    public QueueBinding(

        string routingKeyPattern = "",
        IReadOnlyDictionary<string, object>? headerFilter = null,

    {
        QueueName = queueName;

public class AmqpQueue
{
    public string Name { get; }
    public string? DeadLetterExchange { get; }
    public string? DeadLetterRoutingKey { get; }
    public int PrefetchCount { get; set; } = 10;

    private readonly ConcurrentQueue<AmqpMessage> _messages = new();
    private readonly ConcurrentDictionary<ulong, AmqpMessage> _unackedMessages = new();

    public int ReadyMessageCount => _messages.Count;
    public int UnackedMessageCount => _unackedMessages.Count;

    public AmqpQueue(string name, string? deadLetterExchange = null, string? deadLetterRoutingKey = null)
    {
        Name = name;
        DeadLetterExchange = deadLetterExchange;
        DeadLetterRoutingKey = deadLetterRoutingKey;
    }

    public void Enqueue(AmqpMessage message, bool toFront = false)
    {
        if (toFront)
        {
            // Requeue to head: snapshot, clear, push redelivered, restore remaining
            var list = _messages.ToList();
            while (_messages.TryDequeue(out _)) { }
            _messages.Enqueue(message);
            foreach (var item in list)
            {
                _messages.Enqueue(item);
            }
        }
        else
        {
            _messages.Enqueue(message);
        }
    }

    public AmqpMessage? Dequeue()
    {
        if (_unackedMessages.Count >= PrefetchCount)
        {
            // QoS Prefetch limit reached: hold message delivery until ACK/NACK
            return null;
        }

        if (_messages.TryDequeue(out var msg))
        {
            _unackedMessages[msg.DeliveryTag] = msg;
            return msg;
        }
        return null;
    }

    public bool Ack(ulong deliveryTag)
    {
        return _unackedMessages.TryRemove(deliveryTag, out _);
    }

    public AmqpMessage? Nack(ulong deliveryTag, bool requeue)
    {
        if (!_unackedMessages.TryRemove(deliveryTag, out var msg))
            return null;

        if (requeue)
        {
            Enqueue(msg with { Redelivered = true }, toFront: true);
        }

        return msg;
    }
}

/// <summary>
/// High-fidelity in-memory AMQP 0-9-1 Message Broker Simulator.
/// Simulates Direct, Topic, Fanout, and Headers exchanges, Publisher Confirms,
/// Consumer Ack/Nack, Dead Letter Exchanges (DLX), and Prefetch QoS.
/// </summary>
public class AmqpBrokerSimulator
{
    private readonly ConcurrentDictionary<string, (ExchangeType Type, List<QueueBinding> Bindings)> _exchanges = new();
    private readonly ConcurrentDictionary<string, AmqpQueue> _queues = new();
    private ulong _deliveryTagSequence;

    public int PublishedCount { get; private set; }
    public int AckedCount { get; private set; }
    public int NackedCount { get; private set; }
    public int DeadLetteredCount { get; private set; }

    public void DeclareExchange(string name, ExchangeType type)
    {
        _exchanges.TryAdd(name, (type, new List<QueueBinding>()));
    }

    public void DeclareQueue(string name, string? deadLetterExchange = null, string? deadLetterRoutingKey = null, int prefetchCount = 10)
    {
        var queue = new AmqpQueue(name, deadLetterExchange, deadLetterRoutingKey) { PrefetchCount = prefetchCount };
        _queues.TryAdd(name, queue);
    }

    public void BindQueue(
        string queueName,
        string exchangeName,
        string routingKey = "",
        IReadOnlyDictionary<string, object>? headers = null,
        HeadersMatchMode matchMode = HeadersMatchMode.All)
    {
        if (!_exchanges.TryGetValue(exchangeName, out var exchange))
            throw new InvalidOperationException($"Exchange '{exchangeName}' does not exist.");
        if (!_queues.ContainsKey(queueName))
            throw new InvalidOperationException($"Queue '{queueName}' does not exist.");

        lock (exchange.Bindings)
        {
            exchange.Bindings.Add(new QueueBinding(queueName, routingKey, headers, matchMode));
        }
    }

    /// <summary>
    /// Publishes a message to an exchange with Publisher Confirms semantics.
    /// Returns true (ACK) if successfully delivered to matching queues, or false (NACK) if unrouted on mandatory.
    /// </summary>
    public bool Publish(
        string exchangeName,
        string routingKey,
        string payload,
        IReadOnlyDictionary<string, object>? headers = null,
        bool mandatory = false)
    {
        if (!_exchanges.TryGetValue(exchangeName, out var exchange))
            throw new InvalidOperationException($"Exchange '{exchangeName}' not declared.");

        headers ??= new Dictionary<string, object>();
        var matchingQueueNames = GetMatchingQueues(exchange.Type, exchange.Bindings, routingKey, headers);

        if (matchingQueueNames.Count == 0 && mandatory)
        {
            return false; // Publisher confirm NACK for unroutable mandatory message
        }

        var tag = Interlocked.Increment(ref _deliveryTagSequence);
        var message = new AmqpMessage(
            DeliveryTag: tag,
            MessageId: Guid.NewGuid().ToString("N"),
            RoutingKey: routingKey,
            Payload: payload,
            Headers: headers,
            Redelivered: false,
            TimestampUtc: DateTime.UtcNow);

        foreach (var qName in matchingQueueNames)
        {
            if (_queues.TryGetValue(qName, out var queue))
            {
                queue.Enqueue(message);
            }
        }

        PublishedCount++;
        return true; // Publisher confirm ACK
    }

    public AmqpMessage? BasicGet(string queueName)
    {
        if (!_queues.TryGetValue(queueName, out var queue))
            return null;

        return queue.Dequeue();
    }

    public bool BasicAck(string queueName, ulong deliveryTag)
    {
        if (_queues.TryGetValue(queueName, out var queue))
        {
            var success = queue.Ack(deliveryTag);
            if (success) AckedCount++;
            return success;
        }
        return false;
    }

    public bool BasicNack(string queueName, ulong deliveryTag, bool requeue)
    {
        if (!_queues.TryGetValue(queueName, out var queue))
            return false;

        var message = queue.Nack(deliveryTag, requeue);
        if (message == null) return false;

        NackedCount++;

        if (!requeue && !string.IsNullOrEmpty(queue.DeadLetterExchange))
        {
            // Route to Dead Letter Exchange (DLX)
            DeadLetteredCount++;
            var dlxRoutingKey = queue.DeadLetterRoutingKey ?? message.RoutingKey;
            Publish(queue.DeadLetterExchange, dlxRoutingKey, message.Payload, message.Headers);
        }

        return true;
    }

    public AmqpQueue? GetQueue(string name)
    {
        _queues.TryGetValue(name, out var queue);
        return queue;
    }

    private HashSet<string> GetMatchingQueues(
        ExchangeType type,
        List<QueueBinding> bindings,
        string routingKey,
        IReadOnlyDictionary<string, object> headers)
    {
        var matched = new HashSet<string>();
        lock (bindings)
        {
            foreach (var b in bindings)
            {
                if (IsBindingMatch(type, b, routingKey, headers))
                {
                    matched.Add(b.QueueName);
                }
            }
        }
        return matched;
    }

    private bool IsBindingMatch(
        ExchangeType type,
        QueueBinding binding,
        string routingKey,
        IReadOnlyDictionary<string, object> headers)
    {
        return type switch
        {
            ExchangeType.Fanout => true,
            ExchangeType.Direct => string.Equals(binding.RoutingKeyPattern, routingKey, StringComparison.Ordinal),
            ExchangeType.Topic => MatchTopicPattern(binding.RoutingKeyPattern, routingKey),
            ExchangeType.Headers => MatchHeaders(binding.HeaderFilter, headers, binding.MatchMode),
            _ => false
        };
    }

    private static bool MatchTopicPattern(string pattern, string routingKey)
    {
        // AMQP 0-9-1 Topic Exchange rules:
        // * matches exactly one word
        // # matches zero or more words
        var regexPattern = "^" + Regex.Escape(pattern)
            .Replace("\\*", "[^.]+")
            .Replace("\\#", ".*") + "$";

        return Regex.IsMatch(routingKey, regexPattern);
    }

    private static bool MatchHeaders(
        IReadOnlyDictionary<string, object>? filter,
        IReadOnlyDictionary<string, object> headers,
        HeadersMatchMode mode)
    {
        if (filter == null || filter.Count == 0) return true;

        if (mode == HeadersMatchMode.All)
        {
            foreach (var (k, v) in filter)
            {
                if (!headers.TryGetValue(k, out var actual) || !object.Equals(v, actual))
                    return false;
            }
            return true;
        }
        else // Any
        {
            foreach (var (k, v) in filter)
            {
                if (headers.TryGetValue(k, out var actual) && object.Equals(v, actual))
                    return true;
            }
            return false;
        }
    }
}

/// <summary>
/// Solvers for Graph / Grid algorithms:
/// 1. LeetCode #130: Surrounded Regions (Medium)
/// 2. LeetCode #994: Rotting Oranges (Medium)
/// </summary>
public class SurroundedRegionsAndOrangesSolver
{
    private static readonly int[] RowOffsets = { -1, 1, 0, 0 };
    private static readonly int[] ColOffsets = { 0, 0, -1, 1 };

    /// <summary>
    /// Solves LeetCode #130: Surrounded Regions using reverse boundary DFS.
    /// Captures all regions surrounded by 'X' by preserving boundary-connected 'O's.
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(M * N) recursion stack.
    /// </summary>
    public void SolveSurroundedRegions(char[][]? board)
    {
        if (board == null || board.Length == 0 || board[0].Length == 0)
            return;

        int m = board.Length;
        int n = board[0].Length;

        // 1. Mark boundary 'O's and their connected component as '#' (protected)
        for (int r = 0; r < m; r++)
        {
            if (board[r][0] == 'O') DfsMarkSafe(board, r, 0, m, n);
            if (board[r][n - 1] == 'O') DfsMarkSafe(board, r, n - 1, m, n);
        }

        for (int c = 0; c < n; c++)
        {
            if (board[0][c] == 'O') DfsMarkSafe(board, 0, c, m, n);
            if (board[m - 1][c] == 'O') DfsMarkSafe(board, m - 1, c, m, n);
        }

        // 2. Flip all unprotected 'O's to 'X', and restore '#' back to 'O'
        for (int r = 0; r < m; r++)
        {
            for (int c = 0; c < n; c++)
            {
                if (board[r][c] == 'O')
                {
                    board[r][c] = 'X'; // Captured
                }
                else if (board[r][c] == '#')
                {
                    board[r][c] = 'O'; // Restored
                }
            }
        }
    }

    private void DfsMarkSafe(char[][] board, int r, int c, int m, int n)
    {
        if (r < 0 || r >= m || c < 0 || c >= n || board[r][c] != 'O')
            return;

        board[r][c] = '#'; // Mark safe

        for (int i = 0; i < 4; i++)
        {
            DfsMarkSafe(board, r + RowOffsets[i], c + ColOffsets[i], m, n);
        }
    }

    /// <summary>
    /// Solves LeetCode #994: Rotting Oranges using level-by-level Multi-Source Breadth-First Search (BFS).
    /// Time Complexity: O(M * N)
    /// Space Complexity: O(M * N)
    /// </summary>
    public int OrangesRotting(int[][]? grid)
    {
        if (grid == null || grid.Length == 0 || grid[0].Length == 0)
            return 0;

        int m = grid.Length;
        int n = grid[0].Length;

        var queue = new Queue<(int r, int c)>();
        int freshCount = 0;

        // Clone grid to preserve caller input
        var workingGrid = new int[m][];
        for (int i = 0; i < m; i++)
        {
            workingGrid[i] = (int[])grid[i].Clone();
            for (int j = 0; j < n; j++)
            {
                if (workingGrid[i][j] == 2)
                {
                    queue.Enqueue((i, j));
                }
                else if (workingGrid[i][j] == 1)
                {
                    freshCount++;
                }
            }
        }

        if (freshCount == 0) return 0;

        int minutesElapsed = 0;

        while (queue.Count > 0 && freshCount > 0)
        {
            int currentBatchSize = queue.Count;
            minutesElapsed++;

            for (int i = 0; i < currentBatchSize; i++)
            {
                var (r, c) = queue.Dequeue();

                for (int d = 0; d < 4; d++)
                {
                    int nr = r + RowOffsets[d];
                    int nc = c + ColOffsets[d];

                    if (nr >= 0 && nr < m && nc >= 0 && nc < n && workingGrid[nr][nc] == 1)
                    {
                        workingGrid[nr][nc] = 2; // Infect to rotten
                        freshCount--;
                        queue.Enqueue((nr, nc));
                    }
                }
            }
        }

        return freshCount == 0 ? minutesElapsed : -1;
    }
}
