Deep Dive Notes: Notification Service Architecture

1. High-Scale Notification Pipeline Design

  • Scale Requirements:
  • 10M daily active users $\times$ 10 notifications/day = 100M notifications/day.
  • Average load: $\approx 1,160$ messages/sec; Peak load: $15,000$ messages/sec (e.g. Flash sales, Breaking news).
  • Decoupled Architecture:
  • Ingress API: Validates payload, verifies idempotency key, pushes message to Kafka/RabbitMQ.
  • Workers: Consume by channel and priority. For example, sms-high-priority topic has dedicated worker pools with strict SLAs (< 5s for OTPs), while email-marketing-low has rate-controlled worker pools to avoid blacklisting.
  • Circuit Breakers & Vendor Fallbacks:
  • External vendors (Twilio, SendGrid, APNs, FCM) have fluctuating error rates and rate limits.
  • Wrap provider calls in Polly Circuit Breakers. If Twilio error rate exceeds 15% in a 30s window, trip the breaker and divert traffic to AWS SNS or Infobip automatically.

2. Throttling & User Preferences

  • Sliding-Window Rate Limiting:
  • Redis Sorted Sets (ZADD timestamp, ZREMRANGEBYSCORE 0 now - window, ZCARD) allow sliding-window rate limiting per (user_id, channel).
  • Enforces quiet hours (e.g. 10 PM – 8 AM in recipient's local timezone) by deferring non-urgent messages until morning.
  • Preference Storage:
  • Cassandra or DynamoDB with primary key (user_id) and a bitmask/JSON column of channel opt-outs (sms: false, email: true, push: true). Read-heavy cached in Redis.

3. LeetCode #78 & #90 (Subsets) Backtracking Mechanics

  • The recursion tree for subsets forms a state-space tree where each decision point represents including or excluding an element.
  • For Subsets II (with duplicates):
  • Sorting brings duplicate numbers adjacent: e.g. [1, 2, 2].
  • Sibling branches represent choices at the same recursion level (i > start). If nums[i] == nums[i - 1], choosing nums[i] would generate the identical subtree already explored by nums[i - 1].
  • Skipping nums[i] when i > start prunes duplicate branches cleanly in $O(1)$ without allocating secondary sets.

Day 36: System Design: Notification Service

Architectural Overview

A large-scale notification system must deliver billions of notifications across multiple delivery channels (Email, SMS, Mobile Push, In-App WebSockets) with strict latency guarantees, priority isolation, and abuse protections.

This module implements a resilient notification dispatch engine in .NET 8 featuring:

  • Priority-Based Dispatch Queues: Separate prioritized scheduling (High for OTPs/Security alerts, Normal for transactional receipts, Low for marketing/digests). High-priority items always preempt low-priority items.
  • Provider Abstraction & Automated Failover: Interface INotificationProvider with multi-vendor redundancy (e.g., Primary Twilio -> Secondary AWS SNS fallback on circuit degradation).
  • Per-User Rate Limiting & Throttling: Sliding window rate limiter preventing user notification fatigue and provider API overage (e.g. max 5 SMS/min).
  • User Preference & Opt-Out Matrix: Fine-grained subscription settings honoring user preferences per channel.
  • Idempotent Deduplication: Cache-backed idempotency key verification preventing duplicate charges or duplicate SMS delivery during network retries.

LeetCode #78 & #90: Subsets I & II (Medium)

  • LeetCode #78 (Subsets):
  • Generate power set of size $2^N$ for unique elements.
  • Implemented via Backtracking (DFS tree exploration) and Bit Manipulation ($2^N$ binary bitmasks).
  • LeetCode #90 (Subsets II):
  • Generate power set when array contains duplicate elements.
  • Sorts input and skips duplicate sibling branches:

if (i > start && nums[i] == nums[i - 1]) continue;

  • Guarantees $100\%$ unique subset generation without post-processing HashSet allocations.

10 Senior / Staff-Level Interview Questions with In-Depth Answers:
Q1 How do you design a notification system capable of handling 100 million notifications per day with peak bursts?
▼

Answer:

  1. Asynchronous Ingestion API: A stateless, highly-scalable API gateway receives notification requests, writes to an in-memory Redis deduplication store, and enqueues tasks into partitioned message queues (Kafka or RabbitMQ).
  2. Topic Partitioning by Channel & Priority: Separate message queues by delivery speed requirements (sms-critical, push-critical, email-bulk). Critical queues (OTPs, password resets) have dedicated auto-scaled worker pools with unshared provider capacity.
  3. Worker Fleet: Workers consume messages, verify user preferences from a read-through Redis cache, evaluate rate limit token buckets, and call downstream external providers (Twilio, SendGrid, FCM, APNs) using connection pooling and HTTP keep-alive.
  4. Dead-Letter Queues (DLQ): Failed deliveries after exponential retries are deposited into a DLQ for operational triage and alert auditing.
Q2 How do you ensure high-priority notifications (OTPs) are delivered within 5 seconds even when millions of marketing notifications are queued?
▼

Answer:

Never mix operational priority levels in the same FIFO message queue.

  • Use Priority-Isolated Queuing: Maintain physically or logically separate queues for High (OTP, 2FA, fraud alerts), Normal (order confirmations, delivery tracking), and Low (marketing newsletters, weekly digests).
  • Dedicated worker capacity: Dedicate 70% of worker threads/pods strictly to the High priority queue. If the Low queue experiences a massive backlog (e.g., 5 million marketing emails), it only impacts the Low workers; the High queue remains virtually empty and processed in sub-second latency.
  • Provider prioritization: Reserve separate sub-accounts or dedicated outbound IP pools with vendors (e.g. Twilio High-Throughput Short Codes) exclusively for transactional traffic to prevent marketing email reputation degradation or rate limits from throttling OTPs.
Q3 How do you implement rate limiting per user per channel (e.g. max 3 SMS per hour) at scale?
▼

Answer:

Use a Distributed Sliding Window in Redis using Sorted Sets (ZSET):

  • Key: ratelimit:sms:{userId}
  • When an SMS request arrives at time $T$:
  1. ZREMRANGEBYSCORE key 0 (T - 3600) (remove timestamps older than 1 hour).
  2. ZCARD key (count remaining timestamps in the 1-hour window).
  3. If count $\ge 3$, reject with "Rate limit exceeded".
  4. Else, ZADD key T T and EXPIRE key 3600. Allow execution.
  • Executed via an atomic Redis Lua script to prevent race conditions across parallel worker nodes.
Q4 How do you handle third-party notification provider outages (e.g., Twilio outage)?
▼

Answer:

  1. Provider Abstraction: Define a generic INotificationProvider interface so application logic is completely decoupled from provider SDKs.
  2. Circuit Breakers (Polly in .NET): Track failure rates and timeout percentages. If Twilio returns HTTP 5xx or times out on > 20% of calls over 30 seconds, trip the breaker to Open state.
  3. Automated Secondary Failover: When the primary circuit opens or throws an exception, dynamically re-route traffic to secondary providers (e.g. AWS SNS, Sinch, Infobip).
  4. Health Checking & Canary Probing: The circuit transitions to Half-Open after 60 seconds, sending test canary probes to verify primary recovery before switching traffic back.
Q5 How do you prevent duplicate notification delivery when clients retry failed requests?
▼

Answer:

  1. Idempotency Keys: Require an Idempotency-Key (e.g., derived from eventId or orderId + action).
  2. Atomic Lock / Cache: Before processing, the worker attempts an atomic SET key:notification:{idempotencyKey} "PROCESSING" EX 300 NX in Redis.
  • If key already exists, return immediate cached success without re-sending.
  1. Provider-Level Idempotency: Forward the idempotency key to downstream providers that support it (e.g. Stripe, SendGrid, FCM message IDs) so that even if the internal worker crashes mid-network transmission, the vendor will not dispatch two duplicate physical SMS/emails.
Q6 How do you store and enforce user notification preferences and "Do Not Disturb" (quiet hours)?
▼

Answer:

  • Store user preferences in a primary NoSQL database (DynamoDB/Cassandra) with high read availability, cached in Redis:
  {
    "userId": "usr_99",
    "optedOut": ["marketing_email", "promotional_sms"],
    "quietHours": { "start": "22:00", "end": "08:00", "timezone": "America/New_York" }
  }
  • Before queuing or dispatching non-critical notifications, convert the current UTC time to the user's localized timezone.
  • If current time falls within quietHours, delay message delivery by calculating seconds until 08:00 AM and enqueueing into a delayed/scheduled queue (e.g., RabbitMQ dead-letter exchange with TTL or Redis Sorted Set schedule).
Q7 What telemetry and metrics should be monitored on a notification service?
▼

Answer:

  • Ingestion Rate vs Delivery Rate: Graphing messages queued vs messages acknowledged by vendors.
  • Queue Lag / Backlog Depth: Monitored per channel and priority; triggers alerts if sms-critical lag > 100 messages.
  • Provider Latency & Error Rate: P95/P99 latency of Twilio, SendGrid, APNs, and FCM HTTP endpoints.
  • Delivery Receipt (DLR) Conversion: Percentage of messages marked "Delivered" by mobile carriers via incoming webhooks.
  • Bounce & Complaint Rates: Hard bounces and spam reports on email channels to maintain domain reputation (SPF/DKIM/DMARC).
Q8 In LeetCode #78 (Subsets), what is the difference in time and space complexity between Backtracking and Bit Manipulation?
▼

Answer:

  • Both algorithms have a time complexity of $O(N \times 2^N)$ because there are $2^N$ total subsets, and copying each subset of average length $N/2$ into the final result requires $O(N)$ work.
  • Backtracking:
  • Recursion tree depth is $N$. Space complexity is $O(N)$ for the recursion stack and temporary subset list.
  • Generates subsets in lexicographical prefix order.
  • Bit Manipulation:
  • Loops from $0$ to $2^N - 1$. Iterative with $O(1)$ auxiliary memory (ignoring the output list).
  • Elegant and avoids recursion overhead, but limited to $N \le 64$ due to integer bit width.
Q9 In LeetCode #90 (Subsets II), why does sorting the array and checking `if (i > start && nums[i] == nums[i - 1]) continue;` eliminate duplicate subsets?
▼

Answer:

  • When generating subsets from an array with duplicates (e.g. [1, 2, 2]), duplicate subsets occur when the same value is selected at the same decision depth across different branches.
  • Sorting guarantees all duplicate numbers are placed contiguously.
  • In the loop for (int i = start; i < nums.Length; i++):
  • When $i = \text{start}$, we are exploring the first available instance of this number at this recursion level.
  • When $i > \text{start}$ and $\text{nums}[i] == \text{nums}[i - 1]$, we are considering a sibling branch at the exact same tree level that has the same value.
  • Pruning sibling duplicates skips generating identical subtrees without needing an expensive HashSet of lists.
Q10 How do you handle mobile push notification token invalidation (Apple APNs / Google FCM)?
▼

Answer:

Mobile push tokens expire when users uninstall the app, switch devices, or wipe data.

  1. When calling APNs/FCM, the vendor returns specific error codes: APNs BadDeviceToken (410 Gone) or FCM UNREGISTERED / INVALID_ARGUMENT.
  2. The notification worker intercepts these specific HTTP response codes.
  3. The worker asynchronously emits a DeviceTokenInvalidatedEvent to an internal queue.
  4. An account service updates the device registry database, marking the token inactive/deleted so subsequent notifications are not sent, saving bandwidth and preventing provider penalty rate limiting.

public enum NotificationChannel

public enum NotificationPriority

public record NotificationMessage(

    string? ErrorReason = null

public interface INotificationProvider
{
    NotificationChannel Channel { get; }
    string Name { get; }
    bool IsHealthy { get; set; }
    Task<bool> SendAsync(NotificationMessage message);
}

public class MockNotificationProvider : INotificationProvider
{
    public NotificationChannel Channel { get; }
    public string Name { get; }
    public bool IsHealthy { get; set; } = true;
    public List<NotificationMessage> DeliveredMessages { get; } = new();

    public MockNotificationProvider(NotificationChannel channel, string name)
    {
        Channel = channel;
        Name = name;
    }

    public Task<bool> SendAsync(NotificationMessage message)
    {
        if (!IsHealthy)
        {
            return Task.FromResult(false);
        }
        DeliveredMessages.Add(message);
        return Task.FromResult(true);
    }
}

public class UserNotificationPreferences
{
    public string UserId { get; set; } = string.Empty;
    public HashSet<NotificationChannel> OptedOutChannels { get; } = new();
}

public class NotificationRateLimiter
{
    private readonly Dictionary<string, List<DateTime>> _userChannelTimestamps = new();
    private readonly object _lock = new();

    public bool Allow(string userId, NotificationChannel channel, int maxPerWindow, TimeSpan window)
    {
        lock (_lock)
        {
            string key = $"{userId}:{channel}";
            var now = DateTime.UtcNow;
            if (!_userChannelTimestamps.TryGetValue(key, out var timestamps))
            {
                timestamps = new List<DateTime>();
                _userChannelTimestamps[key] = timestamps;
            }

            // Purge expired entries
            timestamps.RemoveAll(t => now - t > window);

            if (timestamps.Count >= maxPerWindow)
            {
                return false;
            }

            timestamps.Add(now);
            return true;
        }
    }
}

public class NotificationDispatcher
{
    private readonly List<INotificationProvider> _providers;
    private readonly Dictionary<string, UserNotificationPreferences> _preferences = new();
    private readonly NotificationRateLimiter _rateLimiter;
    private readonly HashSet<string> _seenIdempotencyKeys = new();
    private readonly PriorityQueue<NotificationMessage, int> _priorityQueue = new();
    private readonly object _lock = new();

    public NotificationDispatcher(IEnumerable<INotificationProvider> providers, NotificationRateLimiter? rateLimiter = null)
    {
        _providers = providers.ToList();
        _rateLimiter = rateLimiter ?? new NotificationRateLimiter();
    }

    public void SetUserPreferences(string userId, IEnumerable<NotificationChannel> optOuts)
    {
        lock (_lock)
        {
            var pref = new UserNotificationPreferences { UserId = userId };
            foreach (var ch in optOuts)
            {
                pref.OptedOutChannels.Add(ch);
            }
            _preferences[userId] = pref;
        }
    }

    public void Enqueue(NotificationMessage message)
    {
        lock (_lock)
        {
            _priorityQueue.Enqueue(message, (int)message.Priority);
        }
    }

    public int PendingQueueCount
    {
        get
        {
            lock (_lock) return _priorityQueue.Count;
        }
    }

    public async Task<NotificationResult> DispatchNextAsync()
    {
        NotificationMessage message;
        lock (_lock)
        {
            if (_priorityQueue.Count == 0)
            {
                return new NotificationResult(false, string.Empty, string.Empty, null, "Queue is empty");
            }
            message = _priorityQueue.Dequeue();
        }

        return await ProcessMessageAsync(message);
    }

    public async Task<NotificationResult> ProcessMessageAsync(NotificationMessage message)
    {
        // 1. Idempotency Check
        if (!string.IsNullOrEmpty(message.IdempotencyKey))
        {
            lock (_lock)
            {
                if (!_seenIdempotencyKeys.Add(message.IdempotencyKey))
                {
                    return new NotificationResult(true, message.MessageId, message.Channel.ToString(), null, "Deduplicated idempotent request");
                }
            }
        }

        // 2. User Preferences (Opt-out)
        lock (_lock)
        {
            if (_preferences.TryGetValue(message.UserId, out var pref) && pref.OptedOutChannels.Contains(message.Channel))
            {
                return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "User opted out of this channel");
            }
        }

        // 3. Rate Limiting (e.g. Max 5 SMS per 1 minute in tests)
        if (message.Channel == NotificationChannel.Sms)
        {
            if (!_rateLimiter.Allow(message.UserId, message.Channel, maxPerWindow: 5, window: TimeSpan.FromMinutes(1)))
            {
                return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "Rate limit exceeded for channel");
            }
        }

        // 4. Provider Selection & Fallback
        var eligibleProviders = _providers.Where(p => p.Channel == message.Channel).ToList();
        if (eligibleProviders.Count == 0)
        {
            return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "No providers registered for channel");
        }

        foreach (var provider in eligibleProviders)
        {
            try
            {
                bool success = await provider.SendAsync(message);
                if (success)
                {
                    return new NotificationResult(true, message.MessageId, message.Channel.ToString(), provider.Name);
                }
            }
            catch
            {
                // Fall through to secondary provider
            }
        }

        return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "All providers failed or unavailable");
    }
}

namespace Day36.NotificationService;

public static class SubsetsSolver
{
    /// <summary>
    /// LeetCode #78: Subsets (Medium) via Backtracking.
    /// Time Complexity: O(N * 2^N), Space Complexity: O(N) recursion stack.
    /// </summary>
    public static IList<IList<int>> Subsets(int[] nums)
    {
        var result = new List<IList<int>>();
        if (nums == null) return result;

        var current = new List<int>();
        BacktrackSubsets(nums, 0, current, result);
        return result;
    }

    private static void BacktrackSubsets(int[] nums, int start, List<int> current, List<IList<int>> result)
    {
        result.Add(new List<int>(current));

        for (int i = start; i < nums.Length; i++)
        {
            current.Add(nums[i]);
            BacktrackSubsets(nums, i + 1, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }

    /// <summary>
    /// LeetCode #78: Subsets (Medium) via Bit Manipulation.
    /// Iterates through 2^N binary bitmasks.
    /// </summary>
    public static IList<IList<int>> SubsetsBitmask(int[] nums)
    {
        var result = new List<IList<int>>();
        if (nums == null) return result;

        int n = nums.Length;
        int totalSubsets = 1 << n; // 2^n

        for (int mask = 0; mask < totalSubsets; mask++)
        {
            var subset = new List<int>();
            for (int i = 0; i < n; i++)
            {
                if ((mask & (1 << i)) != 0)
                {
                    subset.Add(nums[i]);
                }
            }
            result.Add(subset);
        }

        return result;
    }

    /// <summary>
    /// LeetCode #90: Subsets II (Medium) - contains duplicates.
    /// Sorts input and skips duplicate elements at the same tree depth.
    /// Time Complexity: O(N * 2^N), Space Complexity: O(N).
    /// </summary>
    public static IList<IList<int>> SubsetsWithDup(int[] nums)
    {
        var result = new List<IList<int>>();
        if (nums == null) return result;

        Array.Sort(nums);
        var current = new List<int>();
        BacktrackSubsetsWithDup(nums, 0, current, result);
        return result;
    }

    private static void BacktrackSubsetsWithDup(int[] nums, int start, List<int> current, List<IList<int>> result)
    {
        result.Add(new List<int>(current));

        for (int i = start; i < nums.Length; i++)
        {
            // Skip duplicate sibling branches
            if (i > start && nums[i] == nums[i - 1])
            {
                continue;
            }

            current.Add(nums[i]);
            BacktrackSubsetsWithDup(nums, i + 1, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }
}

📝 Part 1: Deep-Dive Architectural & Engineering Notes

Deep Dive Notes: Notification Service Architecture

1. High-Scale Notification Pipeline Design

  • Scale Requirements:
  • 10M daily active users $\times$ 10 notifications/day = 100M notifications/day.
  • Average load: $\approx 1,160$ messages/sec; Peak load: $15,000$ messages/sec (e.g. Flash sales, Breaking news).
  • Decoupled Architecture:
  • Ingress API: Validates payload, verifies idempotency key, pushes message to Kafka/RabbitMQ.
  • Workers: Consume by channel and priority. For example, sms-high-priority topic has dedicated worker pools with strict SLAs (< 5s for OTPs), while email-marketing-low has rate-controlled worker pools to avoid blacklisting.
  • Circuit Breakers & Vendor Fallbacks:
  • External vendors (Twilio, SendGrid, APNs, FCM) have fluctuating error rates and rate limits.
  • Wrap provider calls in Polly Circuit Breakers. If Twilio error rate exceeds 15% in a 30s window, trip the breaker and divert traffic to AWS SNS or Infobip automatically.

2. Throttling & User Preferences

  • Sliding-Window Rate Limiting:
  • Redis Sorted Sets (ZADD timestamp, ZREMRANGEBYSCORE 0 now - window, ZCARD) allow sliding-window rate limiting per (user_id, channel).
  • Enforces quiet hours (e.g. 10 PM – 8 AM in recipient's local timezone) by deferring non-urgent messages until morning.
  • Preference Storage:
  • Cassandra or DynamoDB with primary key (user_id) and a bitmask/JSON column of channel opt-outs (sms: false, email: true, push: true). Read-heavy cached in Redis.

3. LeetCode #78 & #90 (Subsets) Backtracking Mechanics

  • The recursion tree for subsets forms a state-space tree where each decision point represents including or excluding an element.
  • For Subsets II (with duplicates):
  • Sorting brings duplicate numbers adjacent: e.g. [1, 2, 2].
  • Sibling branches represent choices at the same recursion level (i > start). If nums[i] == nums[i - 1], choosing nums[i] would generate the identical subtree already explored by nums[i - 1].
  • Skipping nums[i] when i > start prunes duplicate branches cleanly in $O(1)$ without allocating secondary sets.

💡 Part 3: Senior & Staff-Level Interview Scenarios (10 Questions)

Q1 How do you design a notification system capable of handling 100 million notifications per day with peak bursts?
▼

Answer:

  1. Asynchronous Ingestion API: A stateless, highly-scalable API gateway receives notification requests, writes to an in-memory Redis deduplication store, and enqueues tasks into partitioned message queues (Kafka or RabbitMQ).
  2. Topic Partitioning by Channel & Priority: Separate message queues by delivery speed requirements (sms-critical, push-critical, email-bulk). Critical queues (OTPs, password resets) have dedicated auto-scaled worker pools with unshared provider capacity.
  3. Worker Fleet: Workers consume messages, verify user preferences from a read-through Redis cache, evaluate rate limit token buckets, and call downstream external providers (Twilio, SendGrid, FCM, APNs) using connection pooling and HTTP keep-alive.
  4. Dead-Letter Queues (DLQ): Failed deliveries after exponential retries are deposited into a DLQ for operational triage and alert auditing.
Q2 How do you ensure high-priority notifications (OTPs) are delivered within 5 seconds even when millions of marketing notifications are queued?
▼

Answer:

Never mix operational priority levels in the same FIFO message queue.

  • Use Priority-Isolated Queuing: Maintain physically or logically separate queues for High (OTP, 2FA, fraud alerts), Normal (order confirmations, delivery tracking), and Low (marketing newsletters, weekly digests).
  • Dedicated worker capacity: Dedicate 70% of worker threads/pods strictly to the High priority queue. If the Low queue experiences a massive backlog (e.g., 5 million marketing emails), it only impacts the Low workers; the High queue remains virtually empty and processed in sub-second latency.
  • Provider prioritization: Reserve separate sub-accounts or dedicated outbound IP pools with vendors (e.g. Twilio High-Throughput Short Codes) exclusively for transactional traffic to prevent marketing email reputation degradation or rate limits from throttling OTPs.
Q3 How do you implement rate limiting per user per channel (e.g. max 3 SMS per hour) at scale?
▼

Answer:

Use a Distributed Sliding Window in Redis using Sorted Sets (ZSET):

  • Key: ratelimit:sms:{userId}
  • When an SMS request arrives at time $T$:
  1. ZREMRANGEBYSCORE key 0 (T - 3600) (remove timestamps older than 1 hour).
  2. ZCARD key (count remaining timestamps in the 1-hour window).
  3. If count $\ge 3$, reject with "Rate limit exceeded".
  4. Else, ZADD key T T and EXPIRE key 3600. Allow execution.
  • Executed via an atomic Redis Lua script to prevent race conditions across parallel worker nodes.
Q4 How do you handle third-party notification provider outages (e.g., Twilio outage)?
▼

Answer:

  1. Provider Abstraction: Define a generic INotificationProvider interface so application logic is completely decoupled from provider SDKs.
  2. Circuit Breakers (Polly in .NET): Track failure rates and timeout percentages. If Twilio returns HTTP 5xx or times out on > 20% of calls over 30 seconds, trip the breaker to Open state.
  3. Automated Secondary Failover: When the primary circuit opens or throws an exception, dynamically re-route traffic to secondary providers (e.g. AWS SNS, Sinch, Infobip).
  4. Health Checking & Canary Probing: The circuit transitions to Half-Open after 60 seconds, sending test canary probes to verify primary recovery before switching traffic back.
Q5 How do you prevent duplicate notification delivery when clients retry failed requests?
▼

Answer:

  1. Idempotency Keys: Require an Idempotency-Key (e.g., derived from eventId or orderId + action).
  2. Atomic Lock / Cache: Before processing, the worker attempts an atomic SET key:notification:{idempotencyKey} "PROCESSING" EX 300 NX in Redis.
  • If key already exists, return immediate cached success without re-sending.
  1. Provider-Level Idempotency: Forward the idempotency key to downstream providers that support it (e.g. Stripe, SendGrid, FCM message IDs) so that even if the internal worker crashes mid-network transmission, the vendor will not dispatch two duplicate physical SMS/emails.
Q6 How do you store and enforce user notification preferences and "Do Not Disturb" (quiet hours)?
▼

Answer:

  • Store user preferences in a primary NoSQL database (DynamoDB/Cassandra) with high read availability, cached in Redis:
  {
    "userId": "usr_99",
    "optedOut": ["marketing_email", "promotional_sms"],
    "quietHours": { "start": "22:00", "end": "08:00", "timezone": "America/New_York" }
  }
  • Before queuing or dispatching non-critical notifications, convert the current UTC time to the user's localized timezone.
  • If current time falls within quietHours, delay message delivery by calculating seconds until 08:00 AM and enqueueing into a delayed/scheduled queue (e.g., RabbitMQ dead-letter exchange with TTL or Redis Sorted Set schedule).
Q7 What telemetry and metrics should be monitored on a notification service?
▼

Answer:

  • Ingestion Rate vs Delivery Rate: Graphing messages queued vs messages acknowledged by vendors.
  • Queue Lag / Backlog Depth: Monitored per channel and priority; triggers alerts if sms-critical lag > 100 messages.
  • Provider Latency & Error Rate: P95/P99 latency of Twilio, SendGrid, APNs, and FCM HTTP endpoints.
  • Delivery Receipt (DLR) Conversion: Percentage of messages marked "Delivered" by mobile carriers via incoming webhooks.
  • Bounce & Complaint Rates: Hard bounces and spam reports on email channels to maintain domain reputation (SPF/DKIM/DMARC).
Q8 In LeetCode #78 (Subsets), what is the difference in time and space complexity between Backtracking and Bit Manipulation?
▼

Answer:

  • Both algorithms have a time complexity of $O(N \times 2^N)$ because there are $2^N$ total subsets, and copying each subset of average length $N/2$ into the final result requires $O(N)$ work.
  • Backtracking:
  • Recursion tree depth is $N$. Space complexity is $O(N)$ for the recursion stack and temporary subset list.
  • Generates subsets in lexicographical prefix order.
  • Bit Manipulation:
  • Loops from $0$ to $2^N - 1$. Iterative with $O(1)$ auxiliary memory (ignoring the output list).
  • Elegant and avoids recursion overhead, but limited to $N \le 64$ due to integer bit width.
Q9 In LeetCode #90 (Subsets II), why does sorting the array and checking `if (i > start && nums[i] == nums[i - 1]) continue;` eliminate duplicate subsets?
▼

Answer:

  • When generating subsets from an array with duplicates (e.g. [1, 2, 2]), duplicate subsets occur when the same value is selected at the same decision depth across different branches.
  • Sorting guarantees all duplicate numbers are placed contiguously.
  • In the loop for (int i = start; i < nums.Length; i++):
  • When $i = \text{start}$, we are exploring the first available instance of this number at this recursion level.
  • When $i > \text{start}$ and $\text{nums}[i] == \text{nums}[i - 1]$, we are considering a sibling branch at the exact same tree level that has the same value.
  • Pruning sibling duplicates skips generating identical subtrees without needing an expensive HashSet of lists.
Q10 How do you handle mobile push notification token invalidation (Apple APNs / Google FCM)?
▼

Answer:

Mobile push tokens expire when users uninstall the app, switch devices, or wipe data.

  1. When calling APNs/FCM, the vendor returns specific error codes: APNs BadDeviceToken (410 Gone) or FCM UNREGISTERED / INVALID_ARGUMENT.
  2. The notification worker intercepts these specific HTTP response codes.
  3. The worker asynchronously emits a DeviceTokenInvalidatedEvent to an internal queue.
  4. An account service updates the device registry database, marking the token inactive/deleted so subsequent notifications are not sent, saving bandwidth and preventing provider penalty rate limiting.

public class NotificationRateLimiter
{
    private readonly Dictionary<string, List<DateTime>> _userChannelTimestamps = new();
    private readonly object _lock = new();

    public bool Allow(string userId, NotificationChannel channel, int maxPerWindow, TimeSpan window)
    {
        lock (_lock)
        {
            string key = $"{userId}:{channel}";
            var now = DateTime.UtcNow;
            if (!_userChannelTimestamps.TryGetValue(key, out var timestamps))
            {
                timestamps = new List<DateTime>();
                _userChannelTimestamps[key] = timestamps;
            }

            // Purge expired entries
            timestamps.RemoveAll(t => now - t > window);

            if (timestamps.Count >= maxPerWindow)
            {
                return false;
            }

            timestamps.Add(now);
            return true;
        }
    }
}

public class NotificationDispatcher
{
    private readonly List<INotificationProvider> _providers;
    private readonly Dictionary<string, UserNotificationPreferences> _preferences = new();
    private readonly NotificationRateLimiter _rateLimiter;
    private readonly HashSet<string> _seenIdempotencyKeys = new();
    private readonly PriorityQueue<NotificationMessage, int> _priorityQueue = new();
    private readonly object _lock = new();

    public NotificationDispatcher(IEnumerable<INotificationProvider> providers, NotificationRateLimiter? rateLimiter = null)
    {
        _providers = providers.ToList();
        _rateLimiter = rateLimiter ?? new NotificationRateLimiter();
    }

    public void SetUserPreferences(string userId, IEnumerable<NotificationChannel> optOuts)
    {
        lock (_lock)
        {
            var pref = new UserNotificationPreferences { UserId = userId };
            foreach (var ch in optOuts)
            {
                pref.OptedOutChannels.Add(ch);
            }
            _preferences[userId] = pref;
        }
    }

    public void Enqueue(NotificationMessage message)
    {
        lock (_lock)
        {
            _priorityQueue.Enqueue(message, (int)message.Priority);
        }
    }

    public int PendingQueueCount
    {
        get
        {
            lock (_lock) return _priorityQueue.Count;
        }
    }

    public async Task<NotificationResult> DispatchNextAsync()
    {
        NotificationMessage message;
        lock (_lock)
        {
            if (_priorityQueue.Count == 0)
            {
                return new NotificationResult(false, string.Empty, string.Empty, null, "Queue is empty");
            }
            message = _priorityQueue.Dequeue();
        }

        return await ProcessMessageAsync(message);
    }

    public async Task<NotificationResult> ProcessMessageAsync(NotificationMessage message)
    {
        // 1. Idempotency Check
        if (!string.IsNullOrEmpty(message.IdempotencyKey))
        {
            lock (_lock)
            {
                if (!_seenIdempotencyKeys.Add(message.IdempotencyKey))
                {
                    return new NotificationResult(true, message.MessageId, message.Channel.ToString(), null, "Deduplicated idempotent request");
                }
            }
        }

        // 2. User Preferences (Opt-out)
        lock (_lock)
        {
            if (_preferences.TryGetValue(message.UserId, out var pref) && pref.OptedOutChannels.Contains(message.Channel))
            {
                return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "User opted out of this channel");
            }
        }

        // 3. Rate Limiting (e.g. Max 5 SMS per 1 minute in tests)
        if (message.Channel == NotificationChannel.Sms)
        {
            if (!_rateLimiter.Allow(message.UserId, message.Channel, maxPerWindow: 5, window: TimeSpan.FromMinutes(1)))
            {
                return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "Rate limit exceeded for channel");
            }
        }

        // 4. Provider Selection & Fallback
        var eligibleProviders = _providers.Where(p => p.Channel == message.Channel).ToList();
        if (eligibleProviders.Count == 0)
        {
            return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "No providers registered for channel");
        }

        foreach (var provider in eligibleProviders)
        {
            try
            {
                bool success = await provider.SendAsync(message);
                if (success)
                {
                    return new NotificationResult(true, message.MessageId, message.Channel.ToString(), provider.Name);
                }
            }
            catch
            {
                // Fall through to secondary provider
            }
        }

        return new NotificationResult(false, message.MessageId, message.Channel.ToString(), null, "All providers failed or unavailable");
    }
}

namespace Day36.NotificationService;

public static class SubsetsSolver
{
    /// <summary>
    /// LeetCode #78: Subsets (Medium) via Backtracking.
    /// Time Complexity: O(N * 2^N), Space Complexity: O(N) recursion stack.
    /// </summary>
    public static IList<IList<int>> Subsets(int[] nums)
    {
        var result = new List<IList<int>>();
        if (nums == null) return result;

        var current = new List<int>();
        BacktrackSubsets(nums, 0, current, result);
        return result;
    }

    private static void BacktrackSubsets(int[] nums, int start, List<int> current, List<IList<int>> result)
    {
        result.Add(new List<int>(current));

        for (int i = start; i < nums.Length; i++)
        {
            current.Add(nums[i]);
            BacktrackSubsets(nums, i + 1, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }

    /// <summary>
    /// LeetCode #78: Subsets (Medium) via Bit Manipulation.
    /// Iterates through 2^N binary bitmasks.
    /// </summary>
    public static IList<IList<int>> SubsetsBitmask(int[] nums)
    {
        var result = new List<IList<int>>();
        if (nums == null) return result;

        int n = nums.Length;
        int totalSubsets = 1 << n; // 2^n

        for (int mask = 0; mask < totalSubsets; mask++)
        {
            var subset = new List<int>();
            for (int i = 0; i < n; i++)
            {
                if ((mask & (1 << i)) != 0)
                {
                    subset.Add(nums[i]);
                }
            }
            result.Add(subset);
        }

        return result;
    }

    /// <summary>
    /// LeetCode #90: Subsets II (Medium) - contains duplicates.
    /// Sorts input and skips duplicate elements at the same tree depth.
    /// Time Complexity: O(N * 2^N), Space Complexity: O(N).
    /// </summary>
    public static IList<IList<int>> SubsetsWithDup(int[] nums)
    {
        var result = new List<IList<int>>();
        if (nums == null) return result;

        Array.Sort(nums);
        var current = new List<int>();
        BacktrackSubsetsWithDup(nums, 0, current, result);
        return result;
    }

    private static void BacktrackSubsetsWithDup(int[] nums, int start, List<int> current, List<IList<int>> result)
    {
        result.Add(new List<int>(current));

        for (int i = start; i < nums.Length; i++)
        {
            // Skip duplicate sibling branches
            if (i > start && nums[i] == nums[i - 1])
            {
                continue;
            }

            current.Add(nums[i]);
            BacktrackSubsetsWithDup(nums, i + 1, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }
}

        var msg2 = new NotificationMessage("msg-2", "u1", NotificationChannel.Push, NotificationPriority.High, "dev-token-1", "Title", "Body", DateTime.UtcNow, IdempotencyKey: "idem-key-99");

        Assert.True(res1.Success);
        Assert.True(res2.Success);

    }

        Assert.Equal(8, subsets.Count);

    [Fact]
    public void SubsetsWithDup_ArrayWithDuplicates_GeneratesNoDuplicateSubsets()
    {
        int[] nums = [1, 2, 2];
        var subsets = SubsetsSolver.SubsetsWithDup(nums);

        // Subsets of [1,2,2]: [], [1], [1,2], [1,2,2], [2], [2,2] -> Total 6
        Assert.Equal(6, subsets.Count);

        var stringified = subsets.Select(s => string.Join(",", s)).ToList();
        Assert.Equal(stringified.Distinct().Count(), subsets.Count);
    }
