Deep Dive Notes: High-Throughput Chat Architecture

1. WebSocket Connection Management & Gateway Tier

  • C10M Problem (10 Million Connections):
  • Long-lived persistent TCP connections consume file descriptors and socket buffers.
  • Linux tuning: sysctl -w fs.file-max=2097152, ulimit -n 1048576, tuning tcp_rmem and tcp_wmem buffer sizes (down from 128KB to 4KB per socket idle) allows a single 64GB RAM node to hold 1M idle WebSocket connections.
  • Connection Routing:
  • Load balancers (Envoy, NGINX) use IP hash or consistent hashing for sticky routing, or simple round-robin with WebSocket upgrade handling.
  • Gateway servers maintain an internal mapping: Dictionary<UserId, List<WebSocketSession>>.

2. Message Ordering & Storage Engines

  • Why NTP Wall Clocks Fail:
  • In distributed systems, clock skew between servers can be 50–200ms. If Message B arrives 10ms after Message A but Server 2's clock is 50ms behind Server 1, sorting by timestamp reverses message order.
  • Monotonic Sequencer Solutions:
  • Redis INCR per channel: INCR channel:{id}:seq provides an atomic 64-bit integer.
  • Snowflake IDs: 64-bit IDs containing timestamp prefix + machine ID + local sequence counter (guarantees rough time ordering, but gaps can exist).
  • Storage: Apache Cassandra / ScyllaDB:
  • Primary Key: ((channel_id), sequence_number) WITH CLUSTERING ORDER BY (sequence_number ASC).
  • Partitioning by channel_id groups all messages of a room on the same storage node/replica. Sequential range queries (SELECT * WHERE channel_id = ? AND sequence_number > ? LIMIT 50) hit a contiguous SSTable disk block with sub-millisecond seek latency.

3. LeetCode #39 & #40: Backtracking Combinations Tree

  • State Space:
  • At each node, decide whether to include candidates[i] and recurse on the remainder.
  • Sorting the array beforehand enables immediate termination of the loop (if (candidates[i] > remain) break;), pruning massive subtrees.
  • Combination Sum I vs II:
  • In I, elements can be picked repeatedly $\implies$ next call is Backtrack(i, remain - candidates[i]).
  • In II, elements cannot be reused $\implies$ next call is Backtrack(i + 1, remain - candidates[i]).
  • In II, duplicate elements exist $\implies$ duplicate branches at the same depth are skipped via if (i > start && candidates[i] == candidates[i - 1]) continue;.

Day 37: System Design: High-Throughput Chat System

Architectural Overview

Real-time chat systems (Slack, Discord, WhatsApp) support hundreds of millions of concurrent WebSocket connections, instant messaging, presence tracking, and ordered message histories.

This module implements a distributed real-time chat architecture in .NET 8 featuring:

  • WebSocket Session Management & Scale: Decouples client connections across distributed gateway hubs (DistributedChatHub).
  • Presence Service: Heartbeat ping/pong mechanism tracking user states (Online, Offline, Away) with timeout-based expiration and instant disconnection cleanup.
  • Cross-Server Pub/Sub Replication: Simulates Redis Pub/Sub backplane. When Alice sends a message to Server East, it publishes to the Redis topic; Server West receives the event and pushes to Bob over his active local WebSocket.
  • Monotonic Message Sequencing: Channel-level sequencers assign sequential integer IDs ($1, 2, 3, \dots$), resolving clock-drift race conditions across distributed gateway nodes and guaranteeing total causal order.
  • Read Receipts & Typing Indicators: Tracks last_read_sequence per user per channel and broadcasts transient typing indicators to peer participants without echoing to sender.

  • Elements can be reused infinitely.
  • Recursion advances with index i (allowing current element reuse).
  • Prunes early when sorted candidate exceeds remaining sum.
  • LeetCode #40 (Combination Sum II):
  • Input array contains duplicate numbers; each element used at most once.
  • Recursion advances with i + 1.

10 Senior / Staff-Level Interview Questions with In-Depth Answers:
Q1 How do you scale a WebSocket gateway to maintain 10 million concurrent active connections?
▼

Answer:

  1. OS & Kernel Tuning:
  • Increase file descriptor limits (ulimit -n 1048576).
  • Reduce TCP read/write buffer allocations (net.ipv4.tcp_rmem = 4096 87380 4194304, net.ipv4.tcp_wmem). For 1M idle connections, saving 50KB RAM per socket saves 50GB of memory.
  • Enable SO_REUSEPORT and epoll/kqueue event-driven non-blocking I/O (built into .NET Kestrel/Sockets).
  1. Stateless Gateway Tier:
  • Deploy a cluster of WebSocket gateways behind Layer 4 Network Load Balancers (AWS NLB) with TLS termination.
  • Maintain minimal session state in the gateway (only socket handle and user ID).
  1. Session Registry:
  • Store mapping of UserId -> GatewayNodeIP in Redis with TTL heartbeats so other services know which gateway holds a specific user's socket.
Q2 Why is Redis Pub/Sub alone insufficient for chat message persistence, and how do you pair it with a database?
▼

Answer:

Redis Pub/Sub is strictly "fire-and-forget":

  • If a client is temporarily offline, or a network flap occurs between Redis and the gateway, messages published to Redis Pub/Sub are lost forever. Redis does not buffer messages for disconnected pub/sub subscribers.
  • Production Architecture:
  1. The API receives the message.
  2. The message is written first to persistent storage (Cassandra/ScyllaDB) or an append-only commit log (Kafka / Redis Streams).
  3. Then the message is published to Redis Pub/Sub for real-time delivery to online users.
  4. When an offline user reconnects, they query the database for messages where sequence_number > last_received_sequence.
Q3 How do you guarantee strict causal message ordering in a group chat across distributed servers without NTP clock synchronization?
▼

Answer:

NTP clock drift between servers makes timestamps non-monotonic and prone to race conditions.

  • Per-Channel Atomic Sequencers:
  • Each chat room/channel has an independent monotonic sequence counter.
  • Implement using Redis INCR channel:{id}:seq or an atomic database sequence.
  • Every message sent to the channel receives an incremented sequence number ($1, 2, 3, \dots$).
  • Client Synchronization:
  • The client displays messages sorted by sequence_number.
  • If a client receives sequence #5 and previously had #3, it immediately detects a gap (missing #4) and requests the missing message from the server's history endpoint before rendering.
Q4 What is the optimal database schema for storing chat messages in Apache Cassandra / ScyllaDB?
▼

Answer:

Cassandra uses a two-part primary key: Partition Key and Clustering Columns.

CREATE TABLE channel_messages (
    channel_id uuid,
    sequence_id bigint,
    message_id uuid,
    sender_id uuid,
    content text,
    created_at timestamp,
    PRIMARY KEY ((channel_id), sequence_id)
) WITH CLUSTERING ORDER BY (sequence_id ASC);
  • channel_id is the Partition Key: all messages for a given room are stored together on the same cluster replica nodes.
  • sequence_id is the Clustering Column: messages are written to disk sorted contiguously. Fetching the last 50 messages (WHERE channel_id = ? AND sequence_id > ? LIMIT 50) is a fast sequential disk read.
  • For extremely active channels (millions of messages), add a bucket (e.g. (channel_id, year_month)) to prevent giant partitions (> 100MB).
Q5 How do you design a Presence Service (Online/Offline/Last Seen) for 100 million users without overloading databases?
▼

Answer:

  1. Heartbeat & Ephemeral TTL:
  • Clients send a lightweight ping every 30 seconds over the existing WebSocket connection.
  • The gateway writes to Redis: SET user:{id}:presence "ONLINE" EX 60.
  • If a client abruptly disconnects without TCP FIN (e.g., cell tower loss, tunnel), the Redis key expires after 60s, automatically marking them offline.
  1. Fan-out Optimization:
  • Do NOT broadcast presence changes to all friends on every heartbeat.
  • Instead, only broadcast presence transitions (Offline $\to$ Online, Online $\to$ Offline).
  • Use lazy-loading: When user opens a friend list or chat room, query the presence state of only the visible users in that viewport.
Q6 How do you implement "Message Read Receipts" (Single check, Double check, Blue check)?
▼

Answer:

Instead of storing a read receipt record per message per user (which causes massive write amplification in group chats):

  • Store a single monotonic pointer per user per channel: LastReadSequenceNumber.
  CREATE TABLE channel_read_pointers (
      channel_id uuid,
      user_id uuid,
      last_read_sequence bigint,
      PRIMARY KEY (channel_id, user_id)
  );
  • When a user views the chat up to message #500, update their pointer to 500.
  • Any message with sequence_number <= 500 is implicitly read by that user.
  • To render read status in a 1-on-1 chat: If Bob's last_read_sequence >= Alice's message sequence, show blue checkmark.
Q7 How do you implement transient features like "Typing Indicators" without disk writes?
▼

Answer:

Typing indicators are ephemeral, short-lived events that should never be persisted to a relational or NoSQL database.

  1. When user types, client sends a lightweight WebSocket payload: {"action": "typing", "channelId": "123"}.
  2. The gateway server throttles typing events from the client (e.g., at most once every 3 seconds).
  3. The event is pushed directly to Redis Pub/Sub topic channel:typing:{channelId}.
  4. Gateway servers holding connections for other members of that channel forward the typing event to their sockets.
  5. The receiving client shows the typing bubble and starts a 4-second local animation timer; if no refresh arrives, it clears automatically.
Q8 In LeetCode #39 (Combination Sum), why is the recursive call invoked with index `i` rather than `0` or `i + 1`?
▼

Answer:

  • If invoked with 0, the algorithm would explore combinations in different permutations (e.g., both [2, 3] and [3, 2]), resulting in duplicate combinations.
  • If invoked with i + 1, each element could only be used at most once, which fails the requirement that the same number may be chosen an unlimited number of times.
  • By invoking with i, we allow the current candidate to be reused repeatedly while enforcing that future choices are $\ge$ the current candidate index, guaranteeing all generated combinations are strictly sorted and unique.
Q9 In LeetCode #40 (Combination Sum II), why is sorting mandatory before backtracking?
▼

Answer:

  1. Early Pruning: When candidates are sorted, if candidates[i] > remain, we know every candidate after index i is also greater than remain. We can break out of the loop immediately rather than continuing useless iterations.
  2. Duplicate Subtree Elimination: Sorting brings duplicate values together. The condition if (i > start && candidates[i] == candidates[i - 1]) continue; allows us to skip identical sibling branches at the current recursion level, preventing duplicate combinations in the output.
Q10 How do you handle End-to-End Encryption (E2EE) in a distributed chat architecture?
▼

Answer:

In E2EE (e.g. Signal Protocol / WhatsApp):

  1. The server is treated as an untrusted, blind relay. The server only sees ciphertext and cryptographic metadata (pre-keys, identity keys, ratcheting parameters).
  2. Users register public identity keys and one-time prekeys with a Key Distribution Center (KDC).
  3. To start a chat, Alice fetches Bob's prekeys, initiates the Double Ratchet Algorithm, and generates a shared session key.
  4. Alice encrypts the payload locally; the server stores and routes the encrypted blob. Only Bob's private device key can decrypt the message.
  5. Search and media processing must be executed locally on the client device.

using System.Collections.Concurrent;

namespace Day37.ChatSystem;

public enum UserPresenceState
{
    Offline,
    Online,
    Away
}

public record UserPresence(string UserId, UserPresenceState State, DateTime LastSeenUtc);

public class PresenceTracker
{
    private readonly ConcurrentDictionary<string, DateTime> _heartbeats = new();
    private readonly TimeSpan _onlineTimeout;

    public PresenceTracker(TimeSpan? onlineTimeout = null)
    {
        _onlineTimeout = onlineTimeout ?? TimeSpan.FromSeconds(30);
    }

    public void Heartbeat(string userId)
    {
        _heartbeats[userId] = DateTime.UtcNow;
    }

    public void ExplicitDisconnect(string userId)
    {
        _heartbeats.TryRemove(userId, out _);
    }

    public UserPresence GetPresence(string userId)
    {
        if (_heartbeats.TryGetValue(userId, out var lastSeen))
        {
            if (DateTime.UtcNow - lastSeen <= _onlineTimeout)
            {
                return new UserPresence(userId, UserPresenceState.Online, lastSeen);
            }
        }
        return new UserPresence(userId, UserPresenceState.Offline, lastSeen == default ? DateTime.MinValue : lastSeen);
    }
}

public record ChatMessage(
    string MessageId,
    string ChannelId,
    string SenderId,
    string Content,
    long SequenceNumber,
    DateTime TimestampUtc
);

public class ChannelSequencer
{
    private readonly ConcurrentDictionary<string, long> _channelSequences = new();

    public long GetNextSequenceNumber(string channelId)
    {
        return _channelSequences.AddOrUpdate(channelId, 1, (_, current) => current + 1);
    }

    public long GetCurrentSequence(string channelId)
    {
        return _channelSequences.TryGetValue(channelId, out var seq) ? seq : 0;
    }
}

public interface IChatClientConnection
{
    string ConnectionId { get; }
    string UserId { get; }
    Task ReceiveMessageAsync(ChatMessage message);
    Task ReceiveTypingIndicatorAsync(string channelId, string userId, bool isTyping);
}

public class MockWebSocketClient : IChatClientConnection
{
    public string ConnectionId { get; } = Guid.NewGuid().ToString("N");
    public string UserId { get; }
    public List<ChatMessage> ReceivedMessages { get; } = new();
    public List<(string ChannelId, string UserId, bool IsTyping)> TypingEvents { get; } = new();

    public MockWebSocketClient(string userId)
    {
        UserId = userId;
    }

    public Task ReceiveMessageAsync(ChatMessage message)
    {
        ReceivedMessages.Add(message);
        return Task.CompletedTask;
    }

    public Task ReceiveTypingIndicatorAsync(string channelId, string userId, bool isTyping)
    {
        TypingEvents.Add((channelId, userId, isTyping));
        return Task.CompletedTask;
    }
}

public class DistributedChatHub
{
    public string ServerId { get; }
    private readonly ChannelSequencer _sequencer;
    private readonly ConcurrentDictionary<string, List<IChatClientConnection>> _channelSubscribers = new();
    private readonly ConcurrentDictionary<string, long> _userReadReceipts = new(); // key: "userId:channelId" -> seq
    private readonly List<ChatMessage> _messageHistory = new();
    private readonly object _historyLock = new();

    // Event bus simulating Redis Pub/Sub for cross-server message replication
    public static event Action<string, ChatMessage>? CrossServerMessagePublished;
    public static event Action<string, string, bool>? CrossServerTypingPublished;

    public DistributedChatHub(string serverId, ChannelSequencer sequencer)
    {
        ServerId = serverId;
        _sequencer = sequencer;

        CrossServerMessagePublished += HandleCrossServerMessage;
        CrossServerTypingPublished += HandleCrossServerTyping;
    }

    public void Subscribe(string channelId, IChatClientConnection client)
    {
        _channelSubscribers.AddOrUpdate(
            channelId,
            _ => [client],
            (_, list) => { lock (list) { list.Add(client); } return list; }
        );
    }

    public void Unsubscribe(string channelId, IChatClientConnection client)
    {
        if (_channelSubscribers.TryGetValue(channelId, out var list))
        {
            lock (list)
            {
                list.Remove(client);
            }
        }
    }

    public async Task<ChatMessage> SendMessageAsync(string channelId, string senderId, string content)
    {
        long seq = _sequencer.GetNextSequenceNumber(channelId);
        var message = new ChatMessage(
            MessageId: Guid.NewGuid().ToString("N"),
            ChannelId: channelId,
            SenderId: senderId,
            Content: content,
            SequenceNumber: seq,
            TimestampUtc: DateTime.UtcNow
        );

        // Store to channel history
        lock (_historyLock)
        {
            _messageHistory.Add(message);
        }

        // Broadcast to Redis pub/sub
        CrossServerMessagePublished?.Invoke(channelId, message);

        return await Task.FromResult(message);
    }

    public void SendTyping(string channelId, string userId, bool isTyping)
    {
        CrossServerTypingPublished?.Invoke(channelId, userId, isTyping);
    }

    public void MarkRead(string userId, string channelId, long sequenceNumber)
    {
        _userReadReceipts[$"{userId}:{channelId}"] = sequenceNumber;
    }

    public long GetLastReadSequence(string userId, string channelId)
    {
        return _userReadReceipts.TryGetValue($"{userId}:{channelId}", out var seq) ? seq : 0;
    }

    public IReadOnlyList<ChatMessage> GetMessageHistory(string channelId)
    {
        lock (_historyLock)
        {
            return _messageHistory.Where(m => m.ChannelId == channelId).OrderBy(m => m.SequenceNumber).ToList();
        }
    }

    private void HandleCrossServerMessage(string channelId, ChatMessage message)
    {
        if (_channelSubscribers.TryGetValue(channelId, out var list))
        {
            List<IChatClientConnection> clients;
            lock (list)
            {
                clients = list.ToList();
            }

            foreach (var client in clients)
            {
                _ = client.ReceiveMessageAsync(message);
            }
        }
    }

    private void HandleCrossServerTyping(string channelId, string userId, bool isTyping)
    {
        if (_channelSubscribers.TryGetValue(channelId, out var list))
        {
            List<IChatClientConnection> clients;
            lock (list)
            {
                clients = list.ToList();
            }

            foreach (var client in clients)
            {
                if (client.UserId != userId) // don't echo to self
                {
                    _ = client.ReceiveTypingIndicatorAsync(channelId, userId, isTyping);
                }
            }
        }
    }
}

namespace Day37.ChatSystem;

public static class CombinationSumSolver
{
    /// <summary>
    /// LeetCode #39: Combination Sum (Medium).
    /// Candidates are distinct. Elements can be chosen unlimited number of times.
    /// Time Complexity: O(2^T) where T = target / min(candidates). Space: O(T) stack.
    /// </summary>
    public static IList<IList<int>> CombinationSum(int[] candidates, int target)
    {
        var result = new List<IList<int>>();
        if (candidates == null || candidates.Length == 0) return result;

        Array.Sort(candidates);
        var current = new List<int>();
        BacktrackSum1(candidates, target, 0, current, result);
        return result;
    }

    private static void BacktrackSum1(int[] candidates, int remain, int start, List<int> current, List<IList<int>> result)
    {
        if (remain == 0)
        {
            result.Add(new List<int>(current));
            return;
        }

        for (int i = start; i < candidates.Length; i++)
        {
            if (candidates[i] > remain) break; // Prune: sorted array, no subsequent elements can fit

            current.Add(candidates[i]);
            // Pass 'i' instead of 'i + 1' to allow reuse of current element
            BacktrackSum1(candidates, remain - candidates[i], i, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }

    /// <summary>
    /// LeetCode #40: Combination Sum II (Medium).
    /// Candidates may contain duplicates. Each element can be used AT MOST ONCE.
    /// Result must not contain duplicate combinations.
    /// </summary>
    public static IList<IList<int>> CombinationSum2(int[] candidates, int target)
    {
        var result = new List<IList<int>>();
        if (candidates == null || candidates.Length == 0) return result;

        Array.Sort(candidates);
        var current = new List<int>();
        BacktrackSum2(candidates, target, 0, current, result);
        return result;
    }

    private static void BacktrackSum2(int[] candidates, int remain, int start, List<int> current, List<IList<int>> result)
    {
        if (remain == 0)
        {
            result.Add(new List<int>(current));
            return;
        }

        for (int i = start; i < candidates.Length; i++)
        {
            if (candidates[i] > remain) break; // Prune

            // Skip duplicate sibling branches at the same tree depth
            if (i > start && candidates[i] == candidates[i - 1])
            {
                continue;
            }

            current.Add(candidates[i]);
            // Pass 'i + 1' so each element is only used once
            BacktrackSum2(candidates, remain - candidates[i], i + 1, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }
}

📝 Part 1: Deep-Dive Architectural & Engineering Notes

Deep Dive Notes: High-Throughput Chat Architecture

1. WebSocket Connection Management & Gateway Tier

  • C10M Problem (10 Million Connections):
  • Long-lived persistent TCP connections consume file descriptors and socket buffers.
  • Linux tuning: sysctl -w fs.file-max=2097152, ulimit -n 1048576, tuning tcp_rmem and tcp_wmem buffer sizes (down from 128KB to 4KB per socket idle) allows a single 64GB RAM node to hold 1M idle WebSocket connections.
  • Connection Routing:
  • Load balancers (Envoy, NGINX) use IP hash or consistent hashing for sticky routing, or simple round-robin with WebSocket upgrade handling.
  • Gateway servers maintain an internal mapping: Dictionary<UserId, List<WebSocketSession>>.

2. Message Ordering & Storage Engines

  • Why NTP Wall Clocks Fail:
  • In distributed systems, clock skew between servers can be 50–200ms. If Message B arrives 10ms after Message A but Server 2's clock is 50ms behind Server 1, sorting by timestamp reverses message order.
  • Monotonic Sequencer Solutions:
  • Redis INCR per channel: INCR channel:{id}:seq provides an atomic 64-bit integer.
  • Snowflake IDs: 64-bit IDs containing timestamp prefix + machine ID + local sequence counter (guarantees rough time ordering, but gaps can exist).
  • Storage: Apache Cassandra / ScyllaDB:
  • Primary Key: ((channel_id), sequence_number) WITH CLUSTERING ORDER BY (sequence_number ASC).
  • Partitioning by channel_id groups all messages of a room on the same storage node/replica. Sequential range queries (SELECT * WHERE channel_id = ? AND sequence_number > ? LIMIT 50) hit a contiguous SSTable disk block with sub-millisecond seek latency.

3. LeetCode #39 & #40: Backtracking Combinations Tree

  • State Space:
  • At each node, decide whether to include candidates[i] and recurse on the remainder.
  • Sorting the array beforehand enables immediate termination of the loop (if (candidates[i] > remain) break;), pruning massive subtrees.
  • Combination Sum I vs II:
  • In I, elements can be picked repeatedly $\implies$ next call is Backtrack(i, remain - candidates[i]).
  • In II, elements cannot be reused $\implies$ next call is Backtrack(i + 1, remain - candidates[i]).
  • In II, duplicate elements exist $\implies$ duplicate branches at the same depth are skipped via if (i > start && candidates[i] == candidates[i - 1]) continue;.

Day 37: System Design: High-Throughput Chat System

Architectural Overview

Real-time chat systems (Slack, Discord, WhatsApp) support hundreds of millions of concurrent WebSocket connections, instant messaging, presence tracking, and ordered message histories.

This module implements a distributed real-time chat architecture in .NET 8 featuring:

  • WebSocket Session Management & Scale: Decouples client connections across distributed gateway hubs (DistributedChatHub).
  • Presence Service: Heartbeat ping/pong mechanism tracking user states (Online, Offline, Away) with timeout-based expiration and instant disconnection cleanup.
  • Cross-Server Pub/Sub Replication: Simulates Redis Pub/Sub backplane. When Alice sends a message to Server East, it publishes to the Redis topic; Server West receives the event and pushes to Bob over his active local WebSocket.
  • Monotonic Message Sequencing: Channel-level sequencers assign sequential integer IDs ($1, 2, 3, \dots$), resolving clock-drift race conditions across distributed gateway nodes and guaranteeing total causal order.
  • Read Receipts & Typing Indicators: Tracks last_read_sequence per user per channel and broadcasts transient typing indicators to peer participants without echoing to sender.

💡 Part 3: Senior & Staff-Level Interview Scenarios (10 Questions)

Q1 How do you scale a WebSocket gateway to maintain 10 million concurrent active connections?
▼

Answer:

  1. OS & Kernel Tuning:
  • Increase file descriptor limits (ulimit -n 1048576).
  • Reduce TCP read/write buffer allocations (net.ipv4.tcp_rmem = 4096 87380 4194304, net.ipv4.tcp_wmem). For 1M idle connections, saving 50KB RAM per socket saves 50GB of memory.
  • Enable SO_REUSEPORT and epoll/kqueue event-driven non-blocking I/O (built into .NET Kestrel/Sockets).
  1. Stateless Gateway Tier:
  • Deploy a cluster of WebSocket gateways behind Layer 4 Network Load Balancers (AWS NLB) with TLS termination.
  • Maintain minimal session state in the gateway (only socket handle and user ID).
  1. Session Registry:
  • Store mapping of UserId -> GatewayNodeIP in Redis with TTL heartbeats so other services know which gateway holds a specific user's socket.
Q2 Why is Redis Pub/Sub alone insufficient for chat message persistence, and how do you pair it with a database?
▼

Answer:

Redis Pub/Sub is strictly "fire-and-forget":

  • If a client is temporarily offline, or a network flap occurs between Redis and the gateway, messages published to Redis Pub/Sub are lost forever. Redis does not buffer messages for disconnected pub/sub subscribers.
  • Production Architecture:
  1. The API receives the message.
  2. The message is written first to persistent storage (Cassandra/ScyllaDB) or an append-only commit log (Kafka / Redis Streams).
  3. Then the message is published to Redis Pub/Sub for real-time delivery to online users.
  4. When an offline user reconnects, they query the database for messages where sequence_number > last_received_sequence.
Q3 How do you guarantee strict causal message ordering in a group chat across distributed servers without NTP clock synchronization?
▼

Answer:

NTP clock drift between servers makes timestamps non-monotonic and prone to race conditions.

  • Per-Channel Atomic Sequencers:
  • Each chat room/channel has an independent monotonic sequence counter.
  • Implement using Redis INCR channel:{id}:seq or an atomic database sequence.
  • Every message sent to the channel receives an incremented sequence number ($1, 2, 3, \dots$).
  • Client Synchronization:
  • The client displays messages sorted by sequence_number.
  • If a client receives sequence #5 and previously had #3, it immediately detects a gap (missing #4) and requests the missing message from the server's history endpoint before rendering.
Q4 What is the optimal database schema for storing chat messages in Apache Cassandra / ScyllaDB?
▼

Answer:

Cassandra uses a two-part primary key: Partition Key and Clustering Columns.

CREATE TABLE channel_messages (
    channel_id uuid,
    sequence_id bigint,
    message_id uuid,
    sender_id uuid,
    content text,
    created_at timestamp,
    PRIMARY KEY ((channel_id), sequence_id)
) WITH CLUSTERING ORDER BY (sequence_id ASC);
  • channel_id is the Partition Key: all messages for a given room are stored together on the same cluster replica nodes.
  • sequence_id is the Clustering Column: messages are written to disk sorted contiguously. Fetching the last 50 messages (WHERE channel_id = ? AND sequence_id > ? LIMIT 50) is a fast sequential disk read.
  • For extremely active channels (millions of messages), add a bucket (e.g. (channel_id, year_month)) to prevent giant partitions (> 100MB).
Q5 How do you design a Presence Service (Online/Offline/Last Seen) for 100 million users without overloading databases?
▼

Answer:

  1. Heartbeat & Ephemeral TTL:
  • Clients send a lightweight ping every 30 seconds over the existing WebSocket connection.
  • The gateway writes to Redis: SET user:{id}:presence "ONLINE" EX 60.
  • If a client abruptly disconnects without TCP FIN (e.g., cell tower loss, tunnel), the Redis key expires after 60s, automatically marking them offline.
  1. Fan-out Optimization:
  • Do NOT broadcast presence changes to all friends on every heartbeat.
  • Instead, only broadcast presence transitions (Offline $\to$ Online, Online $\to$ Offline).
  • Use lazy-loading: When user opens a friend list or chat room, query the presence state of only the visible users in that viewport.
Q6 How do you implement "Message Read Receipts" (Single check, Double check, Blue check)?
▼

Answer:

Instead of storing a read receipt record per message per user (which causes massive write amplification in group chats):

  • Store a single monotonic pointer per user per channel: LastReadSequenceNumber.
  CREATE TABLE channel_read_pointers (
      channel_id uuid,
      user_id uuid,
      last_read_sequence bigint,
      PRIMARY KEY (channel_id, user_id)
  );
  • When a user views the chat up to message #500, update their pointer to 500.
  • Any message with sequence_number <= 500 is implicitly read by that user.
  • To render read status in a 1-on-1 chat: If Bob's last_read_sequence >= Alice's message sequence, show blue checkmark.
Q7 How do you implement transient features like "Typing Indicators" without disk writes?
▼

Answer:

Typing indicators are ephemeral, short-lived events that should never be persisted to a relational or NoSQL database.

  1. When user types, client sends a lightweight WebSocket payload: {"action": "typing", "channelId": "123"}.
  2. The gateway server throttles typing events from the client (e.g., at most once every 3 seconds).
  3. The event is pushed directly to Redis Pub/Sub topic channel:typing:{channelId}.
  4. Gateway servers holding connections for other members of that channel forward the typing event to their sockets.
  5. The receiving client shows the typing bubble and starts a 4-second local animation timer; if no refresh arrives, it clears automatically.
Q8 In LeetCode #39 (Combination Sum), why is the recursive call invoked with index `i` rather than `0` or `i + 1`?
▼

Answer:

  • If invoked with 0, the algorithm would explore combinations in different permutations (e.g., both [2, 3] and [3, 2]), resulting in duplicate combinations.
  • If invoked with i + 1, each element could only be used at most once, which fails the requirement that the same number may be chosen an unlimited number of times.
  • By invoking with i, we allow the current candidate to be reused repeatedly while enforcing that future choices are $\ge$ the current candidate index, guaranteeing all generated combinations are strictly sorted and unique.
Q9 In LeetCode #40 (Combination Sum II), why is sorting mandatory before backtracking?
▼

Answer:

  1. Early Pruning: When candidates are sorted, if candidates[i] > remain, we know every candidate after index i is also greater than remain. We can break out of the loop immediately rather than continuing useless iterations.
  2. Duplicate Subtree Elimination: Sorting brings duplicate values together. The condition if (i > start && candidates[i] == candidates[i - 1]) continue; allows us to skip identical sibling branches at the current recursion level, preventing duplicate combinations in the output.
Q10 How do you handle End-to-End Encryption (E2EE) in a distributed chat architecture?
▼

Answer:

In E2EE (e.g. Signal Protocol / WhatsApp):

  1. The server is treated as an untrusted, blind relay. The server only sees ciphertext and cryptographic metadata (pre-keys, identity keys, ratcheting parameters).
  2. Users register public identity keys and one-time prekeys with a Key Distribution Center (KDC).
  3. To start a chat, Alice fetches Bob's prekeys, initiates the Double Ratchet Algorithm, and generates a shared session key.
  4. Alice encrypts the payload locally; the server stores and routes the encrypted blob. Only Bob's private device key can decrypt the message.
  5. Search and media processing must be executed locally on the client device.

using System.Collections.Concurrent;

namespace Day37.ChatSystem;

public enum UserPresenceState
{
    Offline,
    Online,
    Away
}

public record UserPresence(string UserId, UserPresenceState State, DateTime LastSeenUtc);

public class PresenceTracker
{
    private readonly ConcurrentDictionary<string, DateTime> _heartbeats = new();
    private readonly TimeSpan _onlineTimeout;

    public PresenceTracker(TimeSpan? onlineTimeout = null)
    {
        _onlineTimeout = onlineTimeout ?? TimeSpan.FromSeconds(30);
    }

    public void Heartbeat(string userId)
    {
        _heartbeats[userId] = DateTime.UtcNow;
    }

    public void ExplicitDisconnect(string userId)
    {
        _heartbeats.TryRemove(userId, out _);
    }

    public UserPresence GetPresence(string userId)
    {
        if (_heartbeats.TryGetValue(userId, out var lastSeen))
        {
            if (DateTime.UtcNow - lastSeen <= _onlineTimeout)
            {
                return new UserPresence(userId, UserPresenceState.Online, lastSeen);
            }
        }
        return new UserPresence(userId, UserPresenceState.Offline, lastSeen == default ? DateTime.MinValue : lastSeen);
    }
}

public record ChatMessage(
    string MessageId,
    string ChannelId,
    string SenderId,
    string Content,
    long SequenceNumber,
    DateTime TimestampUtc
);

public class ChannelSequencer
{
    private readonly ConcurrentDictionary<string, long> _channelSequences = new();

    public long GetNextSequenceNumber(string channelId)
    {
        return _channelSequences.AddOrUpdate(channelId, 1, (_, current) => current + 1);
    }

    public long GetCurrentSequence(string channelId)
    {
        return _channelSequences.TryGetValue(channelId, out var seq) ? seq : 0;
    }
}

{
    string ConnectionId { get; }
    string UserId { get; }

    Task ReceiveTypingIndicatorAsync(string channelId, string userId, bool isTyping);
}

public class MockWebSocketClient : IChatClientConnection
{
    public string ConnectionId { get; } = Guid.NewGuid().ToString("N");
    public string UserId { get; }
    public List<ChatMessage> ReceivedMessages { get; } = new();
    public List<(string ChannelId, string UserId, bool IsTyping)> TypingEvents { get; } = new();

    public MockWebSocketClient(string userId)

        UserId = userId;

public class DistributedChatHub
{
    public string ServerId { get; }
    private readonly ChannelSequencer _sequencer;
    private readonly ConcurrentDictionary<string, List<IChatClientConnection>> _channelSubscribers = new();
    private readonly ConcurrentDictionary<string, long> _userReadReceipts = new(); // key: "userId:channelId" -> seq
    private readonly List<ChatMessage> _messageHistory = new();
    private readonly object _historyLock = new();

    // Event bus simulating Redis Pub/Sub for cross-server message replication
    public static event Action<string, ChatMessage>? CrossServerMessagePublished;
    public static event Action<string, string, bool>? CrossServerTypingPublished;

    public DistributedChatHub(string serverId, ChannelSequencer sequencer)
    {
        ServerId = serverId;
        _sequencer = sequencer;

        CrossServerMessagePublished += HandleCrossServerMessage;
        CrossServerTypingPublished += HandleCrossServerTyping;
    }

    public void Subscribe(string channelId, IChatClientConnection client)
    {
        _channelSubscribers.AddOrUpdate(
            channelId,
            _ => [client],
            (_, list) => { lock (list) { list.Add(client); } return list; }
        );
    }

    public void Unsubscribe(string channelId, IChatClientConnection client)
    {
        if (_channelSubscribers.TryGetValue(channelId, out var list))
        {
            lock (list)
            {
                list.Remove(client);
            }
        }
    }

    public async Task<ChatMessage> SendMessageAsync(string channelId, string senderId, string content)
    {
        long seq = _sequencer.GetNextSequenceNumber(channelId);
        var message = new ChatMessage(
            MessageId: Guid.NewGuid().ToString("N"),
            ChannelId: channelId,
            SenderId: senderId,
            Content: content,
            SequenceNumber: seq,
            TimestampUtc: DateTime.UtcNow
        );

        // Store to channel history
        lock (_historyLock)
        {
            _messageHistory.Add(message);
        }

        // Broadcast to Redis pub/sub
        CrossServerMessagePublished?.Invoke(channelId, message);

        return await Task.FromResult(message);
    }

    public void SendTyping(string channelId, string userId, bool isTyping)
    {
        CrossServerTypingPublished?.Invoke(channelId, userId, isTyping);
    }

    public void MarkRead(string userId, string channelId, long sequenceNumber)
    {
        _userReadReceipts[$"{userId}:{channelId}"] = sequenceNumber;
    }

    public long GetLastReadSequence(string userId, string channelId)
    {
        return _userReadReceipts.TryGetValue($"{userId}:{channelId}", out var seq) ? seq : 0;
    }

    public IReadOnlyList<ChatMessage> GetMessageHistory(string channelId)
    {
        lock (_historyLock)
        {
            return _messageHistory.Where(m => m.ChannelId == channelId).OrderBy(m => m.SequenceNumber).ToList();
        }
    }

    private void HandleCrossServerMessage(string channelId, ChatMessage message)
    {
        if (_channelSubscribers.TryGetValue(channelId, out var list))
        {
            List<IChatClientConnection> clients;
            lock (list)
            {
                clients = list.ToList();
            }

            foreach (var client in clients)
            {
                _ = client.ReceiveMessageAsync(message);
            }
        }
    }

    private void HandleCrossServerTyping(string channelId, string userId, bool isTyping)
    {
        if (_channelSubscribers.TryGetValue(channelId, out var list))
        {
            List<IChatClientConnection> clients;
            lock (list)
            {
                clients = list.ToList();
            }

            foreach (var client in clients)
            {
                if (client.UserId != userId) // don't echo to self
                {
                    _ = client.ReceiveTypingIndicatorAsync(channelId, userId, isTyping);
                }
            }
        }
    }

namespace Day37.ChatSystem;

public static class CombinationSumSolver
{
    /// <summary>
    /// LeetCode #39: Combination Sum (Medium).
    /// Candidates are distinct. Elements can be chosen unlimited number of times.
    /// Time Complexity: O(2^T) where T = target / min(candidates). Space: O(T) stack.
    /// </summary>
    public static IList<IList<int>> CombinationSum(int[] candidates, int target)
    {
        var result = new List<IList<int>>();
        if (candidates == null || candidates.Length == 0) return result;

        Array.Sort(candidates);
        var current = new List<int>();
        BacktrackSum1(candidates, target, 0, current, result);
        return result;
    }

    private static void BacktrackSum1(int[] candidates, int remain, int start, List<int> current, List<IList<int>> result)
    {
        if (remain == 0)
        {
            result.Add(new List<int>(current));
            return;
        }

        for (int i = start; i < candidates.Length; i++)
        {
            if (candidates[i] > remain) break; // Prune: sorted array, no subsequent elements can fit

            current.Add(candidates[i]);
            // Pass 'i' instead of 'i + 1' to allow reuse of current element
            BacktrackSum1(candidates, remain - candidates[i], i, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }

    /// <summary>
    /// LeetCode #40: Combination Sum II (Medium).
    /// Candidates may contain duplicates. Each element can be used AT MOST ONCE.
    /// Result must not contain duplicate combinations.
    /// </summary>
    public static IList<IList<int>> CombinationSum2(int[] candidates, int target)
    {
        var result = new List<IList<int>>();
        if (candidates == null || candidates.Length == 0) return result;

        Array.Sort(candidates);
        var current = new List<int>();
        BacktrackSum2(candidates, target, 0, current, result);
        return result;
    }

    private static void BacktrackSum2(int[] candidates, int remain, int start, List<int> current, List<IList<int>> result)
    {
        if (remain == 0)
        {
            result.Add(new List<int>(current));
            return;
        }

        for (int i = start; i < candidates.Length; i++)
        {
            if (candidates[i] > remain) break; // Prune

            // Skip duplicate sibling branches at the same tree depth
            if (i > start && candidates[i] == candidates[i - 1])
            {
                continue;
            }

            current.Add(candidates[i]);
            // Pass 'i + 1' so each element is only used once
            BacktrackSum2(candidates, remain - candidates[i], i + 1, current, result);
            current.RemoveAt(current.Count - 1);
        }
    }
}
