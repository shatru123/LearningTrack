Deep Dive Notes: CAP, PACELC & Distributed Consensus

1. CAP Theorem Formalization (Gilbert & Lynch Proof)

  • Consistency ($C$): Linearizability. Every read receives the most recent write or an error. All nodes appear to see operations in a single global, atomic order.
  • Availability ($A$): Every non-failing node returns a non-error response for every received request (no guarantees on data freshness).
  • Partition Tolerance ($P$): The network can drop or delay an arbitrary number of messages between nodes.
  • Theorem: On an asynchronous network where partitions $P$ can occur, a distributed datastore CANNOT achieve both $C$ and $A$. You MUST choose whether to preserve consistency by rejecting requests (CP) or preserve availability by accepting potentially conflicting writes (AP).

2. PACELC Theorem (Daniel Abadi)

CAP only considers behavior when the system is actively partitioned ($P$). However, partitions are relatively rare in healthy datacenters. PACELC explains system behavior during normal (non-partitioned) states:

  • If Partition ($P$):
  • Choose between Availability ($A$) or Consistency ($C$).
  • Else ($E$):
  • Choose between Latency ($L$) or Consistency ($C$).
  • Categorization Matrix:
  • PC/EC (Google Spanner, CockroachDB): Prefers consistency during partitions; prefers multi-datacenter two-phase commit / Paxos during normal operation (paying higher latency for consistency).
  • PA/EL (Apache Cassandra, Amazon DynamoDB, Couchbase): Prefers availability during partitions; returns local replica reads immediately during normal operation (paying consistency for low latency).
  • PC/EL (MongoDB default primary read/write): Refuses writes if primary partitioned (PC), but does fast local primary replication (EL).

3. Tunable Consistency Math ($N, W, R$)

  • By the Pigeonhole Principle:
  • Total nodes = $N$.
  • Number of write nodes = $W$.
  • Number of read nodes = $R$.
  • If $W + R > N$, the set of nodes containing writes and the set of nodes consulted on reads MUST intersect by at least one node:

$$\text{Intersection} = (W + R) - N \ge 1$$

  • The intersecting node holds the latest version $V_{\max}$.
  • Read Repair vs Anti-Entropy:
  • Read Repair: Opportunistic sync during client reads. When a read quorum returns mismatched versions, the coordinator writes the newest version back to the stale nodes.
  • Anti-Entropy: Background process using Merkle trees to compare replica ranges and stream differences without client intervention.

Architectural Overview

Distributed systems running on unreliable networks must navigate fundamental trade-offs between consistency, availability, latency, and fault tolerance.

This module implements and proves distributed consensus and quorum models in .NET 8:

  • CAP Theorem (Brewer):
  • In the presence of a network Partition ($P$), a distributed system must choose between Consistency ($C$) or Availability ($A$).
  • PACELC Theorem (Abadi):
  • Extends CAP to normal operational states:
  • If Partition ($P$): choose between Availability ($A$) and Consistency ($C$).
  • Else ($E$): choose between Latency ($L$) and Consistency ($C$).
  • Examples: Spanner (PC/EC), Cassandra/DynamoDB (PA/EL), MongoDB (PC/EC or PA/EL depending on read concern).
  • Tunable Quorums ($N, W, R$):
  • $N$: Replication factor (e.g. 3 or 5 replicas).
  • $W$: Write quorum (number of nodes that must acknowledge a write before success).
  • $R$: Read quorum (number of nodes contacted during read).
  • Strong Consistency (Pigeonhole Principle): When $R + W > N$, the read quorum and write quorum are mathematically guaranteed to overlap by at least one node, ensuring the client always observes the latest state.
  • Eventual Consistency: When $R + W \le N$, reads may return stale data.
  • Conflict Resolution & Read Repair: Resolves conflicting replica versions via Last-Write-Wins (LWW) and automatically repairs out-of-date replica nodes asynchronously.

10 Senior / Staff-Level Interview Questions with In-Depth Answers:
Q1 What is the formal difference between CAP Consistency and ACID Consistency?
▼

Answer:

They describe completely different properties despite sharing the same word "Consistency":

  • CAP Consistency ($C$): Means Linearizability / Single-copy consistency. It is a distributed systems property ensuring that once a write completes, all subsequent reads across any node in the cluster will observe that write or a later one.
  • ACID Consistency ($C$): Means Application Invariant Preservation. It is a database transaction property ensuring state transitions obey all domain business rules, schema constraints, foreign keys, and unique indices (e.g. account balances cannot drop below zero).
Q2 Why is "CA" (Consistent + Available without Partition Tolerance) an impossible architectural choice in distributed systems?
▼

Answer:

A network partition is not a design choice; it is an inevitable physical reality of distributed infrastructure (cables cut, switch failures, cross-datacenter fiber cuts, GC pauses causing heartbeat timeouts).

  • If a partition occurs, nodes in partition group 1 cannot communicate with nodes in partition group 2.
  • If a client issues a write to group 1:
  • If group 1 accepts the write, group 2 becomes stale (sacrificing Consistency $C$).
  • If group 1 rejects the write or blocks forever waiting for group 2, the system stops serving requests (sacrificing Availability $A$).
  • Therefore, every real distributed system MUST be partition-tolerant ($P$). The only choice is between CP and AP.
Q3 Explain PACELC theorem and give real-world database examples for each quadrant.
▼

Answer:

PACELC states: If Partition ($P$), trade off Availability ($A$) vs Consistency ($C$); Else (normal non-partitioned operation), trade off Latency ($L$) vs Consistency ($C$).

  • PC/EC (Google Spanner, CockroachDB): Prefers consistency during partitions (fails un-elected nodes); prefers strong consistency during normal operations (requires multi-region Paxos/Raft consensus before acknowledging writes, incurring network roundtrip latency).
  • PA/EL (Apache Cassandra, Amazon DynamoDB, Couchbase): Prefers availability during partitions (accepts writes on any node); prefers ultra-low latency during normal operation (writes to local node and replicates asynchronously, risking stale reads).
  • PC/EL (MongoDB with default settings): Master node rejects writes if isolated from replica majority (PC), but does fast local replication with eventual consistency for secondaries (EL).
Q4 Prove mathematically why $R + W > N$ guarantees strong consistency (Linearizability) in quorum systems.
▼

Answer:

Let $N$ be the total number of replica nodes for a key.

  • A write is acknowledged when written to a set of $W$ nodes: $S_w \subseteq \text{Nodes}, |S_w| = W$.
  • A read contacts a set of $R$ nodes: $S_r \subseteq \text{Nodes}, |S_r| = R$.
  • By the Pigeonhole Principle:

$$|S_w \cap S_r| = |S_w| + |S_r| - |S_w \cup S_r| \ge W + R - N$$

  • Since $W + R > N$, we have:

$$|S_w \cap S_r| \ge 1$$

  • This guarantees the read set and write set intersect by at least one common replica node. Because that common node has the latest write (tracked via version or timestamp), the read coordinator receives the latest version and returns it to the client.
Q5 What is "Read Repair" and how does it maintain eventual consistency in leaderless distributed databases?
▼

Answer:

In leaderless systems (Cassandra, Dynamo):

  1. A client initiates a read with quorum $R=2$ on a cluster with $N=3$.
  2. Node 1 returns {value: "Active", version: 5}.
  3. Node 2 returns {value: "Pending", version: 4}.
  4. The coordinator notices a version discrepancy. It returns version 5 ("Active") to the client.
  5. In the background (asynchronously), the coordinator sends an update to Node 2 with version 5.
  • Over time, frequently read data is self-healing, reducing entropy without expensive full-cluster scans.
Q6 What are the risks of using Last-Write-Wins (LWW) conflict resolution, and what is the alternative?
▼

Answer:

  • Risks of LWW:
  • Relies on physical wall-clock timestamps (NTP).
  • Clock skew between servers can cause a write that occurred physically earlier to overwrite a write that occurred physically later if Server A's clock is running 50ms fast.
  • Concurrent writes at the same millisecond silently drop one update, leading to data loss.
  • Alternatives:
  • Vector Clocks / Version Vectors: Track causal history per node ([NodeA: 2, NodeB: 1]). If vectors do not dominate, a true conflict is detected and surfaced to the application (or resolved via CRDTs).
  • Conflict-Free Replicated Data Types (CRDTs): Mathematically structured data types (e.g. PN-Counters, Observed-Remove Sets) whose merge operations are associative, commutative, and idempotent ($A \cup B = B \cup A$).
Q7 In LeetCode #79 (Word Search), why is in-place grid mutation (`board[r][c] = '#'`) superior to maintaining a `HashSet<(int, int)>` or `bool[][]`?
▼

Answer:

  • A HashSet<(int, int)> allocates heap memory for every visited cell, causes boxing, and incurs hash table lookup overhead on every step.
  • A separate bool[rows][cols] matrix requires $O(M \times N)$ auxiliary memory allocation per test case or expensive zeroing resets.
  • By mutating the character directly in board[r][c] = '#' and restoring it on backtrack (board[r][c] = original), the algorithm uses $O(1)$ auxiliary memory and stays completely cache-friendly within the L1 data cache.
Q8 What is the time complexity of Word Search on an $M \times N$ board for a word of length $L$?
▼

Answer:

  • There are $M \times N$ possible starting positions on the board.
  • From each cell, the DFS explores in 4 directions. However, since we cannot visit the cell we just came from, subsequent steps have at most 3 branches.
  • For a word of length $L$, the maximum depth of the recursion tree is $L$.
  • Total worst-case time complexity: $O(M \times N \times 3^L)$.
  • Space complexity: $O(L)$ for the recursion stack depth.
Q9 In LeetCode #17 (Letter Combinations of a Phone Number), what is the maximum number of combinations generated for an input of length $N$?
▼

Answer:

  • Digits 7 and 9 map to 4 letters each ('pqrs', 'wxyz'); digits 2, 3, 4, 5, 6, 8 map to 3 letters each.
  • In the worst case where all $N$ digits are 7 or 9, the total number of combinations is $4^N$.
  • Copying each combination of length $N$ into the output list takes $O(N)$ operations.
  • Total time complexity: $O(4^N \times N)$.
  • Space complexity: $O(N)$ auxiliary stack space.
Q10 How does Google Spanner claim to achieve "both Consistency and Availability" despite the CAP theorem?
▼

Answer:

Spanner does not violate the CAP theorem; it is technically a CP system.

  • If a network partition isolates a replica from the Paxos quorum, Spanner chooses Consistency over Availability for that partition.
  • However, Google minimizes partitions to near zero through:
  1. Private multi-redundant global fiber optic backbone with automated rerouting.
  2. TrueTime API: Uses synchronized atomic clocks and GPS receivers in every datacenter, guaranteeing clock uncertainty $\epsilon < 7\text{ms}$.
  3. By waiting out the small uncertainty window $2\epsilon$ before committing transactions, Spanner achieves external consistency (strict serializability) globally with five-nines (99.999%) availability in practice, appearing as "CA" to external users.

namespace Day39.DistributedConsensus;

public class QuorumUnavailableException : Exception
{
    public QuorumUnavailableException(string message) : base(message) { }
}

public record ReplicaValue<T>(T Value, long Version, long TimestampTicks);

public class ReplicaNode<T>
{
    public string NodeId { get; }
    public bool IsPartitioned { get; set; } = false;
    private readonly Dictionary<string, ReplicaValue<T>> _store = new();
    private readonly object _lock = new();

    public ReplicaNode(string nodeId)
    {
        NodeId = nodeId;
    }

    public bool TryWrite(string key, T value, long version, long timestampTicks)
    {
        if (IsPartitioned) return false;

        lock (_lock)
        {
            if (!_store.TryGetValue(key, out var current) || version >= current.Version)
            {
                _store[key] = new ReplicaValue<T>(value, version, timestampTicks);
                return true;
            }
            return false;
        }
    }

    public bool TryRead(string key, out ReplicaValue<T>? value)
    {
        value = null;
        if (IsPartitioned) return false;

        lock (_lock)
        {
            if (_store.TryGetValue(key, out var val))
            {
                value = val;
                return true;
            }
            return true; // Read succeeded, value is null
        }
    }
}

public class QuorumCluster<T>
{
    public int N => Nodes.Count;
    public int W { get; }
    public int R { get; }
    public IReadOnlyList<ReplicaNode<T>> Nodes { get; }
    public bool IsStronglyConsistent => (R + W) > N;

    private long _globalVersion = 0;

    public QuorumCluster(int nodeCount, int writeQuorum, int readQuorum)
    {
        if (writeQuorum > nodeCount || readQuorum > nodeCount)
            throw new ArgumentException("Quorum cannot exceed total node count");

        W = writeQuorum;
        R = readQuorum;

        var list = new List<ReplicaNode<T>>();
        for (int i = 1; i <= nodeCount; i++)
        {
            list.Add(new ReplicaNode<T>($"node-{i}"));
        }
        Nodes = list;
    }

    public async Task<bool> WriteAsync(string key, T value)
    {
        long version = Interlocked.Increment(ref _globalVersion);
        long timestamp = DateTime.UtcNow.Ticks;

        int acks = 0;
        foreach (var node in Nodes)
        {
            if (node.TryWrite(key, value, version, timestamp))
            {
                acks++;
            }
        }

        if (acks < W)
        {
            throw new QuorumUnavailableException(
                $"Write quorum failed: Required {W} acks but received {acks} from {N} nodes.");
        }

        return await Task.FromResult(true);
    }

    public async Task<T?> ReadAsync(string key, bool triggerReadRepair = true)
    {
        var responses = new List<(ReplicaNode<T> Node, ReplicaValue<T>? Value)>();

        foreach (var node in Nodes)
        {
            if (node.TryRead(key, out var val))
            {
                responses.Add((node, val));
            }
        }

        if (responses.Count < R)
        {
            throw new QuorumUnavailableException(
                $"Read quorum failed: Required {R} responses but received {responses.Count} from {N} nodes.");
        }

        // Filter valid non-null values
        var validValues = responses
            .Where(r => r.Value != null)
            .Select(r => r.Value!)
            .ToList();

        if (validValues.Count == 0)
        {
            return default;
        }

        // Conflict resolution: highest version and latest timestamp (Last-Write-Wins)
        var latest = validValues
            .OrderByDescending(v => v.Version)
            .ThenByDescending(v => v.TimestampTicks)
            .First();

        // Read Repair: asynchronously update any node that returned stale data
        if (triggerReadRepair)
        {
            foreach (var (node, val) in responses)
            {
                if (val == null || val.Version < latest.Version)
                {
                    node.TryWrite(key, latest.Value, latest.Version, latest.TimestampTicks);
                }
            }
        }

        return await Task.FromResult(latest.Value);
    }
}

using System.Text;

namespace Day39.DistributedConsensus;

public static class WordSearchAndPhoneSolver
{
    #region LeetCode #79: Word Search

    /// <summary>
    /// LeetCode #79: Word Search (Medium).
    /// DFS Backtracking on 2D character grid with in-place cell marking.
    /// Time Complexity: O(M * N * 3^L) where L = word.Length. Space: O(L) recursion stack.
    /// </summary>
    public static bool Exist(char[][] board, string word)
    {
        if (board == null || board.Length == 0 || string.IsNullOrEmpty(word))
            return false;

        int rows = board.Length;
        int cols = board[0].Length;

        for (int r = 0; r < rows; r++)
        {
            for (int c = 0; c < cols; c++)
            {
                if (board[r][c] == word[0] && DfsWordSearch(board, word, r, c, 0))
                {
                    return true;
                }
            }
        }

        return false;
    }

    private static bool DfsWordSearch(char[][] board, string word, int r, int c, int index)
    {
        if (index == word.Length)
        {
            return true;
        }

        if (r < 0 || r >= board.Length || c < 0 || c >= board[0].Length || board[r][c] != word[index])
        {
            return false;
        }

        char original = board[r][c];
        board[r][c] = '#'; // Mark cell as visited in-place

        bool found = DfsWordSearch(board, word, r + 1, c, index + 1) ||
                     DfsWordSearch(board, word, r - 1, c, index + 1) ||
                     DfsWordSearch(board, word, r, c + 1, index + 1) ||
                     DfsWordSearch(board, word, r, c - 1, index + 1);

        board[r][c] = original; // Backtrack / unmark
        return found;
    }

    #endregion

    #region LeetCode #17: Letter Combinations of a Phone Number

    private static readonly string[] DigitMap =
    [
        "",     // 0
        "",     // 1
        "abc",  // 2
        "def",  // 3
        "ghi",  // 4
        "jkl",  // 5
        "mno",  // 6
        "pqrs", // 7
        "tuv",  // 8
        "wxyz"  // 9
    ];

    /// <summary>
    /// LeetCode #17: Letter Combinations of a Phone Number (Medium).
    /// Time Complexity: O(4^N * N), Space Complexity: O(N) stack.
    /// </summary>
    public static IList<string> LetterCombinations(string digits)
    {
        var result = new List<string>();
        if (string.IsNullOrEmpty(digits)) return result;

        var current = new StringBuilder();
        BacktrackLetters(digits, 0, current, result);
        return result;
    }

    private static void BacktrackLetters(string digits, int index, StringBuilder current, List<string> result)
    {
        if (index == digits.Length)
        {
            result.Add(current.ToString());
            return;
        }

        int digit = digits[index] - '0';
        if (digit < 2 || digit > 9) return;

        string letters = DigitMap[digit];
        foreach (char ch in letters)
        {
            current.Append(ch);
            BacktrackLetters(digits, index + 1, current, result);
            current.Length--; // Backtrack
        }
    }

    #endregion
}

📝 Part 1: Deep-Dive Architectural & Engineering Notes

Deep Dive Notes: CAP, PACELC & Distributed Consensus

1. CAP Theorem Formalization (Gilbert & Lynch Proof)

  • Consistency ($C$): Linearizability. Every read receives the most recent write or an error. All nodes appear to see operations in a single global, atomic order.
  • Availability ($A$): Every non-failing node returns a non-error response for every received request (no guarantees on data freshness).
  • Partition Tolerance ($P$): The network can drop or delay an arbitrary number of messages between nodes.
  • Theorem: On an asynchronous network where partitions $P$ can occur, a distributed datastore CANNOT achieve both $C$ and $A$. You MUST choose whether to preserve consistency by rejecting requests (CP) or preserve availability by accepting potentially conflicting writes (AP).

2. PACELC Theorem (Daniel Abadi)

CAP only considers behavior when the system is actively partitioned ($P$). However, partitions are relatively rare in healthy datacenters. PACELC explains system behavior during normal (non-partitioned) states:

  • If Partition ($P$):
  • Choose between Availability ($A$) or Consistency ($C$).
  • Else ($E$):
  • Choose between Latency ($L$) or Consistency ($C$).
  • Categorization Matrix:
  • PC/EC (Google Spanner, CockroachDB): Prefers consistency during partitions; prefers multi-datacenter two-phase commit / Paxos during normal operation (paying higher latency for consistency).
  • PA/EL (Apache Cassandra, Amazon DynamoDB, Couchbase): Prefers availability during partitions; returns local replica reads immediately during normal operation (paying consistency for low latency).
  • PC/EL (MongoDB default primary read/write): Refuses writes if primary partitioned (PC), but does fast local primary replication (EL).

3. Tunable Consistency Math ($N, W, R$)

  • By the Pigeonhole Principle:
  • Total nodes = $N$.
  • Number of write nodes = $W$.
  • Number of read nodes = $R$.
  • If $W + R > N$, the set of nodes containing writes and the set of nodes consulted on reads MUST intersect by at least one node:

$$\text{Intersection} = (W + R) - N \ge 1$$

  • The intersecting node holds the latest version $V_{\max}$.
  • Read Repair vs Anti-Entropy:
  • Read Repair: Opportunistic sync during client reads. When a read quorum returns mismatched versions, the coordinator writes the newest version back to the stale nodes.
  • Anti-Entropy: Background process using Merkle trees to compare replica ranges and stream differences without client intervention.

Day 39: CAP Theorem & PACELC in Practice

Architectural Overview

Distributed systems running on unreliable networks must navigate fundamental trade-offs between consistency, availability, latency, and fault tolerance.

This module implements and proves distributed consensus and quorum models in .NET 8:

  • CAP Theorem (Brewer):
  • In the presence of a network Partition ($P$), a distributed system must choose between Consistency ($C$) or Availability ($A$).
  • PACELC Theorem (Abadi):
  • Extends CAP to normal operational states:
  • If Partition ($P$): choose between Availability ($A$) and Consistency ($C$).
  • Else ($E$): choose between Latency ($L$) and Consistency ($C$).
  • Examples: Spanner (PC/EC), Cassandra/DynamoDB (PA/EL), MongoDB (PC/EC or PA/EL depending on read concern).
  • Tunable Quorums ($N, W, R$):
  • $N$: Replication factor (e.g. 3 or 5 replicas).
  • $W$: Write quorum (number of nodes that must acknowledge a write before success).
  • $R$: Read quorum (number of nodes contacted during read).
  • Strong Consistency (Pigeonhole Principle): When $R + W > N$, the read quorum and write quorum are mathematically guaranteed to overlap by at least one node, ensuring the client always observes the latest state.
  • Eventual Consistency: When $R + W \le N$, reads may return stale data.
  • Conflict Resolution & Read Repair: Resolves conflicting replica versions via Last-Write-Wins (LWW) and automatically repairs out-of-date replica nodes asynchronously.

💡 Part 3: Senior & Staff-Level Interview Scenarios (10 Questions)

Q1 What is the formal difference between CAP Consistency and ACID Consistency?
▼

Answer:

They describe completely different properties despite sharing the same word "Consistency":

  • CAP Consistency ($C$): Means Linearizability / Single-copy consistency. It is a distributed systems property ensuring that once a write completes, all subsequent reads across any node in the cluster will observe that write or a later one.
  • ACID Consistency ($C$): Means Application Invariant Preservation. It is a database transaction property ensuring state transitions obey all domain business rules, schema constraints, foreign keys, and unique indices (e.g. account balances cannot drop below zero).
Q2 Why is "CA" (Consistent + Available without Partition Tolerance) an impossible architectural choice in distributed systems?
▼

Answer:

A network partition is not a design choice; it is an inevitable physical reality of distributed infrastructure (cables cut, switch failures, cross-datacenter fiber cuts, GC pauses causing heartbeat timeouts).

  • If a partition occurs, nodes in partition group 1 cannot communicate with nodes in partition group 2.
  • If a client issues a write to group 1:
  • If group 1 accepts the write, group 2 becomes stale (sacrificing Consistency $C$).
  • If group 1 rejects the write or blocks forever waiting for group 2, the system stops serving requests (sacrificing Availability $A$).
  • Therefore, every real distributed system MUST be partition-tolerant ($P$). The only choice is between CP and AP.
Q3 Explain PACELC theorem and give real-world database examples for each quadrant.
▼

Answer:

PACELC states: If Partition ($P$), trade off Availability ($A$) vs Consistency ($C$); Else (normal non-partitioned operation), trade off Latency ($L$) vs Consistency ($C$).

  • PC/EC (Google Spanner, CockroachDB): Prefers consistency during partitions (fails un-elected nodes); prefers strong consistency during normal operations (requires multi-region Paxos/Raft consensus before acknowledging writes, incurring network roundtrip latency).
  • PA/EL (Apache Cassandra, Amazon DynamoDB, Couchbase): Prefers availability during partitions (accepts writes on any node); prefers ultra-low latency during normal operation (writes to local node and replicates asynchronously, risking stale reads).
  • PC/EL (MongoDB with default settings): Master node rejects writes if isolated from replica majority (PC), but does fast local replication with eventual consistency for secondaries (EL).
Q4 Prove mathematically why $R + W > N$ guarantees strong consistency (Linearizability) in quorum systems.
▼

Answer:

Let $N$ be the total number of replica nodes for a key.

  • A write is acknowledged when written to a set of $W$ nodes: $S_w \subseteq \text{Nodes}, |S_w| = W$.
  • A read contacts a set of $R$ nodes: $S_r \subseteq \text{Nodes}, |S_r| = R$.
  • By the Pigeonhole Principle:

$$|S_w \cap S_r| = |S_w| + |S_r| - |S_w \cup S_r| \ge W + R - N$$

  • Since $W + R > N$, we have:

$$|S_w \cap S_r| \ge 1$$

  • This guarantees the read set and write set intersect by at least one common replica node. Because that common node has the latest write (tracked via version or timestamp), the read coordinator receives the latest version and returns it to the client.
Q5 What is "Read Repair" and how does it maintain eventual consistency in leaderless distributed databases?
▼

Answer:

In leaderless systems (Cassandra, Dynamo):

  1. A client initiates a read with quorum $R=2$ on a cluster with $N=3$.
  2. Node 1 returns {value: "Active", version: 5}.
  3. Node 2 returns {value: "Pending", version: 4}.
  4. The coordinator notices a version discrepancy. It returns version 5 ("Active") to the client.
  5. In the background (asynchronously), the coordinator sends an update to Node 2 with version 5.
  • Over time, frequently read data is self-healing, reducing entropy without expensive full-cluster scans.
Q6 What are the risks of using Last-Write-Wins (LWW) conflict resolution, and what is the alternative?
▼

Answer:

  • Risks of LWW:
  • Relies on physical wall-clock timestamps (NTP).
  • Clock skew between servers can cause a write that occurred physically earlier to overwrite a write that occurred physically later if Server A's clock is running 50ms fast.
  • Concurrent writes at the same millisecond silently drop one update, leading to data loss.
  • Alternatives:
  • Vector Clocks / Version Vectors: Track causal history per node ([NodeA: 2, NodeB: 1]). If vectors do not dominate, a true conflict is detected and surfaced to the application (or resolved via CRDTs).
  • Conflict-Free Replicated Data Types (CRDTs): Mathematically structured data types (e.g. PN-Counters, Observed-Remove Sets) whose merge operations are associative, commutative, and idempotent ($A \cup B = B \cup A$).
Q7 In LeetCode #79 (Word Search), why is in-place grid mutation (`board[r][c] = '#'`) superior to maintaining a `HashSet<(int, int)>` or `bool[][]`?
▼

Answer:

  • A HashSet<(int, int)> allocates heap memory for every visited cell, causes boxing, and incurs hash table lookup overhead on every step.
  • A separate bool[rows][cols] matrix requires $O(M \times N)$ auxiliary memory allocation per test case or expensive zeroing resets.
  • By mutating the character directly in board[r][c] = '#' and restoring it on backtrack (board[r][c] = original), the algorithm uses $O(1)$ auxiliary memory and stays completely cache-friendly within the L1 data cache.
Q8 What is the time complexity of Word Search on an $M \times N$ board for a word of length $L$?
▼

Answer:

  • There are $M \times N$ possible starting positions on the board.
  • From each cell, the DFS explores in 4 directions. However, since we cannot visit the cell we just came from, subsequent steps have at most 3 branches.
  • For a word of length $L$, the maximum depth of the recursion tree is $L$.
  • Total worst-case time complexity: $O(M \times N \times 3^L)$.
  • Space complexity: $O(L)$ for the recursion stack depth.
Q9 In LeetCode #17 (Letter Combinations of a Phone Number), what is the maximum number of combinations generated for an input of length $N$?
▼

Answer:

  • Digits 7 and 9 map to 4 letters each ('pqrs', 'wxyz'); digits 2, 3, 4, 5, 6, 8 map to 3 letters each.
  • In the worst case where all $N$ digits are 7 or 9, the total number of combinations is $4^N$.
  • Copying each combination of length $N$ into the output list takes $O(N)$ operations.
  • Total time complexity: $O(4^N \times N)$.
  • Space complexity: $O(N)$ auxiliary stack space.
Q10 How does Google Spanner claim to achieve "both Consistency and Availability" despite the CAP theorem?
▼

Answer:

Spanner does not violate the CAP theorem; it is technically a CP system.

  • If a network partition isolates a replica from the Paxos quorum, Spanner chooses Consistency over Availability for that partition.
  • However, Google minimizes partitions to near zero through:
  1. Private multi-redundant global fiber optic backbone with automated rerouting.
  2. TrueTime API: Uses synchronized atomic clocks and GPS receivers in every datacenter, guaranteeing clock uncertainty $\epsilon < 7\text{ms}$.
  3. By waiting out the small uncertainty window $2\epsilon$ before committing transactions, Spanner achieves external consistency (strict serializability) globally with five-nines (99.999%) availability in practice, appearing as "CA" to external users.

namespace Day39.DistributedConsensus;

public class QuorumUnavailableException : Exception
{
    public QuorumUnavailableException(string message) : base(message) { }
}

public record ReplicaValue<T>(T Value, long Version, long TimestampTicks);

public class ReplicaNode<T>
{
    public string NodeId { get; }
    public bool IsPartitioned { get; set; } = false;
    private readonly Dictionary<string, ReplicaValue<T>> _store = new();
    private readonly object _lock = new();

    public ReplicaNode(string nodeId)
    {
        NodeId = nodeId;
    }

    public bool TryWrite(string key, T value, long version, long timestampTicks)
    {
        if (IsPartitioned) return false;

        lock (_lock)
        {
            if (!_store.TryGetValue(key, out var current) || version >= current.Version)
            {
                _store[key] = new ReplicaValue<T>(value, version, timestampTicks);
                return true;
            }
            return false;
        }
    }

    public bool TryRead(string key, out ReplicaValue<T>? value)
    {
        value = null;
        if (IsPartitioned) return false;

        lock (_lock)
        {
            if (_store.TryGetValue(key, out var val))
            {
                value = val;
                return true;
            }
            return true; // Read succeeded, value is null
        }
    }
}

public class QuorumCluster<T>
{
    public int N => Nodes.Count;
    public int W { get; }
    public int R { get; }
    public IReadOnlyList<ReplicaNode<T>> Nodes { get; }
    public bool IsStronglyConsistent => (R + W) > N;

    private long _globalVersion = 0;

    public QuorumCluster(int nodeCount, int writeQuorum, int readQuorum)
    {
        if (writeQuorum > nodeCount || readQuorum > nodeCount)
            throw new ArgumentException("Quorum cannot exceed total node count");

        W = writeQuorum;
        R = readQuorum;

        var list = new List<ReplicaNode<T>>();
        for (int i = 1; i <= nodeCount; i++)
        {
            list.Add(new ReplicaNode<T>($"node-{i}"));
        }
        Nodes = list;
    }

    public async Task<bool> WriteAsync(string key, T value)
    {
        long version = Interlocked.Increment(ref _globalVersion);
        long timestamp = DateTime.UtcNow.Ticks;

        int acks = 0;
        foreach (var node in Nodes)
        {
            if (node.TryWrite(key, value, version, timestamp))
            {
                acks++;
            }
        }

        if (acks < W)
        {
            throw new QuorumUnavailableException(
                $"Write quorum failed: Required {W} acks but received {acks} from {N} nodes.");
        }

        return await Task.FromResult(true);
    }

    public async Task<T?> ReadAsync(string key, bool triggerReadRepair = true)
    {
        var responses = new List<(ReplicaNode<T> Node, ReplicaValue<T>? Value)>();

        foreach (var node in Nodes)
        {
            if (node.TryRead(key, out var val))
            {
                responses.Add((node, val));
            }
        }

        if (responses.Count < R)
        {
            throw new QuorumUnavailableException(
                $"Read quorum failed: Required {R} responses but received {responses.Count} from {N} nodes.");
        }

        // Filter valid non-null values
        var validValues = responses
            .Where(r => r.Value != null)
            .Select(r => r.Value!)
            .ToList();

        if (validValues.Count == 0)
        {
            return default;
        }

        // Conflict resolution: highest version and latest timestamp (Last-Write-Wins)
        var latest = validValues
            .OrderByDescending(v => v.Version)
            .ThenByDescending(v => v.TimestampTicks)
            .First();

        // Read Repair: asynchronously update any node that returned stale data
        if (triggerReadRepair)
        {
            foreach (var (node, val) in responses)
            {
                if (val == null || val.Version < latest.Version)
                {
                    node.TryWrite(key, latest.Value, latest.Version, latest.TimestampTicks);
                }
            }
        }

        return await Task.FromResult(latest.Value);
    }
}

using System.Text;

namespace Day39.DistributedConsensus;

public static class WordSearchAndPhoneSolver
{
    #region LeetCode #79: Word Search

    /// <summary>
    /// LeetCode #79: Word Search (Medium).
    /// DFS Backtracking on 2D character grid with in-place cell marking.
    /// Time Complexity: O(M * N * 3^L) where L = word.Length. Space: O(L) recursion stack.
    /// </summary>
    public static bool Exist(char[][] board, string word)
    {
        if (board == null || board.Length == 0 || string.IsNullOrEmpty(word))
            return false;

        int rows = board.Length;
        int cols = board[0].Length;

        for (int r = 0; r < rows; r++)
        {
            for (int c = 0; c < cols; c++)
            {
                if (board[r][c] == word[0] && DfsWordSearch(board, word, r, c, 0))
                {
                    return true;
                }
            }
        }

        return false;
    }

    private static bool DfsWordSearch(char[][] board, string word, int r, int c, int index)
    {
        if (index == word.Length)
        {
            return true;
        }

        if (r < 0 || r >= board.Length || c < 0 || c >= board[0].Length || board[r][c] != word[index])
        {
            return false;
        }

        char original = board[r][c];
        board[r][c] = '#'; // Mark cell as visited in-place

        bool found = DfsWordSearch(board, word, r + 1, c, index + 1) ||
                     DfsWordSearch(board, word, r - 1, c, index + 1) ||
                     DfsWordSearch(board, word, r, c + 1, index + 1) ||
                     DfsWordSearch(board, word, r, c - 1, index + 1);

        board[r][c] = original; // Backtrack / unmark
        return found;
    }

    #endregion

    #region LeetCode #17: Letter Combinations of a Phone Number

    private static readonly string[] DigitMap =
    [
        "",     // 0
        "",     // 1
        "abc",  // 2
        "def",  // 3
        "ghi",  // 4
        "jkl",  // 5
        "mno",  // 6
        "pqrs", // 7
        "tuv",  // 8
        "wxyz"  // 9
    ];

    /// <summary>
    /// LeetCode #17: Letter Combinations of a Phone Number (Medium).
    /// Time Complexity: O(4^N * N), Space Complexity: O(N) stack.
    /// </summary>
    public static IList<string> LetterCombinations(string digits)
    {
        var result = new List<string>();
        if (string.IsNullOrEmpty(digits)) return result;

        var current = new StringBuilder();
        BacktrackLetters(digits, 0, current, result);
        return result;
    }

    private static void BacktrackLetters(string digits, int index, StringBuilder current, List<string> result)
    {
        if (index == digits.Length)
        {
            result.Add(current.ToString());
            return;
        }

        int digit = digits[index] - '0';
        if (digit < 2 || digit > 9) return;

        string letters = DigitMap[digit];
        foreach (char ch in letters)
        {
            current.Append(ch);
            BacktrackLetters(digits, index + 1, current, result);
            current.Length--; // Backtrack
        }
    }

    #endregion
}
