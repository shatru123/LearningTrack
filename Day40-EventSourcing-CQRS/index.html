Deep Dive Notes: Event Sourcing & CQRS Pattern

1. Event Sourcing Core Principles

  • State as a Left Fold:
  • In CRUD, UPDATE accounts SET balance = 150 WHERE id = 1 destroys the history of how the balance became 150.
  • In Event Sourcing, state is derived:

state = events.Aggregate(initial, (acc, evt) => acc.Apply(evt))

  • The Event Store is the single source of truth.
  • Optimistic Concurrency Control (OCC):
  • Stream table schema: (stream_id, version, payload, timestamp) with unique constraint on (stream_id, version).
  • When appending, specify ExpectedVersion. If another process appended version 3 first, the unique constraint or check fails, aborting the write and forcing the caller to reload and re-evaluate business logic.

2. CQRS (Command Query Responsibility Segregation)

  • Asymmetric Scaling:
  • Most business systems have an 80:20 or 99:1 read-to-write ratio.
  • Write Model: Optimized for transactional integrity, validation, and zero locks (aggregates write to append-only tables).
  • Read Model: Optimized for queries (denormalized relational tables, Elasticsearch indices, or Redis hashes).
  • Handling Eventual Consistency in UI:
  • Because read projections update asynchronously after the event is committed, a read immediately following a write might not show the new item.
  • Mitigation Strategies:
  1. Optimistic UI update: The client updates local UI state immediately.
  2. Read-your-own-writes session token: Query model waits until projected version $\ge$ token version before responding.

3. LeetCode #131: Palindrome Partitioning DP Optimization

  • A naive check reverses every substring, taking $O(K)$ time per substring. With $2^N$ possible partition combinations, this wastes CPU cycles.
  • DP Table Formulation:
  • Let dp[i, j] represent whether s[i..j] is a palindrome.
  • Base case: dp[i, i] = true for all $i$.
  • For substrings of length $L \ge 2$:

$$\text{dp}[i, j] = (s[i] == s[j]) \land (L == 2 \lor \text{dp}[i+1, j-1])$$

  • Filling the DP table takes $O(N^2)$ time once up front. Then, each palindrome check in the backtracking loop is a lightning-fast $O(1)$ table lookup.

Day 40: Event Sourcing & CQRS Foundations

Architectural Overview

Traditional CRUD applications mutate state in place, overwriting historical data and making auditing, time-travel debugging, and distributed synchronization complex.

Event Sourcing models application state as an append-only sequence of immutable domain events:

$$\text{Current State} = \text{FoldLeft}(\text{Initial State},\; \text{Events})$$

This module implements enterprise Event Sourcing and CQRS (Command Query Responsibility Segregation) in .NET 8:

  • Aggregate Root Pattern: BankAccountAggregate validates commands (Open, Deposit, Withdraw, Close) against current business rules and emits immutable domain events.
  • Append-Only Event Store: Stores events ordered by monotonic version per stream (AccountId).
  • Optimistic Concurrency Control: Employs ExpectedVersion checking during append operations to detect and reject concurrent write collisions (OptimisticConcurrencyException).
  • State Reconstruction & Snapshotting: Rebuilds aggregate state by applying events sequentially. Periodic snapshots bound replay time from $O(N)$ to $O(k)$ where $k \le \text{snapshot interval}$.
  • CQRS Read-Model Projections: Separates the write model from the query model. An AccountProjectionManager listens to committed events and materializes denormalized read views (AccountSummaryView) optimized for high-speed queries.

LeetCode #131: Palindrome Partitioning (Medium)

Partition string $s$ such that every substring is a palindrome:

  • DP Precomputation: Constructs a 2D boolean dynamic programming table dp[i, j] where dp[i, j] = true if s[i..j] is a palindrome. Base cases handle length 1 and 2; transitions evaluate s[i] == s[j] && dp[i+1, j-1].
  • Backtracking: Traverses partitions using $O(1)$ DP palindrome verification, avoiding redundant $O(K)$ string reversal checks per branch.

10 Senior / Staff-Level Interview Questions with In-Depth Answers:
Q1 What is Event Sourcing, and how does it fundamentally differ from traditional CRUD persistence?
▼

Answer:

  • CRUD (Create, Read, Update, Delete): Directly mutates the current snapshot of an entity in a database table. Prior states are overwritten and lost unless secondary audit tables are maintained.
  • Event Sourcing: Replaces mutable tables with an immutable, append-only log of domain events (AccountOpened, FundsDeposited, FundsWithdrawn).
  • Current state is not stored as the primary source of truth; it is derived by replaying (folding) all past events from genesis to present.
  • Guarantees 100% auditability, eliminates object-relational mapping impedance mismatch, enables time-travel debugging, and provides native event publishing for microservice event-driven choreography.
Q2 What is CQRS, and why is it frequently paired with Event Sourcing?
▼

Answer:

CQRS (Command Query Responsibility Segregation) separates data modification (Commands) from data retrieval (Queries):

  • Why paired: An event-sourced write model is structurally an append-only log (StreamId, Version, Payload). Querying complex relational filters (e.g., "Find all accounts in California with balance > \$5,000 created in 2024") on an append-only event log would require replaying every event in the entire database, which is $O(N)$ and prohibitively expensive.
  • Solution: Event handlers listen to committed events and project (materialize) them into read-optimized SQL tables, Elasticsearch indices, or Redis caches. Commands hit the aggregate; queries hit the projections.
Q3 How do you implement Optimistic Concurrency Control in an append-only Event Store?
▼

Answer:

  1. When loading an aggregate root to execute a command, record its current version (e.g. Version = 4).
  2. The aggregate executes business logic and emits new uncommitted events (e.g., versions 5 and 6).
  3. The event store executes an atomic append:

INSERT INTO events (stream_id, version, payload) VALUES ...

  1. The database enforces a unique composite constraint on (stream_id, version) or checks WHERE stream_id = @id AND version = @expectedVersion.
  2. If another concurrent request already appended version 5, the insert fails with a unique constraint violation.
  3. The application catches this error, raises an OptimisticConcurrencyException, reloads the fresh aggregate state, and retries the command.
Q4 What is Snapshotting in Event Sourcing, and when should it be triggered?
▼

Answer:

As an entity's lifecycle lengthens, replaying thousands of historical events on every load degrades latency ($O(N)$ event deserialization).

  • Snapshotting: The system periodically serializes the aggregate's in-memory state alongside its version (e.g., at version 100, AccountSnapshot(Balance=1500, Version=100)).
  • When loading the aggregate, fetch the newest snapshot first ($O(1)$) and only replay events with Version > Snapshot.Version.
  • Triggers: Periodic threshold (every $N=100$ events), time-based, or asynchronous background snapshot worker.
Q5 How do you handle schema evolution and breaking changes in immutable domain events ("Versioning Events")?
▼

Answer:

Because events are immutable and persisted permanently, old events cannot be casually rewritten in the database.

  • Strategies:
  1. Upcasting: Middleware intercepts raw JSON during deserialization. If an event is version 1, an upcaster transforms it into version 2 schema (e.g., splitting FullName into FirstName and LastName) before handing it to the aggregate.
  2. Additive Schema Evolution: Make changes backward-compatible: new properties must be nullable or have safe defaults; never delete or rename properties.
  3. Event Migration / Copy-and-Replace: Create a background migration script that reads from stream V1, translates events, and writes to stream V2.
Q6 How do you guarantee idempotency and "at-least-once" projection updates in CQRS?
▼

Answer:

Projections subscribe to the event stream over message brokers or database change data capture (CDC).

  • Network glitches cause event re-deliveries.
  • Projection Idempotency:
  • Maintain a last_processed_version column in the projection database within the same local transaction as the projection update:
    UPDATE account_views 
    SET balance = balance + @amount, last_version = @version 
    WHERE account_id = @id AND last_version = @version - 1;
  • If an event with version <= last_version arrives, the projection ignores it, preventing duplicate mutations.
Q7 How do you comply with GDPR "Right to be Forgotten" in an immutable Event Store?
▼

Answer:

GDPR requires permanently deleting personal identifiable data (PII), which conflicts with append-only immutability.

  • Crypto-Shredding (Cryptographic Erasure):
  • Personal data fields (name, email, SSN) inside domain events are encrypted with a unique per-user symmetric key ($K_{\text{user}}$).
  • The keys are stored in a dedicated key vault.
  • When the user requests account deletion, simply destroy $K_{\text{user}}$.
  • The events remain in the append-only store preserving cryptographic hashes and stream version integrity, but the PII is permanently and irrecoverably rendered unreadable ciphertext.
Q8 In LeetCode #131 (Palindrome Partitioning), how does Dynamic Programming optimize the backtracking search?
▼

Answer:

  • Checking if a substring $s[i..j]$ is a palindrome naively requires $O(j - i)$ two-pointer comparisons.
  • In backtracking, the same substring is evaluated repeatedly across different partitioning prefixes.
  • Precomputing a 2D boolean table dp[i, j] using the recurrence:

$$\text{dp}[i, j] = (s[i] == s[j]) \land (j - i \le 2 \lor \text{dp}[i+1, j-1])$$

takes $O(N^2)$ time once.

  • During backtracking, verifying if a substring is a valid palindrome is reduced from $O(N)$ to $O(1)$ memory lookup, dramatically pruning recursive branches and reducing execution time.
Q9 What are the primary trade-offs and downsides of Event Sourcing?
▼

Answer:

  • Complexity: Significantly steeper learning curve than standard CRUD; developers must think in terms of immutable facts rather than current state.
  • Eventual Consistency: Read projections are asynchronously updated, requiring UI accommodation (optimistic rendering, spinners, or polling).
  • Storage Overhead: An append-only store grows monotonically and requires partitioning, archival, and snapshotting strategies.
  • Query Impedance: Directly querying the event store for ad-hoc business reporting is impractical; an external projection layer (CQRS) is mandatory.
Q10 How do you test an Event-Sourced Aggregate Root?
▼

Answer:

Event-sourced aggregates are pure domain models with zero external I/O dependencies, making them exceptionally easy and fast to unit test using the Given-When-Then specification pattern:

  • Given: A sequence of past historical events:

[AccountOpened(balance=100), FundsDeposited(amount=50)]

  • When: A command is executed:

account.Withdraw(30)

  • Then: Assert that the expected domain event is emitted:

[FundsWithdrawn(amount=30, version=3)]

  • Or assert that a domain exception is thrown:

account.Withdraw(500) -> throws InsufficientFundsException

namespace Day40.EventSourcing;

public class OptimisticConcurrencyException : Exception
{
    public OptimisticConcurrencyException(string message) : base(message) { }
}

public interface IDomainEvent
{
    string StreamId { get; }
    long Version { get; }
    DateTime OccurredAtUtc { get; }
}

public record AccountOpenedEvent(string AccountId, string OwnerName, decimal InitialBalance, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record FundsDepositedEvent(string AccountId, decimal Amount, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record FundsWithdrawnEvent(string AccountId, decimal Amount, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record AccountClosedEvent(string AccountId, string Reason, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record AccountSnapshot(string AccountId, string OwnerName, decimal Balance, bool IsClosed, long Version);

public class BankAccountAggregate
{
    public string Id { get; private set; } = string.Empty;
    public string OwnerName { get; private set; } = string.Empty;
    public decimal Balance { get; private set; } = 0m;
    public bool IsClosed { get; private set; } = false;
    public long Version { get; private set; } = 0;

    private readonly List<IDomainEvent> _uncommittedEvents = new();
    public IReadOnlyList<IDomainEvent> UncommittedEvents => _uncommittedEvents.ToList();

    public void ClearUncommittedEvents() => _uncommittedEvents.Clear();

    public void LoadFromHistory(IEnumerable<IDomainEvent> history)
    {
        foreach (var evt in history)
        {
            Apply(evt);
            Version = evt.Version;
        }
    }

    public void RestoreFromSnapshot(AccountSnapshot snapshot)
    {
        Id = snapshot.AccountId;
        OwnerName = snapshot.OwnerName;
        Balance = snapshot.Balance;
        IsClosed = snapshot.IsClosed;
        Version = snapshot.Version;
    }

    public void Open(string accountId, string ownerName, decimal initialBalance)
    {
        if (Version > 0) throw new InvalidOperationException("Account is already open");
        if (initialBalance < 0) throw new ArgumentException("Initial balance cannot be negative");

        Emit(new AccountOpenedEvent(accountId, ownerName, initialBalance, Version + 1, DateTime.UtcNow));
    }

    public void Deposit(decimal amount)
    {
        if (IsClosed) throw new InvalidOperationException("Cannot deposit to closed account");
        if (amount <= 0) throw new ArgumentException("Deposit must be positive");

        Emit(new FundsDepositedEvent(Id, amount, Version + 1, DateTime.UtcNow));
    }

    public void Withdraw(decimal amount)
    {
        if (IsClosed) throw new InvalidOperationException("Cannot withdraw from closed account");
        if (amount <= 0) throw new ArgumentException("Withdrawal must be positive");
        if (Balance < amount) throw new InvalidOperationException("Insufficient funds");

        Emit(new FundsWithdrawnEvent(Id, amount, Version + 1, DateTime.UtcNow));
    }

    public void Close(string reason)
    {
        if (IsClosed) throw new InvalidOperationException("Account is already closed");
        Emit(new AccountClosedEvent(Id, reason, Version + 1, DateTime.UtcNow));
    }

    private void Emit(IDomainEvent evt)
    {
        Apply(evt);
        Version = evt.Version;
        _uncommittedEvents.Add(evt);
    }

    private void Apply(IDomainEvent evt)
    {
        switch (evt)
        {
            case AccountOpenedEvent opened:
                Id = opened.AccountId;
                OwnerName = opened.OwnerName;
                Balance = opened.InitialBalance;
                IsClosed = false;
                break;
            case FundsDepositedEvent deposited:
                Balance += deposited.Amount;
                break;
            case FundsWithdrawnEvent withdrawn:
                Balance -= withdrawn.Amount;
                break;
            case AccountClosedEvent:
                IsClosed = true;
                break;
        }
    }
}

public class EventStore
{
    private readonly Dictionary<string, List<IDomainEvent>> _streams = new();
    private readonly Dictionary<string, AccountSnapshot> _snapshots = new();
    private readonly object _lock = new();

    public event Action<IDomainEvent>? EventAppended;

    public void AppendEvents(string streamId, long expectedVersion, IEnumerable<IDomainEvent> newEvents)
    {
        lock (_lock)
        {
            if (!_streams.TryGetValue(streamId, out var stream))
            {
                stream = new List<IDomainEvent>();
                _streams[streamId] = stream;
            }

            long currentVersion = stream.Count > 0 ? stream[^1].Version : 0;
            if (currentVersion != expectedVersion)
            {
                throw new OptimisticConcurrencyException(
                    $"Stream '{streamId}' concurrency conflict. Expected version {expectedVersion}, actual {currentVersion}.");
            }

            foreach (var evt in newEvents)
            {
                stream.Add(evt);
                EventAppended?.Invoke(evt);
            }
        }
    }

    public void SaveSnapshot(string streamId, AccountSnapshot snapshot)
    {
        lock (_lock)
        {
            _snapshots[streamId] = snapshot;
        }
    }

    public BankAccountAggregate LoadAggregate(string streamId)
    {
        lock (_lock)
        {
            var aggregate = new BankAccountAggregate();
            long fromVersion = 0;

            if (_snapshots.TryGetValue(streamId, out var snapshot))
            {
                aggregate.RestoreFromSnapshot(snapshot);
                fromVersion = snapshot.Version;
            }

            if (_streams.TryGetValue(streamId, out var stream))
            {
                var subsequentEvents = stream.Where(e => e.Version > fromVersion);
                aggregate.LoadFromHistory(subsequentEvents);
            }

            return aggregate;
        }
    }
}

public record AccountSummaryView(string AccountId, string OwnerName, decimal CurrentBalance, int TransactionCount, string Status);

public class AccountProjectionManager
{
    private readonly Dictionary<string, AccountSummaryView> _readViews = new();
    private readonly object _lock = new();

    public AccountProjectionManager(EventStore eventStore)
    {
        eventStore.EventAppended += Project;
    }

    public AccountSummaryView? GetAccountView(string accountId)
    {
        lock (_lock)
        {
            return _readViews.TryGetValue(accountId, out var view) ? view : null;
        }
    }

    private void Project(IDomainEvent evt)
    {
        lock (_lock)
        {
            switch (evt)
            {
                case AccountOpenedEvent opened:
                    _readViews[opened.AccountId] = new AccountSummaryView(
                        opened.AccountId,
                        opened.OwnerName,
                        opened.InitialBalance,
                        TransactionCount: 1,
                        Status: "Active"
                    );
                    break;
                case FundsDepositedEvent deposited:
                    if (_readViews.TryGetValue(deposited.AccountId, out var currentDep))
                    {
                        _readViews[deposited.AccountId] = currentDep with
                        {
                            CurrentBalance = currentDep.CurrentBalance + deposited.Amount,
                            TransactionCount = currentDep.TransactionCount + 1
                        };
                    }
                    break;
                case FundsWithdrawnEvent withdrawn:
                    if (_readViews.TryGetValue(withdrawn.AccountId, out var currentWd))
                    {
                        _readViews[withdrawn.AccountId] = currentWd with
                        {
                            CurrentBalance = currentWd.CurrentBalance - withdrawn.Amount,
                            TransactionCount = currentWd.TransactionCount + 1
                        };
                    }
                    break;
                case AccountClosedEvent closed:
                    if (_readViews.TryGetValue(closed.AccountId, out var currentCl))
                    {
                        _readViews[closed.AccountId] = currentCl with
                        {
                            Status = "Closed",
                            TransactionCount = currentCl.TransactionCount + 1
                        };
                    }
                    break;
            }
        }
    }
}

namespace Day40.EventSourcing;

public static class PalindromePartitioningSolver
{
    /// <summary>
    /// LeetCode #131: Palindrome Partitioning (Medium).
    /// Uses DP precomputation table to check palindromes in O(1) time during backtracking.
    /// Time Complexity: O(N * 2^N), Space Complexity: O(N^2) for DP table + O(N) recursion stack.
    /// </summary>
    public static IList<IList<string>> Partition(string s)
    {
        var result = new List<IList<string>>();
        if (string.IsNullOrEmpty(s)) return result;

        int n = s.Length;
        // DP table: dp[i, j] is true if substring s[i..j] is a palindrome
        var dp = new bool[n, n];

        for (int i = 0; i < n; i++)
        {
            dp[i, i] = true;
        }

        for (int len = 2; len <= n; len++)
        {
            for (int i = 0; i <= n - len; i++)
            {
                int j = i + len - 1;
                if (s[i] == s[j])
                {
                    dp[i, j] = len == 2 || dp[i + 1, j - 1];
                }
            }
        }

        var current = new List<string>();
        Backtrack(s, 0, dp, current, result);
        return result;
    }

    private static void Backtrack(string s, int start, bool[,] dp, List<string> current, List<IList<string>> result)
    {
        if (start == s.Length)
        {
            result.Add(new List<string>(current));
            return;
        }

        for (int end = start; end < s.Length; end++)
        {
            if (dp[start, end])
            {
                current.Add(s.Substring(start, end - start + 1));
                Backtrack(s, end + 1, dp, current, result);
                current.RemoveAt(current.Count - 1);
            }
        }
    }
}

📝 Part 1: Deep-Dive Architectural & Engineering Notes

Deep Dive Notes: Event Sourcing & CQRS Pattern

1. Event Sourcing Core Principles

  • State as a Left Fold:
  • In CRUD, UPDATE accounts SET balance = 150 WHERE id = 1 destroys the history of how the balance became 150.
  • In Event Sourcing, state is derived:

state = events.Aggregate(initial, (acc, evt) => acc.Apply(evt))

  • The Event Store is the single source of truth.
  • Optimistic Concurrency Control (OCC):
  • Stream table schema: (stream_id, version, payload, timestamp) with unique constraint on (stream_id, version).
  • When appending, specify ExpectedVersion. If another process appended version 3 first, the unique constraint or check fails, aborting the write and forcing the caller to reload and re-evaluate business logic.

2. CQRS (Command Query Responsibility Segregation)

  • Asymmetric Scaling:
  • Most business systems have an 80:20 or 99:1 read-to-write ratio.
  • Write Model: Optimized for transactional integrity, validation, and zero locks (aggregates write to append-only tables).
  • Read Model: Optimized for queries (denormalized relational tables, Elasticsearch indices, or Redis hashes).
  • Handling Eventual Consistency in UI:
  • Because read projections update asynchronously after the event is committed, a read immediately following a write might not show the new item.
  • Mitigation Strategies:
  1. Optimistic UI update: The client updates local UI state immediately.
  2. Read-your-own-writes session token: Query model waits until projected version $\ge$ token version before responding.

3. LeetCode #131: Palindrome Partitioning DP Optimization

  • A naive check reverses every substring, taking $O(K)$ time per substring. With $2^N$ possible partition combinations, this wastes CPU cycles.
  • DP Table Formulation:
  • Let dp[i, j] represent whether s[i..j] is a palindrome.
  • Base case: dp[i, i] = true for all $i$.
  • For substrings of length $L \ge 2$:

$$\text{dp}[i, j] = (s[i] == s[j]) \land (L == 2 \lor \text{dp}[i+1, j-1])$$

  • Filling the DP table takes $O(N^2)$ time once up front. Then, each palindrome check in the backtracking loop is a lightning-fast $O(1)$ table lookup.

Day 40: Event Sourcing & CQRS Foundations

Architectural Overview

Traditional CRUD applications mutate state in place, overwriting historical data and making auditing, time-travel debugging, and distributed synchronization complex.

Event Sourcing models application state as an append-only sequence of immutable domain events:

$$\text{Current State} = \text{FoldLeft}(\text{Initial State},\; \text{Events})$$

This module implements enterprise Event Sourcing and CQRS (Command Query Responsibility Segregation) in .NET 8:

  • Aggregate Root Pattern: BankAccountAggregate validates commands (Open, Deposit, Withdraw, Close) against current business rules and emits immutable domain events.
  • Append-Only Event Store: Stores events ordered by monotonic version per stream (AccountId).
  • Optimistic Concurrency Control: Employs ExpectedVersion checking during append operations to detect and reject concurrent write collisions (OptimisticConcurrencyException).
  • State Reconstruction & Snapshotting: Rebuilds aggregate state by applying events sequentially. Periodic snapshots bound replay time from $O(N)$ to $O(k)$ where $k \le \text{snapshot interval}$.
  • CQRS Read-Model Projections: Separates the write model from the query model. An AccountProjectionManager listens to committed events and materializes denormalized read views (AccountSummaryView) optimized for high-speed queries.

  • Backtracking: Traverses partitions using $O(1)$ DP palindrome verification, avoiding redundant $O(K)$ string reversal checks per branch.

💡 Part 3: Senior & Staff-Level Interview Scenarios (10 Questions)

Q1 What is Event Sourcing, and how does it fundamentally differ from traditional CRUD persistence?
▼

Answer:

  • CRUD (Create, Read, Update, Delete): Directly mutates the current snapshot of an entity in a database table. Prior states are overwritten and lost unless secondary audit tables are maintained.
  • Event Sourcing: Replaces mutable tables with an immutable, append-only log of domain events (AccountOpened, FundsDeposited, FundsWithdrawn).
  • Current state is not stored as the primary source of truth; it is derived by replaying (folding) all past events from genesis to present.
  • Guarantees 100% auditability, eliminates object-relational mapping impedance mismatch, enables time-travel debugging, and provides native event publishing for microservice event-driven choreography.
Q2 What is CQRS, and why is it frequently paired with Event Sourcing?
▼

Answer:

CQRS (Command Query Responsibility Segregation) separates data modification (Commands) from data retrieval (Queries):

  • Why paired: An event-sourced write model is structurally an append-only log (StreamId, Version, Payload). Querying complex relational filters (e.g., "Find all accounts in California with balance > \$5,000 created in 2024") on an append-only event log would require replaying every event in the entire database, which is $O(N)$ and prohibitively expensive.
  • Solution: Event handlers listen to committed events and project (materialize) them into read-optimized SQL tables, Elasticsearch indices, or Redis caches. Commands hit the aggregate; queries hit the projections.
Q3 How do you implement Optimistic Concurrency Control in an append-only Event Store?
▼

Answer:

  1. When loading an aggregate root to execute a command, record its current version (e.g. Version = 4).
  2. The aggregate executes business logic and emits new uncommitted events (e.g., versions 5 and 6).
  3. The event store executes an atomic append:

INSERT INTO events (stream_id, version, payload) VALUES ...

  1. The database enforces a unique composite constraint on (stream_id, version) or checks WHERE stream_id = @id AND version = @expectedVersion.
  2. If another concurrent request already appended version 5, the insert fails with a unique constraint violation.
  3. The application catches this error, raises an OptimisticConcurrencyException, reloads the fresh aggregate state, and retries the command.
Q4 What is Snapshotting in Event Sourcing, and when should it be triggered?
▼

Answer:

As an entity's lifecycle lengthens, replaying thousands of historical events on every load degrades latency ($O(N)$ event deserialization).

  • Snapshotting: The system periodically serializes the aggregate's in-memory state alongside its version (e.g., at version 100, AccountSnapshot(Balance=1500, Version=100)).
  • When loading the aggregate, fetch the newest snapshot first ($O(1)$) and only replay events with Version > Snapshot.Version.
  • Triggers: Periodic threshold (every $N=100$ events), time-based, or asynchronous background snapshot worker.
Q5 How do you handle schema evolution and breaking changes in immutable domain events ("Versioning Events")?
▼

Answer:

Because events are immutable and persisted permanently, old events cannot be casually rewritten in the database.

  • Strategies:
  1. Upcasting: Middleware intercepts raw JSON during deserialization. If an event is version 1, an upcaster transforms it into version 2 schema (e.g., splitting FullName into FirstName and LastName) before handing it to the aggregate.
  2. Additive Schema Evolution: Make changes backward-compatible: new properties must be nullable or have safe defaults; never delete or rename properties.
  3. Event Migration / Copy-and-Replace: Create a background migration script that reads from stream V1, translates events, and writes to stream V2.
Q6 How do you guarantee idempotency and "at-least-once" projection updates in CQRS?
▼

Answer:

Projections subscribe to the event stream over message brokers or database change data capture (CDC).

  • Network glitches cause event re-deliveries.
  • Projection Idempotency:
  • Maintain a last_processed_version column in the projection database within the same local transaction as the projection update:
    UPDATE account_views 
    SET balance = balance + @amount, last_version = @version 
    WHERE account_id = @id AND last_version = @version - 1;
  • If an event with version <= last_version arrives, the projection ignores it, preventing duplicate mutations.
Q7 How do you comply with GDPR "Right to be Forgotten" in an immutable Event Store?
▼

Answer:

GDPR requires permanently deleting personal identifiable data (PII), which conflicts with append-only immutability.

  • Crypto-Shredding (Cryptographic Erasure):
  • Personal data fields (name, email, SSN) inside domain events are encrypted with a unique per-user symmetric key ($K_{\text{user}}$).
  • The keys are stored in a dedicated key vault.
  • When the user requests account deletion, simply destroy $K_{\text{user}}$.
  • The events remain in the append-only store preserving cryptographic hashes and stream version integrity, but the PII is permanently and irrecoverably rendered unreadable ciphertext.
Q8 In LeetCode #131 (Palindrome Partitioning), how does Dynamic Programming optimize the backtracking search?
▼

Answer:

  • Checking if a substring $s[i..j]$ is a palindrome naively requires $O(j - i)$ two-pointer comparisons.
  • In backtracking, the same substring is evaluated repeatedly across different partitioning prefixes.
  • Precomputing a 2D boolean table dp[i, j] using the recurrence:

$$\text{dp}[i, j] = (s[i] == s[j]) \land (j - i \le 2 \lor \text{dp}[i+1, j-1])$$

takes $O(N^2)$ time once.

  • During backtracking, verifying if a substring is a valid palindrome is reduced from $O(N)$ to $O(1)$ memory lookup, dramatically pruning recursive branches and reducing execution time.
Q9 What are the primary trade-offs and downsides of Event Sourcing?
▼

Answer:

  • Complexity: Significantly steeper learning curve than standard CRUD; developers must think in terms of immutable facts rather than current state.
  • Eventual Consistency: Read projections are asynchronously updated, requiring UI accommodation (optimistic rendering, spinners, or polling).
  • Storage Overhead: An append-only store grows monotonically and requires partitioning, archival, and snapshotting strategies.
  • Query Impedance: Directly querying the event store for ad-hoc business reporting is impractical; an external projection layer (CQRS) is mandatory.
Q10 How do you test an Event-Sourced Aggregate Root?
▼

Answer:

Event-sourced aggregates are pure domain models with zero external I/O dependencies, making them exceptionally easy and fast to unit test using the Given-When-Then specification pattern:

  • Given: A sequence of past historical events:

[AccountOpened(balance=100), FundsDeposited(amount=50)]

  • When: A command is executed:

account.Withdraw(30)

  • Then: Assert that the expected domain event is emitted:

[FundsWithdrawn(amount=30, version=3)]

  • Or assert that a domain exception is thrown:

account.Withdraw(500) -> throws InsufficientFundsException

namespace Day40.EventSourcing;

public class OptimisticConcurrencyException : Exception
{
    public OptimisticConcurrencyException(string message) : base(message) { }
}

public interface IDomainEvent
{
    string StreamId { get; }
    long Version { get; }
    DateTime OccurredAtUtc { get; }
}

public record AccountOpenedEvent(string AccountId, string OwnerName, decimal InitialBalance, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record FundsDepositedEvent(string AccountId, decimal Amount, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record FundsWithdrawnEvent(string AccountId, decimal Amount, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record AccountClosedEvent(string AccountId, string Reason, long Version, DateTime OccurredAtUtc) : IDomainEvent
{
    public string StreamId => AccountId;
}

public record AccountSnapshot(string AccountId, string OwnerName, decimal Balance, bool IsClosed, long Version);

public class BankAccountAggregate
{
    public string Id { get; private set; } = string.Empty;
    public string OwnerName { get; private set; } = string.Empty;
    public decimal Balance { get; private set; } = 0m;
    public bool IsClosed { get; private set; } = false;
    public long Version { get; private set; } = 0;

    private readonly List<IDomainEvent> _uncommittedEvents = new();
    public IReadOnlyList<IDomainEvent> UncommittedEvents => _uncommittedEvents.ToList();

    public void ClearUncommittedEvents() => _uncommittedEvents.Clear();

    public void LoadFromHistory(IEnumerable<IDomainEvent> history)
    {
        foreach (var evt in history)
        {
            Apply(evt);
            Version = evt.Version;
        }
    }

    public void RestoreFromSnapshot(AccountSnapshot snapshot)
    {
        Id = snapshot.AccountId;
        OwnerName = snapshot.OwnerName;
        Balance = snapshot.Balance;
        IsClosed = snapshot.IsClosed;
        Version = snapshot.Version;
    }

    public void Open(string accountId, string ownerName, decimal initialBalance)
    {
        if (Version > 0) throw new InvalidOperationException("Account is already open");
        if (initialBalance < 0) throw new ArgumentException("Initial balance cannot be negative");

        Emit(new AccountOpenedEvent(accountId, ownerName, initialBalance, Version + 1, DateTime.UtcNow));
    }

    public void Deposit(decimal amount)
    {
        if (IsClosed) throw new InvalidOperationException("Cannot deposit to closed account");
        if (amount <= 0) throw new ArgumentException("Deposit must be positive");

        Emit(new FundsDepositedEvent(Id, amount, Version + 1, DateTime.UtcNow));
    }

    public void Withdraw(decimal amount)
    {
        if (IsClosed) throw new InvalidOperationException("Cannot withdraw from closed account");
        if (amount <= 0) throw new ArgumentException("Withdrawal must be positive");
        if (Balance < amount) throw new InvalidOperationException("Insufficient funds");

        Emit(new FundsWithdrawnEvent(Id, amount, Version + 1, DateTime.UtcNow));
    }

    public void Close(string reason)
    {
        if (IsClosed) throw new InvalidOperationException("Account is already closed");
        Emit(new AccountClosedEvent(Id, reason, Version + 1, DateTime.UtcNow));
    }

    private void Emit(IDomainEvent evt)
    {
        Apply(evt);
        Version = evt.Version;
        _uncommittedEvents.Add(evt);
    }

    private void Apply(IDomainEvent evt)
    {
        switch (evt)
        {
            case AccountOpenedEvent opened:
                Id = opened.AccountId;
                OwnerName = opened.OwnerName;
                Balance = opened.InitialBalance;
                IsClosed = false;
                break;
            case FundsDepositedEvent deposited:
                Balance += deposited.Amount;
                break;
            case FundsWithdrawnEvent withdrawn:
                Balance -= withdrawn.Amount;
                break;
            case AccountClosedEvent:
                IsClosed = true;
                break;
        }
    }
}

public class EventStore
{
    private readonly Dictionary<string, List<IDomainEvent>> _streams = new();
    private readonly Dictionary<string, AccountSnapshot> _snapshots = new();
    private readonly object _lock = new();

    public event Action<IDomainEvent>? EventAppended;

    public void AppendEvents(string streamId, long expectedVersion, IEnumerable<IDomainEvent> newEvents)
    {
        lock (_lock)
        {
            if (!_streams.TryGetValue(streamId, out var stream))
            {
                stream = new List<IDomainEvent>();
                _streams[streamId] = stream;
            }

            long currentVersion = stream.Count > 0 ? stream[^1].Version : 0;
            if (currentVersion != expectedVersion)
            {
                throw new OptimisticConcurrencyException(
                    $"Stream '{streamId}' concurrency conflict. Expected version {expectedVersion}, actual {currentVersion}.");
            }

            foreach (var evt in newEvents)
            {
                stream.Add(evt);
                EventAppended?.Invoke(evt);
            }
        }
    }

    public void SaveSnapshot(string streamId, AccountSnapshot snapshot)
    {
        lock (_lock)
        {
            _snapshots[streamId] = snapshot;
        }
    }

    public BankAccountAggregate LoadAggregate(string streamId)
    {
        lock (_lock)
        {
            var aggregate = new BankAccountAggregate();
            long fromVersion = 0;

            if (_snapshots.TryGetValue(streamId, out var snapshot))
            {
                aggregate.RestoreFromSnapshot(snapshot);
                fromVersion = snapshot.Version;
            }

            if (_streams.TryGetValue(streamId, out var stream))
            {
                var subsequentEvents = stream.Where(e => e.Version > fromVersion);
                aggregate.LoadFromHistory(subsequentEvents);
            }

            return aggregate;
        }
    }
}

public record AccountSummaryView(string AccountId, string OwnerName, decimal CurrentBalance, int TransactionCount, string Status);

public class AccountProjectionManager
{
    private readonly Dictionary<string, AccountSummaryView> _readViews = new();
    private readonly object _lock = new();

    public AccountProjectionManager(EventStore eventStore)
    {
        eventStore.EventAppended += Project;
    }

    public AccountSummaryView? GetAccountView(string accountId)
    {
        lock (_lock)
        {
            return _readViews.TryGetValue(accountId, out var view) ? view : null;
        }
    }

    private void Project(IDomainEvent evt)
    {
        lock (_lock)
        {
            switch (evt)
            {
                case AccountOpenedEvent opened:
                    _readViews[opened.AccountId] = new AccountSummaryView(
                        opened.AccountId,
                        opened.OwnerName,
                        opened.InitialBalance,
                        TransactionCount: 1,
                        Status: "Active"
                    );
                    break;
                case FundsDepositedEvent deposited:
                    if (_readViews.TryGetValue(deposited.AccountId, out var currentDep))
                    {
                        _readViews[deposited.AccountId] = currentDep with
                        {
                            CurrentBalance = currentDep.CurrentBalance + deposited.Amount,
                            TransactionCount = currentDep.TransactionCount + 1
                        };
                    }
                    break;
                case FundsWithdrawnEvent withdrawn:
                    if (_readViews.TryGetValue(withdrawn.AccountId, out var currentWd))
                    {
                        _readViews[withdrawn.AccountId] = currentWd with
                        {
                            CurrentBalance = currentWd.CurrentBalance - withdrawn.Amount,
                            TransactionCount = currentWd.TransactionCount + 1
                        };
                    }
                    break;
                case AccountClosedEvent closed:
                    if (_readViews.TryGetValue(closed.AccountId, out var currentCl))
                    {
                        _readViews[closed.AccountId] = currentCl with
                        {
                            Status = "Closed",
                            TransactionCount = currentCl.TransactionCount + 1
                        };
                    }
                    break;
            }
        }
    }
}

namespace Day40.EventSourcing;

public static class PalindromePartitioningSolver
{
    /// <summary>
    /// LeetCode #131: Palindrome Partitioning (Medium).
    /// Uses DP precomputation table to check palindromes in O(1) time during backtracking.
    /// Time Complexity: O(N * 2^N), Space Complexity: O(N^2) for DP table + O(N) recursion stack.
    /// </summary>
    public static IList<IList<string>> Partition(string s)
    {
        var result = new List<IList<string>>();
        if (string.IsNullOrEmpty(s)) return result;

        int n = s.Length;
        // DP table: dp[i, j] is true if substring s[i..j] is a palindrome
        var dp = new bool[n, n];

        for (int i = 0; i < n; i++)
        {
            dp[i, i] = true;
        }

        for (int len = 2; len <= n; len++)
        {
            for (int i = 0; i <= n - len; i++)
            {
                int j = i + len - 1;
                if (s[i] == s[j])
                {
                    dp[i, j] = len == 2 || dp[i + 1, j - 1];
                }
            }
        }

        var current = new List<string>();
        Backtrack(s, 0, dp, current, result);
        return result;
    }

    private static void Backtrack(string s, int start, bool[,] dp, List<string> current, List<IList<string>> result)
    {
        if (start == s.Length)
        {
            result.Add(new List<string>(current));
            return;
        }

        for (int end = start; end < s.Length; end++)
        {
            if (dp[start, end])
            {
                current.Add(s.Substring(start, end - start + 1));
                Backtrack(s, end + 1, dp, current, result);
                current.RemoveAt(current.Count - 1);
            }
        }
    }
}
