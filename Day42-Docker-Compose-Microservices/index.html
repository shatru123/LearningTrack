Deep Dive Notes: Docker Compose for Microservice Stacks

1. Network Bridging & Service Discovery

In Docker Compose, custom networks create isolated virtual ethernet bridges (veth pairs). Every container registered on the network is assigned an internal IP address and can resolve other containers via their service name or container name using Docker's internal embedded DNS server (127.0.0.11).

2. Healthcheck Coordination vs Simple depends_on

A plain depends_on directive only guarantees that container A starts after container B process execution begins. It does not wait for database initialization, schema migration, or port binding.

Using condition: service_healthy ensures that Docker's daemon executes the specified healthcheck.test command (e.g. pg_isready, redis-cli ping, rabbitmq-diagnostics check_running) until the consecutive success threshold is reached before unblocking dependent containers.

3. Volume Persistence Strategies

  • Named Volumes: Managed by the Docker daemon in /var/lib/docker/volumes/, offering high performance, automatic directory creation, and OS-agnostic mount paths.
  • Bind Mounts: Direct host filesystem bindings (./data:/var/lib/data), ideal for local source code syncing during development but dangerous in production due to permission mismatches.

Day 42: Docker Compose for Microservice Stacks

Overview

Day 42 focuses on production-grade multi-container orchestration with Docker Compose, managing interdependent microservice topologies including ASP.NET Core APIs, PostgreSQL 16, Redis 7, RabbitMQ 3.13, and Jaeger distributed tracing.

Key Architectures

  • Bridge Network Isolation: Dedicated microservices-net bridge preventing external network contamination and providing automatic DNS name resolution (postgres, redis, rabbitmq, jaeger).
  • Healthcheck Dependency Coordination: depends_on with condition: service_healthy ensuring the ASP.NET Core API doesn't start until backing data stores and brokers are ready.
  • Volume Persistence: Named volumes (pgdata, redisdata, rabbitdata) surviving container recreation.
  • Environment Variable Interpolation: ${VAR:-default} pattern decoupling environment-specific configuration from code.

DSA Problem: LeetCode #198 & #213 (House Robber I & II)

  • LC #198 (House Robber): 1D Dynamic Programming with state $dp[i] = \max(dp[i-1], dp[i-2] + nums[i])$ in $\mathcal{O}(1)$ space.
  • LC #213 (House Robber II): Circular street constraint where house $0$ and house $N-1$ are adjacent. Decomposed into $\max(\text{Rob}(0, N-2), \text{Rob}(1, N-1))$.

10 Senior / Staff-Level Interview Questions with In-Depth Answers:
Q1 What is the critical difference between `depends_on` with and without `condition: service_healthy` in Docker Compose?
▼

Answer:

A bare depends_on: [postgres] only waits for the PostgreSQL container process to be spawned (ENTRYPOINT started). It does not wait for the database engine to finish initializing, replay logs, or open socket connections. This causes downstream services to crash immediately with connection refused errors.

With condition: service_healthy, Compose queries the Docker daemon's health monitoring daemon and blocks downstream container creation until the healthcheck command (such as pg_isready -U user -d db) returns exit code 0 consecutively retries times.

Q2 How does Docker Compose implement internal DNS resolution between services?
▼

Answer:

When containers join a user-defined network, Docker starts an embedded DNS server on 127.0.0.11. Whenever an application attempts to resolve a hostname like http://rabbitmq:5672, the container's resolver routes the DNS query to 127.0.0.11, which maps the service name or container aliases to the container's current internal IP address on the bridge network.

Q3 How do you prevent port collision when running multiple compose stacks on a developer machine?
▼

Answer:

Avoid hardcoding host ports in production compose files. Instead, use environment variable interpolation (e.g., "${API_PORT:-8080}:8080"), or leave the host port empty ("8080") to let Docker assign ephemeral random host ports, inspected via docker compose port order-api 8080.

Q4 How should secrets and connection strings be injected in production Docker Compose?
▼

Answer:

Never commit unencrypted credentials to docker-compose.yml. Use Docker Compose Secrets (secrets: top-level block with file: or environment:) or load credentials from an .env file that is excluded via .gitignore. In cloud environments, reference runtime secret injection tools such as AWS Secrets Manager or HashiCorp Vault.

Q5 What is the difference between Docker `bridge` and `host` network drivers?
▼

Answer:

bridge provides isolated network namespace with its own IP and subnet, requiring explicit port mapping (-p 8080:8080). host removes network namespace isolation, binding the container's network directly to the host's network interfaces, eliminating NAT packet rewriting overhead at the expense of port conflict risks and loss of internal container name resolution.

Q6 How does Docker Compose handle container restart policies on microservice crashes?
▼

Answer:

Compose supports four restart policies:

  1. no: Default, never restarts container.
  2. always: Always restarts container on exit, even on system boot unless explicitly stopped.
  3. on-failure[:max-retries]: Restarts only if the container exits with a non-zero exit code.
  4. unless-stopped: Similar to always, but retains stopped state across daemon reboots if stopped manually.
Q7 Explain the dynamic programming state transition for LeetCode #198 House Robber.
▼

Answer:

Let $dp[i]$ represent the maximum money robbable from the first $i$ houses:

$$dp[i] = \max(dp[i-1], dp[i-2] + nums[i])$$

Since $dp[i]$ depends only on the previous two values, we can discard the array and maintain two scalar variables (prev1, prev2), optimizing space complexity from $\mathcal{O}(N)$ to $\mathcal{O}(1)$.

Q8 How do you solve the circular dependency in LeetCode #213 House Robber II?
▼

Answer:

Because the first house and last house cannot both be robbed, the circular street yields two mutually exclusive scenarios:

  1. Rob houses from index $0$ to $N-2$ (ignoring the last house).
  2. Rob houses from index $1$ to $N-1$ (ignoring the first house).

We run the linear House Robber algorithm on both slices and take $\max(\text{rob}(0, N-2), \text{rob}(1, N-1))$.

Q9 How can you optimize Docker image build caching within a Docker Compose build context?
▼

Answer:

Structure the Dockerfile so frequently modified files (source code) appear after infrequently modified files (package descriptors). In .NET:

  1. COPY *.csproj . and run dotnet restore.
  2. COPY . . and run dotnet build / publish.

In Compose, specify cache_from: pointing to pre-built registry images to leverage remote layer caches in CI/CD.

Q10 How do named volumes differ from bind mounts in Docker Compose?
▼

Answer:

Named volumes are isolated in Docker's storage driver directory (/var/lib/docker/volumes), have predictable read/write performance across Linux, Mac, and Windows, and support volume drivers (NFS, cloud storage). Bind mounts mount arbitrary host paths directly, requiring identical file permissions (UID/GID) between host and container.

    public List<string> DetectPortCollisions(IEnumerable<ServiceDefinition> services)
    {
        var hostPortMap = new Dictionary<int, string>();
        var collisions = new List<string>();

        foreach (var svc in services)
        {
            foreach (var portMapping in svc.Ports)
            {
                var parts = portMapping.Split(':');
                if (parts.Length == 2 && int.TryParse(parts[0], out int hostPort))
                {
                    if (hostPortMap.TryGetValue(hostPort, out var existingSvc))
                    {
                        collisions.Add($"Port collision on host port {hostPort}: claimed by '{existingSvc}' and '{svc.Name}'");
                    }
                    else
                    {
                        hostPortMap[hostPort] = svc.Name;
                    }
                }
            }
        }
        return collisions;
    }

    public List<string> GetTopologicalStartupOrder(ComposeConfig config)
    {
        var result = new List<string>();
        var inDegree = new Dictionary<string, int>();
        var graph = new Dictionary<string, List<string>>();

        foreach (var svc in config.Services.Keys)
        {
            inDegree[svc] = 0;
            graph[svc] = new List<string>();
        }

        foreach (var (svcName, svc) in config.Services)
        {
            foreach (var dep in svc.DependsOn.Keys)
            {
                if (config.Services.ContainsKey(dep))
                {
                    graph[dep].Add(svcName);
                    inDegree[svcName]++;
                }
            }
        }

        var queue = new Queue<string>(inDegree.Where(kv => kv.Value == 0).Select(kv => kv.Key).OrderBy(s => s));

        while (queue.Count > 0)
        {
            var current = queue.Dequeue();
            result.Add(current);

            foreach (var neighbor in graph[current].OrderBy(s => s))
            {
                inDegree[neighbor]--;
                if (inDegree[neighbor] == 0)
                {
                    queue.Enqueue(neighbor);
                }
            }
        }

        return result;
    }

    public string SubstituteEnvironmentVariables(string input, Dictionary<string, string> envVariables)
    {
        var pattern = @"\$\{([A-Za-z0-9_]+)(?::-([^}]+))?\}";
        return Regex.Replace(input, pattern, match =>
        {
            var varName = match.Groups[1].Value;
            var defaultValue = match.Groups[2].Success ? match.Groups[2].Value : "";

            if (envVariables.TryGetValue(varName, out var val) && !string.IsNullOrEmpty(val))
            {
                return val;
            }
            return defaultValue;
        });
    }
}

using System;

namespace Day42.DockerCompose;

/// <summary>
/// Solves LeetCode #198 (House Robber) and LeetCode #213 (House Robber II).
/// </summary>
public static class HouseRobberSolver
{
    /// <summary>
    /// LC #198: Standard linear street of houses.
    /// Time Complexity: O(N), Space Complexity: O(1).
    /// </summary>
    public static int Rob(int[] nums)
    {
        if (nums == null || nums.Length == 0) return 0;
        if (nums.Length == 1) return nums[0];

        int prev2 = 0;
        int prev1 = 0;

        foreach (var val in nums)
        {
            int current = Math.Max(prev1, prev2 + val);
            prev2 = prev1;
            prev1 = current;
        }

        return prev1;
    }

    /// <summary>
    /// LC #213: Circular street of houses (first and last are adjacent).
    /// Breaks problem into two linear sub-ranges: [0 .. N-2] and [1 .. N-1].
    /// Time Complexity: O(N), Space Complexity: O(1).
    /// </summary>
    public static int RobCircular(int[] nums)
    {
        if (nums == null || nums.Length == 0) return 0;
        if (nums.Length == 1) return nums[0];
        if (nums.Length == 2) return Math.Max(nums[0], nums[1]);

        int n = nums.Length;
        int robRange1 = RobRange(nums, 0, n - 2);
        int robRange2 = RobRange(nums, 1, n - 1);

        return Math.Max(robRange1, robRange2);
    }

    private static int RobRange(int[] nums, int start, int end)
    {
        int prev2 = 0;
        int prev1 = 0;

        for (int i = start; i <= end; i++)
        {
            int current = Math.Max(prev1, prev2 + nums[i]);
            prev2 = prev1;
            prev1 = current;
        }

        return prev1;
    }
}

  2. always: Always restarts container on exit, even on system boot unless explicitly stopped.
  3. on-failure[:max-retries]: Restarts only if the container exits with a non-zero exit code.
  4. unless-stopped: Similar to always, but retains stopped state across daemon reboots if stopped manually.
Q7 Explain the dynamic programming state transition for LeetCode #198 House Robber.
▼

Answer:

Let $dp[i]$ represent the maximum money robbable from the first $i$ houses:

$$dp[i] = \max(dp[i-1], dp[i-2] + nums[i])$$

Since $dp[i]$ depends only on the previous two values, we can discard the array and maintain two scalar variables (prev1, prev2), optimizing space complexity from $\mathcal{O}(N)$ to $\mathcal{O}(1)$.

Q8 How do you solve the circular dependency in LeetCode #213 House Robber II?
▼

Answer:

Because the first house and last house cannot both be robbed, the circular street yields two mutually exclusive scenarios:

  1. Rob houses from index $0$ to $N-2$ (ignoring the last house).
  2. Rob houses from index $1$ to $N-1$ (ignoring the first house).

We run the linear House Robber algorithm on both slices and take $\max(\text{rob}(0, N-2), \text{rob}(1, N-1))$.

Q9 How can you optimize Docker image build caching within a Docker Compose build context?
▼

Answer:

Structure the Dockerfile so frequently modified files (source code) appear after infrequently modified files (package descriptors). In .NET:

  1. COPY *.csproj . and run dotnet restore.
  2. COPY . . and run dotnet build / publish.

In Compose, specify cache_from: pointing to pre-built registry images to leverage remote layer caches in CI/CD.

Q10 How do named volumes differ from bind mounts in Docker Compose?
▼

Answer:

Named volumes are isolated in Docker's storage driver directory (/var/lib/docker/volumes), have predictable read/write performance across Linux, Mac, and Windows, and support volume drivers (NFS, cloud storage). Bind mounts mount arbitrary host paths directly, requiring identical file permissions (UID/GID) between host and container.

    public List<string> DetectPortCollisions(IEnumerable<ServiceDefinition> services)
    {
        var hostPortMap = new Dictionary<int, string>();
        var collisions = new List<string>();

        foreach (var svc in services)
        {
            foreach (var portMapping in svc.Ports)
            {
                var parts = portMapping.Split(':');
                if (parts.Length == 2 && int.TryParse(parts[0], out int hostPort))
                {
                    if (hostPortMap.TryGetValue(hostPort, out var existingSvc))
                    {
                        collisions.Add($"Port collision on host port {hostPort}: claimed by '{existingSvc}' and '{svc.Name}'");
                    }
                    else
                    {
                        hostPortMap[hostPort] = svc.Name;
                    }
                }
            }
        }
        return collisions;
    }

    public List<string> GetTopologicalStartupOrder(ComposeConfig config)
    {
        var result = new List<string>();
        var inDegree = new Dictionary<string, int>();
        var graph = new Dictionary<string, List<string>>();

        foreach (var svc in config.Services.Keys)
        {
            inDegree[svc] = 0;
            graph[svc] = new List<string>();
        }

        foreach (var (svcName, svc) in config.Services)
        {
            foreach (var dep in svc.DependsOn.Keys)
            {
                if (config.Services.ContainsKey(dep))
                {
                    graph[dep].Add(svcName);
                    inDegree[svcName]++;
                }
            }
        }

        var queue = new Queue<string>(inDegree.Where(kv => kv.Value == 0).Select(kv => kv.Key).OrderBy(s => s));

        while (queue.Count > 0)
        {
            var current = queue.Dequeue();
            result.Add(current);

            foreach (var neighbor in graph[current].OrderBy(s => s))
            {
                inDegree[neighbor]--;
                if (inDegree[neighbor] == 0)
                {
                    queue.Enqueue(neighbor);
                }
            }
        }

        return result;
    }

    public string SubstituteEnvironmentVariables(string input, Dictionary<string, string> envVariables)
    {
        var pattern = @"\$\{([A-Za-z0-9_]+)(?::-([^}]+))?\}";
        return Regex.Replace(input, pattern, match =>
        {
            var varName = match.Groups[1].Value;
            var defaultValue = match.Groups[2].Success ? match.Groups[2].Value : "";

            if (envVariables.TryGetValue(varName, out var val) && !string.IsNullOrEmpty(val))
            {
                return val;
            }
            return defaultValue;
        });
    }

using System;

namespace Day42.DockerCompose;

/// <summary>
/// Solves LeetCode #198 (House Robber) and LeetCode #213 (House Robber II).
/// </summary>
public static class HouseRobberSolver
{
    /// <summary>
    /// LC #198: Standard linear street of houses.
    /// Time Complexity: O(N), Space Complexity: O(1).
    /// </summary>
    public static int Rob(int[] nums)
    {
        if (nums == null || nums.Length == 0) return 0;
        if (nums.Length == 1) return nums[0];

        int prev2 = 0;
        int prev1 = 0;

        foreach (var val in nums)
        {
            int current = Math.Max(prev1, prev2 + val);
            prev2 = prev1;
            prev1 = current;
        }

        return prev1;
    }

    /// <summary>
    /// LC #213: Circular street of houses (first and last are adjacent).
    /// Breaks problem into two linear sub-ranges: [0 .. N-2] and [1 .. N-1].
    /// Time Complexity: O(N), Space Complexity: O(1).
    /// </summary>
    public static int RobCircular(int[] nums)
    {
        if (nums == null || nums.Length == 0) return 0;
        if (nums.Length == 1) return nums[0];
        if (nums.Length == 2) return Math.Max(nums[0], nums[1]);

        int n = nums.Length;
        int robRange1 = RobRange(nums, 0, n - 2);
        int robRange2 = RobRange(nums, 1, n - 1);

        return Math.Max(robRange1, robRange2);
    }

    private static int RobRange(int[] nums, int start, int end)
    {
        int prev2 = 0;
        int prev1 = 0;

        for (int i = start; i <= end; i++)
        {
            int current = Math.Max(prev1, prev2 + nums[i]);
            prev2 = prev1;
            prev1 = current;
        }

        return prev1;
    }
}
