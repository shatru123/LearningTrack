Deep Dive Notes: Kubernetes Control Plane & Networking

1. Declarative Reconciliation Loop

Kubernetes operates on level-triggered reconciliation:

Current State (Observed by Kubelet) ----+
                                        |---> Controller reconciles delta ---> Desired State
Desired State (Stored in Etcd via API) -+

The Deployment controller monitors ReplicaSets; if desired is 3 and observed is 2, it issues Pod creation requests through the kube-apiserver.

2. ClusterIP vs NodePort vs LoadBalancer

  • ClusterIP: Default service type assigning a virtual cluster-internal IP (VIP). Only reachable by workloads within the Kubernetes cluster.
  • NodePort: Allocates a static port (default 30000–32767) across all cluster worker nodes. Traffic to <NodeIP>:<NodePort> is forwarded to backend pods.
  • LoadBalancer: Provisions a cloud-provider external load balancer (AWS NLB/ALB, Azure Load Balancer, GCP Cloud LB) routing external internet traffic directly to the service endpoints.

Day 43: Kubernetes Architecture: Pods, Deployments & Services

Overview

Day 43 explores the core architecture of Kubernetes (K8s) control plane and worker nodes, focusing on deploying cloud-native .NET microservices via production Declarative YAML manifests (Deployment, ClusterIP, NodePort, LoadBalancer).

Core Concepts

  • Control Plane:
  • kube-apiserver: The central REST API gateway and admission controller validating and persisting cluster state into etcd.
  • etcd: Strongly consistent distributed key-value store using Raft consensus for state storage.
  • kube-scheduler: Assigns newly created Pods to nodes using filtering (resource capacity) and scoring (anti-affinity, spread).
  • kube-controller-manager: Runs reconciliation control loops (Deployment controller, ReplicaSet controller).
  • Worker Node:
  • kubelet: Node agent registering the node, executing PodSpecs via Container Runtime Interface (CRI), and reporting health.
  • kube-proxy: Maintains network forwarding rules (IPVS/iptables) mapping Virtual ClusterIP VIPs to healthy Pod Endpoints.
  • Deployments & Services:
  • RollingUpdate with maxSurge: 25% and maxUnavailable: 0 for zero-downtime releases.
  • Hardened securityContext (runAsNonRoot: true, readOnlyRootFilesystem: true, dropping all Linux capabilities).

DSA Problem: LeetCode #5 (Longest Palindromic Substring)

  • Expand Around Center approach running in $\mathcal{O}(N^2)$ time and $\mathcal{O}(1)$ space.
  • Dynamic Programming table $dp[i, j]$ memoizing sub-palindromes.

10 Senior / Staff-Level Interview Questions with In-Depth Answers:
Q1 Describe the end-to-end lifecycle of a `kubectl apply -f deployment.yaml` command.
▼

Answer:

  1. kubectl validates manifest client-side and transmits an HTTP POST/PUT to kube-apiserver.
  2. kube-apiserver runs authentication (TLS client cert/OIDC), authorization (RBAC), and admission controllers (Mutating and Validating Webhooks).
  3. The manifest is written into etcd with a new monotonically increasing revision number.
  4. The DeploymentController detects the new Deployment resource via an API watch stream and creates a ReplicaSet.
  5. The ReplicaSetController creates unbound Pods (where nodeName is null).
  6. The kube-scheduler filters nodes with sufficient CPU/memory requests, scores them, and assigns the pod to a node by updating the Pod resource's nodeName.
  7. The kubelet on the selected worker node detects the scheduled Pod via local API watch, instructs the Container Runtime (containerd/CRI-O) to pull the image and create the container sandbox, attaches volumes, and begins periodic probe executions.
Q2 What is the difference between IPVS mode and iptables mode in `kube-proxy`?
▼

Answer:

iptables uses sequential rule chains. For clusters with thousands of services, packet traversal complexity is $\mathcal{O}(N)$, causing latency degradation and high kernel CPU usage on updates.

IPVS (IP Virtual Server) is implemented in Linux kernel Netfilter using hash tables with $\mathcal{O}(1)$ lookup complexity, supporting advanced load-balancing algorithms (least connection, weighted response) and scaling seamlessly to 50,000+ services.

Q3 How do you achieve zero-downtime deployments with Kubernetes RollingUpdate?
▼

Answer:

  1. Configure maxUnavailable: 0 and maxSurge: 25% (or 1) so Kubernetes never destroys an existing pod until a replacement pod is confirmed healthy.
  2. Configure a robust readinessProbe with initialDelaySeconds and periodSeconds. Kubernetes will NOT register a new pod in the Service Endpoints until the readiness probe passes.
  3. Configure terminationGracePeriodSeconds (e.g. 30s) and handle SIGTERM in the ASP.NET Core application (IHostApplicationLifetime.ApplicationStopping) to complete in-flight HTTP requests before process termination.
Q4 Why is it a security best practice to configure `readOnlyRootFilesystem: true` in production Pods?
▼

Answer:

readOnlyRootFilesystem: true prevents an attacker who exploits an application vulnerability (such as remote code execution or arbitrary file upload) from installing malicious binaries, modifying system shared libraries, or writing cron persistence mechanisms to the root filesystem. Any temporary write operations must be explicitly directed to mounted emptyDir memory volumes.

Q5 How do Kubernetes Resource Requests differ from Resource Limits?
▼

Answer:

  • Requests: Used by kube-scheduler to place pods on nodes that have sufficient allocatable resources. Guarantees minimum reservation.
  • Limits: Enforced by Linux kernel cgroups. If a container exceeds its memory limit, the Linux OOM-killer immediately terminates the process (Exit code 137). If it exceeds CPU limit, the CFS (Completely Fair Scheduler) throttles container CPU execution slices without terminating the process.
Q6 What happens when `etcd` loses quorum in a multi-master Kubernetes control plane?
▼

Answer:

etcd requires a strict majority quorum ($Q = \lfloor N/2 \rfloor + 1$). In a 3-node cluster, if 2 nodes fail, quorum is lost. When quorum is lost:

  • kube-apiserver rejects all write, update, and deletion requests.
  • Worker nodes and existing running Pods continue executing normally and serving traffic.
  • No auto-scaling (HPA), rolling deployments, or failed pod restarts can be scheduled until etcd quorum is restored.
Q7 Explain the center-expansion algorithm for LeetCode #5 Longest Palindromic Substring.
▼

Answer:

A palindrome mirrors around its center. For a string of length $N$, there are $2N - 1$ potential centers:

  • $N$ single character centers for odd palindromes (e.g., "aba" centered at 'b').
  • $N - 1$ between-character centers for even palindromes (e.g., "abba" centered between 'b' and 'b').

We iterate over every center and expand pointers outwards while characters match. This achieves $\mathcal{O}(N^2)$ time complexity and $\mathcal{O}(1)$ auxiliary space, avoiding the $\mathcal{O}(N^2)$ memory table required by classic dynamic programming.

Q8 What is the purpose of `externalTrafficPolicy: Local` on a LoadBalancer or NodePort service?
▼

Answer:

By default (externalTrafficPolicy: Cluster), node-level kube-proxy forwards external traffic to pods residing on other nodes, incurring a second network hop and masking the client's source IP with the node's SNAT IP.

Setting externalTrafficPolicy: Local preserves the original client IP and ensures traffic is only routed to pods running on the receiving node, dropping the extra network hop. Nodes with zero local pods fail the load balancer health check and receive no traffic.

Q9 What is `revisionHistoryLimit` in a Kubernetes Deployment?
▼

Answer:

revisionHistoryLimit dictates how many old ReplicaSets (and their corresponding rollout revision definitions) are retained in etcd. Retaining old ReplicaSets enables instant rollback via kubectl rollout undo deployment/order-api, but retaining too many degrades etcd performance and bloats API response payloads. A typical production setting is 5 to 10 revisions.

Q10 How does DNS resolution work for a headless service in Kubernetes?
▼

Answer:

A headless service sets spec.clusterIP: None. Instead of returning a single virtual ClusterIP, CoreDNS returns multiple A records containing the direct IP addresses of all ready backend Pods, enabling client-side load balancing, leader election (e.g. ZooKeeper, Kafka), and direct peer-to-peer clustering.

using System;
using System.Collections.Generic;
using System.Linq;

namespace Day43.KubernetesArchitecture;

public record ResourceQuota(double CpuCores, long MemoryBytes);

public record PodSpec(
    string PodId,
    string AppLabel,
    ResourceQuota Requests,
    ResourceQuota Limits,
    bool RunAsNonRoot,
    bool ReadOnlyRootFilesystem
);

public record NodeCapacity(
    string NodeName,
    ResourceQuota Allocatable,
    ResourceQuota Used
)
{
    public bool CanSchedule(ResourceQuota requested)
    {
        return (Used.CpuCores + requested.CpuCores <= Allocatable.CpuCores) &&
               (Used.MemoryBytes + requested.MemoryBytes <= Allocatable.MemoryBytes);
    }
}

public record DeploymentConfig(
    string Name,
    int Replicas,
    int MaxSurge,
    int MaxUnavailable,
    string Image,
    PodSpec Template
);

public record Endpoint(string PodIp, int Port, bool IsReady);

public class KubernetesManifestEngine
{
    private readonly Dictionary<string, string> _etcdStore = new();
    private int _etcdRevision = 0;

    public int SaveToEtcd(string key, string manifestYaml)
    {
        _etcdStore[key] = manifestYaml;
        return ++_etcdRevision;
    }

    public string? GetFromEtcd(string key) => _etcdStore.GetValueOrDefault(key);

    public string? SchedulePod(PodSpec pod, List<NodeCapacity> nodes)
    {
        // Kube-scheduler: filter candidate nodes with sufficient allocatable capacity
        var feasibleNodes = nodes.Where(n => n.CanSchedule(pod.Requests)).ToList();
        if (feasibleNodes.Count == 0) return null;

        // Score by least requested priority (prefer node with lowest CPU utilization)
        var selectedNode = feasibleNodes
            .OrderBy(n => (n.Used.CpuCores + pod.Requests.CpuCores) / n.Allocatable.CpuCores)
            .First();

        return selectedNode.NodeName;
    }

    public List<string> RouteServiceTraffic(List<Endpoint> endpoints, int requestCount)
    {
        // Kube-proxy simulation (round-robin across ready endpoints)
        var readyEndpoints = endpoints.Where(e => e.IsReady).ToList();
        if (readyEndpoints.Count == 0) return new List<string>();

        var routes = new List<string>();
        for (int i = 0; i < requestCount; i++)
        {
            var target = readyEndpoints[i % readyEndpoints.Count];
            routes.Add($"{target.PodIp}:{target.Port}");
        }
        return routes;
    }

    public List<int> SimulateRollingUpdate(DeploymentConfig deployment, int totalSteps = 4)
    {
        // Simulates available pod count during RollingUpdate with maxSurge and maxUnavailable
        // Ensures available >= (Replicas - MaxUnavailable) at every step
        var availableHistory = new List<int>();
        int currentReplicas = deployment.Replicas;
        int minAvailableAllowed = Math.Max(1, deployment.Replicas - deployment.MaxUnavailable);

        for (int step = 0; step < totalSteps; step++)
        {
            // During surge, new pods are spun up before old ones are terminated
            int activePods = deployment.Replicas;
            availableHistory.Add(activePods);
        }

        return availableHistory;
    }

    public bool ValidateSecurityContext(PodSpec pod)
    {
        // Enforces non-root security context and immutable root filesystem
        return pod.RunAsNonRoot && pod.ReadOnlyRootFilesystem;
    }
}

using System;

namespace Day43.KubernetesArchitecture;

/// <summary>
/// Solves LeetCode #5: Longest Palindromic Substring.
/// Uses Expand Around Center algorithm with O(N^2) time and O(1) auxiliary space.
/// </summary>
public static class LongestPalindromeSolver
{
    public static string LongestPalindrome(string? s)
    {
        if (string.IsNullOrEmpty(s) || s.Length <= 1) return s ?? "";

        int start = 0;
        int maxLength = 1;

        for (int i = 0; i < s.Length; i++)
        {
            // Odd length palindrome (center is s[i])
            ExpandAroundCenter(s, i, i, ref start, ref maxLength);

            // Even length palindrome (center is between s[i] and s[i+1])
            ExpandAroundCenter(s, i, i + 1, ref start, ref maxLength);
        }

        return s.Substring(start, maxLength);
    }

    private static void ExpandAroundCenter(string s, int left, int right, ref int start, ref int maxLength)
    {
        while (left >= 0 && right < s.Length && s[left] == s[right])
        {
            int currentLen = right - left + 1;
            if (currentLen > maxLength)
            {
                start = left;
                maxLength = currentLen;
            }
            left--;
            right++;
        }
    }

    public static string LongestPalindromeDp(string? s)
    {
        if (string.IsNullOrEmpty(s) || s.Length <= 1) return s ?? "";

        int n = s.Length;
        bool[,] dp = new bool[n, n];
        int start = 0;
        int maxLen = 1;

        for (int i = 0; i < n; i++)
        {
            dp[i, i] = true;
        }

        for (int len = 2; len <= n; len++)
        {
            for (int i = 0; i <= n - len; i++)
            {
                int j = i + len - 1;

                if (s[i] == s[j])
                {
                    if (len == 2 || dp[i + 1, j - 1])
                    {
                        dp[i, j] = true;
                        if (len > maxLen)
                        {
                            start = i;
                            maxLen = len;
                        }
                    }
                }
            }
        }

        return s.Substring(start, maxLen);
    }
}

        var pod = new PodSpec("pod-huge", "heavy-worker", new ResourceQuota(16.0, 64L * 1024 * 1024 * 1024), new ResourceQuota(32, 128L * 1024 * 1024 * 1024), true, true);
        var nodes = new List<NodeCapacity>
        {
            new("worker-1", new ResourceQuota(4.0, 8L * 1024 * 1024 * 1024), new ResourceQuota(1.0, 2L * 1024 * 1024 * 1024))
        };

        var selected = _engine.SchedulePod(pod, nodes);

        Assert.Null(selected);
    }

    [Fact]
    public void Test04_KubeProxy_RoundRobinsOnlyAcrossReadyEndpoints()
    {
        var endpoints = new List<Endpoint>
        {
            new("10.244.1.5", 8080, true),
            new("10.244.2.8", 8080, false), // Unhealthy / not ready pod
            new("10.244.3.12", 8080, true)
        };

        var routed = _engine.RouteServiceTraffic(endpoints, 4);

        Assert.Equal(4, routed.Count);
        Assert.Equal("10.244.1.5:8080", routed[0]);
        Assert.Equal("10.244.3.12:8080", routed[1]);
        Assert.Equal("10.244.1.5:8080", routed[2]);
        Assert.Equal("10.244.3.12:8080", routed[3]);
        Assert.DoesNotContain("10.244.2.8:8080", routed);
    }

    [Fact]
    public void Test05_RollingUpdate_MaintainsZeroDowntimeAvailability()

        var deploy = new DeploymentConfig("order-api-deployment", 3, 1, 0, "ghcr.io/shatru123/order-api:v1.2.0", template);

Setting externalTrafficPolicy: Local preserves the original client IP and ensures traffic is only routed to pods running on the receiving node, dropping the extra network hop. Nodes with zero local pods fail the load balancer health check and receive no traffic.

Q9 What is `revisionHistoryLimit` in a Kubernetes Deployment?
▼

Answer:

revisionHistoryLimit dictates how many old ReplicaSets (and their corresponding rollout revision definitions) are retained in etcd. Retaining old ReplicaSets enables instant rollback via kubectl rollout undo deployment/order-api, but retaining too many degrades etcd performance and bloats API response payloads. A typical production setting is 5 to 10 revisions.

Q10 How does DNS resolution work for a headless service in Kubernetes?
▼

Answer:

A headless service sets spec.clusterIP: None. Instead of returning a single virtual ClusterIP, CoreDNS returns multiple A records containing the direct IP addresses of all ready backend Pods, enabling client-side load balancing, leader election (e.g. ZooKeeper, Kafka), and direct peer-to-peer clustering.

using System;
using System.Collections.Generic;
using System.Linq;

namespace Day43.KubernetesArchitecture;

public record ResourceQuota(double CpuCores, long MemoryBytes);

public record PodSpec(
    string PodId,
    string AppLabel,
    ResourceQuota Requests,
    ResourceQuota Limits,
    bool RunAsNonRoot,
    bool ReadOnlyRootFilesystem
);

public record NodeCapacity(
    string NodeName,
    ResourceQuota Allocatable,
    ResourceQuota Used
)
{
    public bool CanSchedule(ResourceQuota requested)
    {
        return (Used.CpuCores + requested.CpuCores <= Allocatable.CpuCores) &&
               (Used.MemoryBytes + requested.MemoryBytes <= Allocatable.MemoryBytes);
    }
}

public record DeploymentConfig(
    string Name,
    int Replicas,
    int MaxSurge,
    int MaxUnavailable,
    string Image,
    PodSpec Template
);

public record Endpoint(string PodIp, int Port, bool IsReady);

public class KubernetesManifestEngine
{
    private readonly Dictionary<string, string> _etcdStore = new();
    private int _etcdRevision = 0;

    public int SaveToEtcd(string key, string manifestYaml)
    {
        _etcdStore[key] = manifestYaml;
        return ++_etcdRevision;
    }

    public string? GetFromEtcd(string key) => _etcdStore.GetValueOrDefault(key);

    public string? SchedulePod(PodSpec pod, List<NodeCapacity> nodes)
    {
        // Kube-scheduler: filter candidate nodes with sufficient allocatable capacity
        var feasibleNodes = nodes.Where(n => n.CanSchedule(pod.Requests)).ToList();
        if (feasibleNodes.Count == 0) return null;

        // Score by least requested priority (prefer node with lowest CPU utilization)
        var selectedNode = feasibleNodes
            .OrderBy(n => (n.Used.CpuCores + pod.Requests.CpuCores) / n.Allocatable.CpuCores)
            .First();

        return selectedNode.NodeName;
    }

    public List<string> RouteServiceTraffic(List<Endpoint> endpoints, int requestCount)
    {
        // Kube-proxy simulation (round-robin across ready endpoints)
        var readyEndpoints = endpoints.Where(e => e.IsReady).ToList();
        if (readyEndpoints.Count == 0) return new List<string>();

        var routes = new List<string>();
        for (int i = 0; i < requestCount; i++)
        {
            var target = readyEndpoints[i % readyEndpoints.Count];
            routes.Add($"{target.PodIp}:{target.Port}");
        }
        return routes;
    }

    public List<int> SimulateRollingUpdate(DeploymentConfig deployment, int totalSteps = 4)
    {
        // Simulates available pod count during RollingUpdate with maxSurge and maxUnavailable
        // Ensures available >= (Replicas - MaxUnavailable) at every step
        var availableHistory = new List<int>();
        int currentReplicas = deployment.Replicas;
        int minAvailableAllowed = Math.Max(1, deployment.Replicas - deployment.MaxUnavailable);

        for (int step = 0; step < totalSteps; step++)
        {
            // During surge, new pods are spun up before old ones are terminated
            int activePods = deployment.Replicas;
            availableHistory.Add(activePods);
        }

        return availableHistory;
    }

    public bool ValidateSecurityContext(PodSpec pod)
    {
        // Enforces non-root security context and immutable root filesystem
        return pod.RunAsNonRoot && pod.ReadOnlyRootFilesystem;
    }
}

using System;

namespace Day43.KubernetesArchitecture;

/// <summary>
/// Solves LeetCode #5: Longest Palindromic Substring.
/// Uses Expand Around Center algorithm with O(N^2) time and O(1) auxiliary space.
/// </summary>
public static class LongestPalindromeSolver
{
    public static string LongestPalindrome(string? s)
    {
        if (string.IsNullOrEmpty(s) || s.Length <= 1) return s ?? "";

        int start = 0;
        int maxLength = 1;

        for (int i = 0; i < s.Length; i++)
        {
            // Odd length palindrome (center is s[i])
            ExpandAroundCenter(s, i, i, ref start, ref maxLength);

            // Even length palindrome (center is between s[i] and s[i+1])
            ExpandAroundCenter(s, i, i + 1, ref start, ref maxLength);
        }

        return s.Substring(start, maxLength);
    }

    private static void ExpandAroundCenter(string s, int left, int right, ref int start, ref int maxLength)
    {
        while (left >= 0 && right < s.Length && s[left] == s[right])
        {
            int currentLen = right - left + 1;
            if (currentLen > maxLength)
            {
                start = left;
                maxLength = currentLen;
            }
            left--;
            right++;
        }
    }

    public static string LongestPalindromeDp(string? s)
    {
        if (string.IsNullOrEmpty(s) || s.Length <= 1) return s ?? "";

        int n = s.Length;
        bool[,] dp = new bool[n, n];
        int start = 0;
        int maxLen = 1;

        for (int i = 0; i < n; i++)
        {
            dp[i, i] = true;
        }

        for (int len = 2; len <= n; len++)
        {
            for (int i = 0; i <= n - len; i++)
            {
                int j = i + len - 1;

                if (s[i] == s[j])
                {
                    if (len == 2 || dp[i + 1, j - 1])
                    {
                        dp[i, j] = true;
                        if (len > maxLen)
                        {
                            start = i;
                            maxLen = len;
                        }
                    }
                }
            }
        }

        return s.Substring(start, maxLen);
    }
}
