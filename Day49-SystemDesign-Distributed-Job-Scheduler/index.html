Technical Notes: Distributed Job Scheduler Architecture

1. Leader Election & Monotonic Fencing Tokens

In a distributed scheduler cluster, only the leader node queries the job database and enqueues due tasks to worker queues:

  • Lease Lock: Leader acquires a time-bounded lease in Redis or Zookeeper/etcd.
  • Fencing Token: To prevent a GC-paused or partition-delayed former leader from corrupting state, each leadership election increments a strictly monotonic 64-bit integer (FencingToken). Database updates reject writes from stale fencing tokens.

2. Worker Node Liveness & Failover

Worker nodes maintain periodic heartbeats (e.g., every 5s). When a worker fails:

  1. Heartbeat monitor detects elapsed time exceeds timeout threshold (e.g., 15s).
  2. Worker node is evicted from active pool.
  3. Unacknowledged in-flight tasks assigned to the dead worker are re-enqueued to the pending queue for other workers to claim.

3. LeetCode #42: Trapping Rain Water

  • Two Pointers: Maintain leftMax and rightMax. At each step, if height[left] < height[right], the water level is bounded by leftMax. If height[left] >= leftMax, update leftMax; otherwise, add leftMax - height[left]. Advance left. Symmetric for right. Time: $\mathcal{O}(N)$, Space: $\mathcal{O}(1)$.
  • Monotonic Stack: Keep a stack of decreasing bar indices. When a taller bar is encountered, pop the bottom, calculate the horizontal layer of trapped water between current bar and the new stack top: boundedHeight = min(height[left], height[right]) - height[bottom], width = right - left - 1. Time: $\mathcal{O}(N)$, Space: $\mathcal{O}(N)$.

Day 49: System Design: Distributed Job Scheduler

Overview

High-scale architectures require robust background and distributed job scheduling frameworks (e.g. Hangfire Pro, Quartz.NET clustering, Temporal, Cadence) to execute millions of recurring and delayed tasks reliably. Day 49 covers distributed leader election with monotonic fencing tokens, worker node heartbeats and dead node task reassignment, at-least-once task dispatch with idempotency tokens, and LeetCode #42 Trapping Rain Water (Hard) solved via both Two-Pointer and Monotonic Decreasing Stack approaches.

Key Concepts

  • Leader Election with Fencing Tokens: Preventing split-brain race conditions when distributed nodes compete to coordinate task schedules.
  • Worker Registry & Liveness Heartbeats: Monitoring distributed worker node health and automatically reallocating uncompleted tasks upon node failure.
  • Task Dispatch & Idempotency: Guaranteeing at-least-once delivery with at-most-once execution via unique execution tokens.
  • Retry Backoff with Jitter: Mitigating thundering herd stampedes when downstream dependencies fail.
  • Algorithm (LC #42): Trapping Rain Water using two pointers ($\mathcal{O}(N)$ time, $\mathcal{O}(1)$ space) and monotonic decreasing stack ($\mathcal{O}(N)$ space).
10 Senior / Staff-Level Interview Questions with In-Depth Answers:
Q1 How do you design a distributed job scheduler to guarantee that a recurring cron job never runs concurrently on two nodes?
▼

Answer:

  1. Leader-Follower Clustering: Run a leader election (via etcd, Consul, or Redis Redlock with lease). Only the elected leader generates trigger instances.
  2. Database Row-Level Lock: The leader updates the job record using SELECT ... FOR UPDATE or conditional write (UPDATE Jobs SET Status = 'Running', Version = Version + 1 WHERE Id = @Id AND Version = @ExpectedVersion).
  3. Fencing Tokens: Every job execution ticket includes an epoch/fencing token. Workers check this token against a distributed lock before starting execution.
  4. Idempotency Key: Execution key hash(jobId, scheduledFireTimeUtc) ensures deduplication if multiple instances accidentally trigger.
Q2 What happens when the leader node suffers a 30-second Stop-the-World GC pause?
▼

Answer:

During the GC pause, the leader cannot send heartbeat pings. The cluster considers the leader dead, elects a new leader, and issues a higher fencing token ($T_2 > T_1$). When the paused leader awakens:

  • It attempts to write state using its stale fencing token ($T_1$).
  • Storage / worker queues reject the write because $T_1 < T_2$.
  • The old leader catches the fencing token mismatch exception, realizes it has lost leadership, and demotes itself to a follower.
Q3 How do you implement delayed tasks (e.g., "send email in 3 days") at scale?
▼

Answer:

  1. Hashed / Hierarchical Timing Wheel: Circular buffer with time slots (seconds, minutes, hours). Tasks are placed in slots matching (targetTime - currentTime) % wheelSize. Offers $\mathcal{O}(1)$ insertion and expiration check.
  2. Redis Sorted Sets (ZSET): Store member = taskId, score = targetTimestampUtc. A background poller runs ZRANGEBYSCORE tasks -inf <now> to fetch due jobs with $\mathcal{O}(\log N + M)$ efficiency.
  3. Database Partitioning: Partition scheduled jobs table by fire date (fire_date), querying only today\'s partition with an index on fire_time.
Q4 Explain the difference between At-Least-Once and At-Most-Once execution semantics in job scheduling.
▼

Answer:

  • At-Least-Once: Scheduler dispatches the task and waits for an explicit ACK. If the worker crashes mid-execution or the ACK is lost over the network, the scheduler re-dispatches the task. Requires workers to be strictly idempotent.
  • At-Most-Once: Scheduler marks the task as completed immediately upon dispatching it to the worker. If the worker crashes, the task is never re-run. Suitable only for non-critical telemetry or cache warmups.

Enterprise financial workflows use At-Least-Once with application-level idempotency tables.

Q5 What are Misfire Policies in Quartz/Hangfire, and when do you use each?
▼

Answer:

A misfire occurs when a job was scheduled to run at time $T$, but all worker threads were exhausted or the scheduler was down until $T + \Delta$.

  • Fire Now: Immediately execute the missed job, then resume normal schedule (e.g. daily database backup).
  • Ignore / Reschedule Next: Discard the missed execution and wait for the next scheduled cron tick (e.g. real-time stock ticker snapshot).
  • Fire All Missed: Sequentially replay all missed triggers (e.g. hourly financial ledger reconciliation).
Q6 How do you prevent the "Thundering Herd" problem when 10,000 jobs are scheduled at midnight (00:00:00)?
▼

Answer:

  1. Cron Jitter / Staggering: Add randomized jitter to trigger times (e.g., $00:00 \pm 180$ seconds) across non-time-critical jobs.
  2. Priority Rate-Limiting Queues: Enqueue tasks into high, medium, and low priority queues, and throttle worker pull rates using token buckets.
  3. Backpressure: Workers pull tasks only when they have free concurrency slots, preventing queue buffer overflows.
Q7 Compare Quartz.NET, Hangfire Pro, and Temporal/Cadence for enterprise scheduling.
▼

Answer:

  • Quartz.NET: Mature, highly configurable cron engine; stores triggers in SQL tables via ADO.NET; lacks native distributed workflows or visual dashboard out of the box.
  • Hangfire Pro: Excellent ASP.NET Core integration; Redis/SQL storage; beautiful web dashboard; great for fire-and-forget, delayed, and recurring jobs; weaker on long-running complex multi-step orchestration.
  • Temporal / Cadence: Event-sourced code-as-configuration workflow orchestrator; resilient to process crashes, network partitions, and month-long pauses; superior for distributed state machine workflows and human-in-the-loop tasks.
Q8 How do you monitor worker node liveness without overwhelming the database with heartbeat writes?
▼

Answer:

  • Avoid writing heartbeats directly to relational databases.
  • Use Redis Key Expiry: Worker sets SET worker:id:heartbeat "alive" EX 10 every 3 seconds. If the key expires, Redis Keyspace Notifications (__keyevent@0__:expired) alert the scheduler.
  • Alternatively, use a lightweight gossip protocol (e.g. SWIM / Consul) where workers ping peer subsets, reducing $O(N)$ central load to $O(1)$ per node.
Q9 Contrast Two-Pointer vs Monotonic Stack for LeetCode #42 Trapping Rain Water.
▼

Answer:

  • Two Pointers:
  • Traversal: Converges from both ends towards the highest peak.
  • Computation: Calculates water column-by-column vertically ($leftMax - height[left]$).
  • Complexity: $\mathcal{O}(N)$ time, $\mathcal{O}(1)$ auxiliary space.
  • Monotonic Stack:
  • Traversal: Scans left to right once.
  • Computation: Calculates water layer-by-layer horizontally bounded by left and right walls.
  • Complexity: $\mathcal{O}(N)$ time, $\mathcal{O}(N)$ auxiliary space.
Q10 Can Trapping Rain Water be generalized to 3D terrain (LeetCode #407)? What algorithm is required?
▼

Answer:

Yes, in 3D terrain (height map grid $M imes N$), water spills over the lowest boundary cell.

  • The 2D two-pointer approach fails because boundaries form an arbitrary 2D perimeter rather than just two endpoints.
  • Algorithm: Use a Min-Heap (Priority Queue).
  1. Push all outer boundary cells into the min-heap and mark them visited.
  2. While the heap is not empty, pop the lowest cell $(x, y)$ with height $H$.
  3. Explore all 4 adjacent unvisited neighbors. If neighbor height $H_{neighbor} < H$, water trapped $= H - H_{neighbor}$.
  4. Push neighbor into the heap with effective height $\max(H, H_{neighbor})$.
  • Complexity: $\mathcal{O}(M \cdot N \log(M \cdot N))$ time, $\mathcal{O}(M \cdot N)$ space.

namespace Day49.DistributedJobScheduler;

using System;
using System.Collections.Generic;
using System.Linq;

public class SchedulerLeaderElection
{
    private readonly object _lock = new();
    public string? CurrentLeaderId { get; private set; }
    public long FencingToken { get; private set; }
    public DateTime LeaseExpiresAtUtc { get; private set; }

    public bool TryAcquireOrRenewLease(string candidateId, TimeSpan leaseDuration, DateTime nowUtc, out long grantedFencingToken)
    {
        lock (_lock)
        {
            if (CurrentLeaderId == null || nowUtc >= LeaseExpiresAtUtc || CurrentLeaderId == candidateId)
            {
                if (CurrentLeaderId != candidateId)
                {
                    FencingToken++; // Increment monotonic fencing token on leadership transition
                }
                CurrentLeaderId = candidateId;
                LeaseExpiresAtUtc = nowUtc.Add(leaseDuration);
                grantedFencingToken = FencingToken;
                return true;
            }

            grantedFencingToken = 0;
            return false;
        }
    }

    public void RelinquishLeadership(string leaderId)
    {
        lock (_lock)
        {
            if (CurrentLeaderId == leaderId)
            {
                CurrentLeaderId = null;
                LeaseExpiresAtUtc = DateTime.MinValue;
            }
        }
    }
}

public record WorkerNode(string WorkerId, int MaxCapacity, DateTime LastHeartbeatUtc);

public class WorkerNodeRegistry
{
    private readonly Dictionary<string, WorkerNode> _workers = new();
    private readonly Dictionary<string, string> _taskAssignments = new(); // TaskId -> WorkerId

    public void RegisterOrHeartbeat(string workerId, int capacity, DateTime nowUtc)
    {
        _workers[workerId] = new WorkerNode(workerId, capacity, nowUtc);
    }

    public void AssignTask(string taskId, string workerId)
    {
        _taskAssignments[taskId] = workerId;
    }

    public List<string> EvictDeadWorkers(TimeSpan timeout, DateTime nowUtc)
    {
        var deadWorkers = _workers.Values
            .Where(w => nowUtc - w.LastHeartbeatUtc > timeout)
            .Select(w => w.WorkerId)
            .ToList();

        var reallocatedTasks = new List<string>();

        foreach (var deadWorker in deadWorkers)
        {
            _workers.Remove(deadWorker);

            var tasksToReallocate = _taskAssignments
                .Where(kvp => kvp.Value == deadWorker)
                .Select(kvp => kvp.Key)
                .ToList();

            foreach (var t in tasksToReallocate)
            {
                _taskAssignments.Remove(t);
                reallocatedTasks.Add(t);
            }
        }

        return reallocatedTasks;
    }

    public bool IsWorkerAlive(string workerId) => _workers.ContainsKey(workerId);
}

public record ScheduledTask(
    string TaskId,
    DateTime DueAtUtc,
    int RetryCount = 0,
    int MaxRetries = 3);

public class DistributedTaskScheduler
{
    private readonly List<ScheduledTask> _taskQueue = new();
    private readonly HashSet<string> _processedExecutionTokens = new();

    public void EnqueueTask(ScheduledTask task)
    {
        _taskQueue.Add(task);
    }

    public List<ScheduledTask> PollDueTasks(DateTime nowUtc)
    {
        var dueTasks = _taskQueue.Where(t => t.DueAtUtc <= nowUtc).ToList();
        foreach (var t in dueTasks)
        {
            _taskQueue.Remove(t);
        }
        return dueTasks;
    }

    public bool TryExecuteWithIdempotencyToken(string executionToken)
    {
        if (_processedExecutionTokens.Contains(executionToken))
        {
            return false; // Duplicate execution rejected
        }

        _processedExecutionTokens.Add(executionToken);
        return true;
    }

    public static TimeSpan CalculateBackoffWithJitter(int retryCount, int baseDelayMs = 100)
    {
        // Exponential backoff: base * 2^retry
        double delay = baseDelayMs * Math.Pow(2, Math.Min(retryCount, 6));
        // Deterministic jitter simulation (+ 10%)
        return TimeSpan.FromMilliseconds(delay * 1.1);
    }
}

namespace Day49.DistributedJobScheduler;

using System;
using System.Collections.Generic;

public class TrappingRainWaterSolver
{
    /// <summary>
    /// LeetCode #42: Trapping Rain Water.
    /// Optimal Two-Pointer approach: O(N) time, O(1) space.
    /// </summary>
    public static int TrapTwoPointers(int[] height)
    {
        if (height == null || height.Length < 3) return 0;

        int left = 0;
        int right = height.Length - 1;
        int leftMax = 0;
        int rightMax = 0;
        int totalWater = 0;

        while (left < right)
        {
            if (height[left] < height[right])
            {
                if (height[left] >= leftMax)
                {
                    leftMax = height[left];
                }
                else
                {
                    totalWater += leftMax - height[left];
                }
                left++;
            }
            else
            {
                if (height[right] >= rightMax)
                {
                    rightMax = height[right];
                }
                else
                {
                    totalWater += rightMax - height[right];
                }
                right--;
            }
        }

        return totalWater;
    }

    /// <summary>
    /// Monotonic Stack approach: O(N) time, O(N) space.
    /// Computes trapped water bounded horizontally between left and right walls.
    /// </summary>
    public static int TrapMonotonicStack(int[] height)
    {
        if (height == null || height.Length < 3) return 0;

        var stack = new Stack<int>(); // Stores indices of decreasing bars
        int totalWater = 0;

        for (int i = 0; i < height.Length; i++)
        {
            while (stack.Count > 0 && height[i] > height[stack.Peek()])
            {
                int bottomIdx = stack.Pop();

                if (stack.Count == 0) break; // No left boundary

                int leftIdx = stack.Peek();
                int boundedHeight = Math.Min(height[leftIdx], height[i]) - height[bottomIdx];
                int distance = i - leftIdx - 1;

                totalWater += boundedHeight * distance;
            }

            stack.Push(i);
        }

        return totalWater;
    }

    /// <summary>
    /// Dynamic Programming prefix/suffix max approach: O(N) time, O(N) space.
    /// </summary>
    public static int TrapDp(int[] height)
    {
        if (height == null || height.Length < 3) return 0;

        int n = height.Length;
        int[] leftMax = new int[n];
        int[] rightMax = new int[n];

        leftMax[0] = height[0];
        for (int i = 1; i < n; i++)
        {
            leftMax[i] = Math.Max(leftMax[i - 1], height[i]);
        }

        rightMax[n - 1] = height[n - 1];
        for (int i = n - 2; i >= 0; i--)
        {
            rightMax[i] = Math.Max(rightMax[i + 1], height[i]);
        }

        int totalWater = 0;
        for (int i = 0; i < n; i++)
        {
            int trapped = Math.Min(leftMax[i], rightMax[i]) - height[i];
            if (trapped > 0)
            {
                totalWater += trapped;
            }
        }

        return totalWater;
    }
}

  • At-Least-Once: Scheduler dispatches the task and waits for an explicit ACK. If the worker crashes mid-execution or the ACK is lost over the network, the scheduler re-dispatches the task. Requires workers to be strictly idempotent.
  • At-Most-Once: Scheduler marks the task as completed immediately upon dispatching it to the worker. If the worker crashes, the task is never re-run. Suitable only for non-critical telemetry or cache warmups.

Enterprise financial workflows use At-Least-Once with application-level idempotency tables.

Q5 What are Misfire Policies in Quartz/Hangfire, and when do you use each?
▼

Answer:

A misfire occurs when a job was scheduled to run at time $T$, but all worker threads were exhausted or the scheduler was down until $T + \Delta$.

  • Fire Now: Immediately execute the missed job, then resume normal schedule (e.g. daily database backup).
  • Ignore / Reschedule Next: Discard the missed execution and wait for the next scheduled cron tick (e.g. real-time stock ticker snapshot).
  • Fire All Missed: Sequentially replay all missed triggers (e.g. hourly financial ledger reconciliation).
Q6 How do you prevent the "Thundering Herd" problem when 10,000 jobs are scheduled at midnight (00:00:00)?
▼

Answer:

  1. Cron Jitter / Staggering: Add randomized jitter to trigger times (e.g., $00:00 \pm 180$ seconds) across non-time-critical jobs.
  2. Priority Rate-Limiting Queues: Enqueue tasks into high, medium, and low priority queues, and throttle worker pull rates using token buckets.
  3. Backpressure: Workers pull tasks only when they have free concurrency slots, preventing queue buffer overflows.
Q7 Compare Quartz.NET, Hangfire Pro, and Temporal/Cadence for enterprise scheduling.
▼

Answer:

  • Quartz.NET: Mature, highly configurable cron engine; stores triggers in SQL tables via ADO.NET; lacks native distributed workflows or visual dashboard out of the box.
  • Hangfire Pro: Excellent ASP.NET Core integration; Redis/SQL storage; beautiful web dashboard; great for fire-and-forget, delayed, and recurring jobs; weaker on long-running complex multi-step orchestration.
  • Temporal / Cadence: Event-sourced code-as-configuration workflow orchestrator; resilient to process crashes, network partitions, and month-long pauses; superior for distributed state machine workflows and human-in-the-loop tasks.
Q8 How do you monitor worker node liveness without overwhelming the database with heartbeat writes?
▼

Answer:

  • Avoid writing heartbeats directly to relational databases.
  • Use Redis Key Expiry: Worker sets SET worker:id:heartbeat "alive" EX 10 every 3 seconds. If the key expires, Redis Keyspace Notifications (__keyevent@0__:expired) alert the scheduler.
  • Alternatively, use a lightweight gossip protocol (e.g. SWIM / Consul) where workers ping peer subsets, reducing $O(N)$ central load to $O(1)$ per node.
Q9 Contrast Two-Pointer vs Monotonic Stack for LeetCode #42 Trapping Rain Water.
▼

Answer:

  • Two Pointers:
  • Traversal: Converges from both ends towards the highest peak.
  • Computation: Calculates water column-by-column vertically ($leftMax - height[left]$).
  • Complexity: $\mathcal{O}(N)$ time, $\mathcal{O}(1)$ auxiliary space.
  • Monotonic Stack:
  • Traversal: Scans left to right once.
  • Computation: Calculates water layer-by-layer horizontally bounded by left and right walls.
  • Complexity: $\mathcal{O}(N)$ time, $\mathcal{O}(N)$ auxiliary space.
Q10 Can Trapping Rain Water be generalized to 3D terrain (LeetCode #407)? What algorithm is required?
▼

Answer:

Yes, in 3D terrain (height map grid $M imes N$), water spills over the lowest boundary cell.

  • The 2D two-pointer approach fails because boundaries form an arbitrary 2D perimeter rather than just two endpoints.
  • Algorithm: Use a Min-Heap (Priority Queue).
  1. Push all outer boundary cells into the min-heap and mark them visited.
  2. While the heap is not empty, pop the lowest cell $(x, y)$ with height $H$.
  3. Explore all 4 adjacent unvisited neighbors. If neighbor height $H_{neighbor} < H$, water trapped $= H - H_{neighbor}$.
  4. Push neighbor into the heap with effective height $\max(H, H_{neighbor})$.
  • Complexity: $\mathcal{O}(M \cdot N \log(M \cdot N))$ time, $\mathcal{O}(M \cdot N)$ space.

namespace Day49.DistributedJobScheduler;

using System;
using System.Collections.Generic;
using System.Linq;

public class SchedulerLeaderElection
{
    private readonly object _lock = new();
    public string? CurrentLeaderId { get; private set; }
    public long FencingToken { get; private set; }
    public DateTime LeaseExpiresAtUtc { get; private set; }

    public bool TryAcquireOrRenewLease(string candidateId, TimeSpan leaseDuration, DateTime nowUtc, out long grantedFencingToken)
    {
        lock (_lock)
        {
            if (CurrentLeaderId == null || nowUtc >= LeaseExpiresAtUtc || CurrentLeaderId == candidateId)
            {
                if (CurrentLeaderId != candidateId)
                {
                    FencingToken++; // Increment monotonic fencing token on leadership transition
                }
                CurrentLeaderId = candidateId;
                LeaseExpiresAtUtc = nowUtc.Add(leaseDuration);
                grantedFencingToken = FencingToken;
                return true;
            }

            grantedFencingToken = 0;
            return false;
        }
    }

    public void RelinquishLeadership(string leaderId)
    {
        lock (_lock)
        {
            if (CurrentLeaderId == leaderId)
            {
                CurrentLeaderId = null;
                LeaseExpiresAtUtc = DateTime.MinValue;
            }
        }
    }
}

public record WorkerNode(string WorkerId, int MaxCapacity, DateTime LastHeartbeatUtc);

public class WorkerNodeRegistry
{
    private readonly Dictionary<string, WorkerNode> _workers = new();
    private readonly Dictionary<string, string> _taskAssignments = new(); // TaskId -> WorkerId

    public void RegisterOrHeartbeat(string workerId, int capacity, DateTime nowUtc)
    {
        _workers[workerId] = new WorkerNode(workerId, capacity, nowUtc);
    }

    public void AssignTask(string taskId, string workerId)
    {
        _taskAssignments[taskId] = workerId;
    }

    public List<string> EvictDeadWorkers(TimeSpan timeout, DateTime nowUtc)
    {
        var deadWorkers = _workers.Values
            .Where(w => nowUtc - w.LastHeartbeatUtc > timeout)
            .Select(w => w.WorkerId)
            .ToList();

        var reallocatedTasks = new List<string>();

        foreach (var deadWorker in deadWorkers)
        {
            _workers.Remove(deadWorker);

            var tasksToReallocate = _taskAssignments
                .Where(kvp => kvp.Value == deadWorker)
                .Select(kvp => kvp.Key)
                .ToList();

            foreach (var t in tasksToReallocate)
            {
                _taskAssignments.Remove(t);
                reallocatedTasks.Add(t);
            }
        }

        return reallocatedTasks;
    }

    public bool IsWorkerAlive(string workerId) => _workers.ContainsKey(workerId);
}

public record ScheduledTask(
    string TaskId,
    DateTime DueAtUtc,
    int RetryCount = 0,
    int MaxRetries = 3);

public class DistributedTaskScheduler
{
    private readonly List<ScheduledTask> _taskQueue = new();
    private readonly HashSet<string> _processedExecutionTokens = new();

    public void EnqueueTask(ScheduledTask task)
    {
        _taskQueue.Add(task);
    }

    public List<ScheduledTask> PollDueTasks(DateTime nowUtc)
    {
        var dueTasks = _taskQueue.Where(t => t.DueAtUtc <= nowUtc).ToList();
        foreach (var t in dueTasks)
        {
            _taskQueue.Remove(t);
        }
        return dueTasks;
    }

    public bool TryExecuteWithIdempotencyToken(string executionToken)
    {
        if (_processedExecutionTokens.Contains(executionToken))
        {
            return false; // Duplicate execution rejected
        }

        _processedExecutionTokens.Add(executionToken);
        return true;
    }

    public static TimeSpan CalculateBackoffWithJitter(int retryCount, int baseDelayMs = 100)
    {
        // Exponential backoff: base * 2^retry
        double delay = baseDelayMs * Math.Pow(2, Math.Min(retryCount, 6));
        // Deterministic jitter simulation (+ 10%)
        return TimeSpan.FromMilliseconds(delay * 1.1);
    }
}

namespace Day49.DistributedJobScheduler;

using System;
using System.Collections.Generic;

public class TrappingRainWaterSolver
{
    /// <summary>
    /// LeetCode #42: Trapping Rain Water.
    /// Optimal Two-Pointer approach: O(N) time, O(1) space.
    /// </summary>
    public static int TrapTwoPointers(int[] height)
    {
        if (height == null || height.Length < 3) return 0;

        int left = 0;
        int right = height.Length - 1;
        int leftMax = 0;
        int rightMax = 0;
        int totalWater = 0;

        while (left < right)
        {
            if (height[left] < height[right])
            {
                if (height[left] >= leftMax)
                {
                    leftMax = height[left];
                }
                else
                {
                    totalWater += leftMax - height[left];
                }
                left++;
            }
            else
            {
                if (height[right] >= rightMax)
                {
                    rightMax = height[right];
                }
                else
                {
                    totalWater += rightMax - height[right];
                }
                right--;
            }
        }

        return totalWater;
    }

    /// <summary>
    /// Monotonic Stack approach: O(N) time, O(N) space.
    /// Computes trapped water bounded horizontally between left and right walls.
    /// </summary>
    public static int TrapMonotonicStack(int[] height)
    {
        if (height == null || height.Length < 3) return 0;

        var stack = new Stack<int>(); // Stores indices of decreasing bars
        int totalWater = 0;

        for (int i = 0; i < height.Length; i++)
        {
            while (stack.Count > 0 && height[i] > height[stack.Peek()])
            {
                int bottomIdx = stack.Pop();

                if (stack.Count == 0) break; // No left boundary

                int leftIdx = stack.Peek();
                int boundedHeight = Math.Min(height[leftIdx], height[i]) - height[bottomIdx];
                int distance = i - leftIdx - 1;

                totalWater += boundedHeight * distance;
            }

            stack.Push(i);
        }

        return totalWater;
    }

    /// <summary>
    /// Dynamic Programming prefix/suffix max approach: O(N) time, O(N) space.
    /// </summary>
    public static int TrapDp(int[] height)
    {
        if (height == null || height.Length < 3) return 0;

        int n = height.Length;
        int[] leftMax = new int[n];
        int[] rightMax = new int[n];

        leftMax[0] = height[0];
        for (int i = 1; i < n; i++)
        {
            leftMax[i] = Math.Max(leftMax[i - 1], height[i]);
        }

        rightMax[n - 1] = height[n - 1];
        for (int i = n - 2; i >= 0; i--)
        {
            rightMax[i] = Math.Max(rightMax[i + 1], height[i]);
        }

        int totalWater = 0;
        for (int i = 0; i < n; i++)
        {
            int trapped = Math.Min(leftMax[i], rightMax[i]) - height[i];
            if (trapped > 0)
            {
                totalWater += trapped;
            }
        }

        return totalWater;
    }
}
